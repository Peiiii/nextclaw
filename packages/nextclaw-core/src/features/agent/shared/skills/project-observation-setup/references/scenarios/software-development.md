# 软件开发场景映射

本 reference 只解释如何把 `general-work` 映射到软件开发，不定义另一套 Workflow。

| 通用节点 | 软件开发中的常见含义 | 可观察证据示例 |
| --- | --- | --- |
| `exploration` | 澄清问题、用户价值、现状与影响面 | 需求结论、复现证据、范围说明 |
| `planning` | 拆分实施步骤、依赖与验收条件 | 实施计划、验收用例 |
| `design` | 确定产品交互、技术方案或数据合同 | 方案文档、接口设计 |
| `proposal-review` | 在实现前检查方案是否正确、克制且可落地 | 方案评审结论 |
| `execution` | 编码、迁移、配置或文档实现 | 源码与用户文档改动 |
| `verification` | 运行测试、类型检查、真实链路验证与实现复核 | 测试结果、验证记录 |
| `acceptance` | 向用户交付可验证结果并等待最终确认 | 验收链接、开放 request Marker |

不要把“需求、开发、测试、发布”当作整个项目的宏观里程碑写进 Workflow；这里描述的是一条具体工作项当前处于什么工作性质。小修复可以从 `execution` 开始，纯方案任务可以在产出方案后进入 `verification`，但最终仍须经过用户验收才能成为 `completed`。
