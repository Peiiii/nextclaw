# 研究、调研与分析场景映射

本 reference 只解释如何把 `general-work` 映射到科研探索、投资调研、市场分析和其它研究任务，不定义另一套 Workflow。

| 通用节点 | 研究分析中的常见含义 | 可观察证据示例 |
| --- | --- | --- |
| `exploration` | 澄清问题、决策目标、范围与证据标准 | 研究问题、范围说明 |
| `planning` | 规划信息源、分析步骤和交付形式 | 调研计划、分析框架 |
| `design` | 设计方法、比较维度、实验或论证结构 | 方法说明、指标框架 |
| `proposal-review` | 在采集和分析前检查方法能否回答问题 | 方法评审结论 |
| `execution` | 收集证据、计算、分析并形成结果 | 数据、笔记、报告草稿 |
| `verification` | AI 核对来源、计算、反例、局限和结论支持度 | 复核记录、质量检查 |
| `acceptance` | 向用户提交结论和证据并等待最终确认 | 报告预览、开放 request Marker |

不要把“课题立项、长期研究、发表”之类项目级阶段写成单个工作项 Workflow。一次资料核查、一次对比分析或一次研究方案设计都可以成为独立工作项，并从最符合事实的节点开始；只有用户验收后才能报告 `completed`。
