# 个人工作台交互与样式统一执行计划

## 目标与依据

上位设计：`docs/designs/2026-09-25-bibo-personal-agent-implementation-alignment.design.md` 的“操作容器与整行反馈纠偏”及后续输入修订。归原大型合同 BIBO-09/12/13；原父目标开放项不随本轮关闭。用户已有合入主干与正式部署授权；默认单代理，源区 thought WIP 不触碰。

目标：日程就地居中编辑、任务整行反馈与宽详情、目录树完全隐藏和恢复；当前个人 Agent 应用与公共 UI 使用 Tailwind CSS 统一样式链。保留短操作弹层与长内容工作区的区别，按功能实际操作验收。

## 执行顺序

1. **交互结构**：复用已通过 Review 的上位设计；Calendar/Tasks/FileWorkbench 展示归原组件，写入与草稿仍归 space owner。删除日程右栏编辑和任务挤压列表的路径，复合行状态由 ListRow 拥有。首次编辑前工作树干净，已记录源区无关 WIP。验证关闭、忙态、失败、聚焦、嵌套确认和树收放。
2. **Tailwind 样式链**：复用上位技术栈修订；Vite plugin、公共 tokens/primitive、chat/space 布局依次迁移。同一状态唯一 owner，utility 或官方 @apply；不保留平行旧控件实现。每批构建证明样式生成，尺寸和 hover 用实际浏览器比较。
3. **性能**：当前用户问询已取得正式单组耗时与串行刷新证据，记录建议；若进入任务 outbox 实现，先补稳定设计及 Review，证明幂等、账号切换、并发、失败和刷新恢复。不能未经建模直接追加 optimistic 假任务。独立可确认的刷新等待可按原 act 合同优化，但须保护提交/读取失败的区别。
4. **统一验收与 Review**：1440/390/320 跑任务、日程真实读写与弹层/列表/树矩阵；文件、笔记、收件箱、对话/产物、概览代表动作实际走查。共享包与应用 tsc，现有 smoke/领域 tests、diff-only maintainability 和必要治理；找到真实问题继续修，不能把 class 名当视觉证据。
5. **发布闭环**：精确提交、本轮全部改动纳入远程 master，从冻结源码构建部署 app.bibo.bot；真实关键链路复验、用户说明更新、主线回收。文档 CDN 刷新既有额度限制须如实记录，不重复成功上传或虚称流水线成功。
