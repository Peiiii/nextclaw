# Bibo 零容器普通对话交付计划

## 目标和门槛

以 [`BIBO-EDGE-2026-09-29`](../work/2026-09-29-bibo-edge-conversation/acceptance-contract.md) 的 BE-01 至 BE-08 为完成定义。现有 Node 安装、会话、工具、扩展与升级链路保持兼容。Bibo 纯聊天、旧会话续聊与个人空间文件工具不启动用户容器；独立操作系统任务按需执行。生产同口径对照要证明首字、可控平台段、容器调用和成本，不能用一次本地运行替代。

## 执行顺序

### 1. 锁定旧状态和负载

- 从生产观测采集带匿名关联 ID 的 `accepted → 首次模型请求 → 首字 → 提交` 分段，标记新/旧会话、闲置时长、工具、冷/热、模型轮次、容器恢复和快照耗时。至少积累足以比较尾部的样本，并公开样本数、排除条件和分位算法。
- 按同一用户负载（300/900/1800 条每人每月、100/1000 活跃用户、10 倍峰值）计算现有 A、边缘 B、按需共享池 E 的平台资源；模型与搜索依据真实 token/调用分布单列。记录每百条请求的 DO 活跃 GB·s、读写、R2 操作/容量、容器 vCPU/内存/磁盘时长、Worker CPU 和失败率。
- 固定升级样本：现有真实或脱敏 R2 快照、DO UI 会话、长 NCP journal、压缩检查点、个人空间文件、身份/记忆、用户提问及 Agent 送达。记录各类对象数量和校验值；生产数据不写入仓库或日志。

### 2. 抽出可移植的 NextClaw 会话核心

- 从 `DefaultNcpAgentRuntime` 和 `DefaultNcpAgentConversationStateManager` 已有公共合同入手。把当前 Kernel 的模型输入投影、上下文压缩、预算与工具 schema 裁剪抽成宿主无关公共入口；Node Kernel 自身改用同一入口。入口的静态依赖不得拉入 `sharp`、`node:sqlite`、进程和文件系统。
- 保持 Node 当前接口、语义和扩展；用同一 NCP 事件样本比较 Node 与 workerd 的模型输入、工具轮次、压缩前后、取消、重试和长期上下文。真实 workerd 运行模型与 Bibo 工具；工具验证不依赖 Workers 禁止的动态代码生成。
- 若 Worker CPU/内存、长上下文或依赖使目标无法达成，用已抽出的通用核心实测共享 Node 候选；不得在 Bibo 另写一套 Agent 语义。

### 3. 单一状态 owner 与可重入迁移

- DO 以单调版本持久化 NCP 事件、会话元数据、用户问题和结构化空间；文件正文与索引按原 1 MiB 限制在同一 DO 事务提交。执行期间的状态只暂存，成功时同事务提交；取消、断线、模型失败和重复请求不能提交半轮消息或文件。
- 只读导出旧用户容器中的 Kernel journal、压缩检查点、身份/记忆与文件，结合 DO 原 UI 会话与结构化状态。按用户、会话和文件校验数量、最近内容、版本、正文摘要及模型继续输入；用迁移版本和幂等键重复运行不产生重复事件。
- 切换前保持旧快照；每用户有明确版本化切换点。回滚通过验证的反向导出或停写恢复，不允许直接用旧快照覆盖新写入。先本地/测试环境迁移演练，再小流量用户灰度，最后全量；任何校验不一致暂停切换。

### 4. 接通完整 Bibo 用户链路

- 新会话、已闲置一小时的旧会话、长会话压缩、普通工具、`show_file`、搜索、用户提问、文件预览、取消/刷新/重试和并发空间读取均走同一流式事件协议。用户可见的提交、保存和错误状态必须与真实持久结果一致。
- 以容器调用计数和执行轨迹证明这些请求为零；独立 OS 工具经明确能力边界按需启动。并发版本冲突、同账号不同会话与不同账号隔离均有实际验证。
- 运行真实浏览器桌面和手机冒烟；现有 Node 包完整匹配范围 `tsc`、升级与扩展合同回归。对内容、状态、协议和持久性由 AI 自证，视觉审美再由用户评审。

### 5. 自审、主干、上线与量化复验

- 完成设计和实现 Review、diff-only maintainability、必要范围测试、迁移/回滚演练；逐项填 BE 验收账本。找出与旧版相比的体验退化，修复后重新验证，而不改变合同来使其通过。
- 从冻结的远程 `master` 发布同一验证产物，记录构建、上传、切换、冒烟耗时；普通聊天更新不重建 OS 执行器镜像。完成适用的文档站、changeset、NPM/升级合同与主干 reconciliation。
- 上线后取相同模型、地区、内容和冷/热条件的 p50/p95/p99、样本数、分段时长、错误率和每百条资源量；按真实用量复算三档单用户费用。只有 BE-01 至 BE-08 全部达标并经自审，才报告整体交付完成。

## 停止切换的条件

旧用户数据校验或回滚不可靠、Node 旧路径回归失败、Worker 需要复制对话语义、工具/文件/问题能力缺失、生产尾延迟或成本未达到合同，均停止新路径生产切换并回到相应步骤修复。已有假忙修复可独立保留，不能充作整体完成。
