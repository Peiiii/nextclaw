# Bibo 零容器普通对话交付计划

## 目标和门槛

公共 API、宿主边界和旧版升级门以 [Harness 双宿主组合设计](../designs/2026-09-29-nextclaw-harness-host-composition.design.md) 的 2026-09-30 修订为当前设计依据：Harness 是公开入口，依赖通用 Kernel，Kernel 消费 Node/Cloudflare 平台接口。撤回 Kernel 反向依赖 Harness 的讨论建议；核心逻辑仍由同一 Kernel 拥有。下文旧版“仅复用便携组件”“Kernel 宿主”等表述不授权独立 Bibo 编排或把通用 Kernel 绑定 Node；实施顺序以专题设计第 14 节为准，待该设计必要接缝 Review 后恢复实现。

以 [`BIBO-EDGE-2026-09-29`](../work/2026-09-29-bibo-edge-conversation/acceptance-contract.md) 的 BE-01 至 BE-14 为完成定义。完整本地版 NextClaw 是**用户任务结果**的能力基线，不要求相同 Node 工具源码在 Bibo 原样运行；本地 Node 与 Bibo 复用同一通用对话、授权与工具结果语义，下层不感知 Bibo。Bibo 纯聊天不启动用户容器，只有调用依赖进程/二进制的工具时才按需执行；最终在线产物不保留 legacy 对话分支。非必要能力与体验不缩水。生产同口径对照证明首字、直接工具、执行器唤醒、容器调用、文件规模和成本；未达标就返工复验，不能以部署代替交付。

## 执行顺序

### 1. 锁定旧状态和负载

- 从生产观测采集带匿名关联 ID 的 `accepted → 首次模型请求 → 首字 → 提交` 分段，标记新/旧会话、闲置时长、工具、冷/热、模型轮次、容器恢复和快照耗时。至少积累足以比较尾部的样本，并公开样本数、排除条件和分位算法。
- 按同一用户负载（300/900/1800 条每人每月、100/1000 活跃用户、10 倍峰值）计算现有 A、边缘 B、按需执行器 E、共享 Node 宿主 D 的平台资源；模型与搜索依据真实 token/调用分布单列。记录每百条请求的用户进程并发/PSS/CPU、持久磁盘与备份、DO/R2 用量、执行器启动/驻留及失败率。
- 固定升级样本：现有真实或脱敏 R2 快照、DO UI 会话、长 NCP journal、压缩检查点、个人空间文件、身份/记忆、用户提问及 Agent 送达。记录各类对象数量和校验值；生产数据不写入仓库或日志。

### 2. 验证统一基座与 Worker 主链路

- 先通过双宿主反证门：仓库内旧 Harness API 调用可同步迁移，已发布但无人使用的 API 不作为兼容门槛；Worker 中实际运行从现有 Node 链路抽出的同一编排对象，fake-host 完成真实会话加载、工具、压缩、提交和续聊。浏览器打包旧根入口触及 `node:*`，而 Wrangler `nodejs_compat` 的较窄静态打包成功；须用 workerd 实际运行判定，不以任何一个静态探针代替。
- Node 原生 Agent run 已通过 `AgentRunRequestManager` 等现有对象；优先将这些对象的资源接缝变为宿主端口，让 Worker 复用，避免重写 Node 的已验证逻辑。Node 的 Narp、服务、渠道、设备管理继续由原 Kernel 宿主拥有；本地旧 home、session journal、extension 的真实升级矩阵过线后才接 Bibo。Bibo `BiboEdgeConversationService` 当前手工装配的编排须由 Harness 核心替代，最终在线无第二个 Agent owner。

- 以用户任务、状态连续性、隔离、延时和费用为约束；完整本地版是能力基线，不要求 Worker 运行现有 Node 进程。公共 NextClaw 合同拥有 NCP 对话事件、模型输入、能力目录和工具调用语义；Node 与 Worker 装配不同宿主端口。复用现有便携组件，但不把 Bibo 手工边缘工具清单当作最终能力目录。
- 优先沿现有 Worker 对话链路做纵向切片：无需 OS 的文件/网络能力直接运行；Agent 在需要进程、二进制或 stdio MCP 时请求并选择独立执行环境，也能观察、释放或在明确任务中同时持有多个环境；同一轮 NCP run 在工具返回后继续。以旧会话及 `read_file → 按需取得 OS/挂载资源 → exec → read_file` 证明上下文与文件连续，记录每段延时和容器计数。
- 先验证 C1（DO/R2 持久用户资源 + Cloudflare 按需执行器的资源级挂载）：执行环境默认全盘临时，Agent 只挂载此次需要的已有资料或最终结果；挂载路径内普通写入自动持久化，无额外保存步骤。Git clone、仓库历史、安装依赖、构建缓存和 `node_modules` 默认全留在临时磁盘，不做逐文件持久同步；用户要求保留仓库时走获授权的远端 Git 服务，不把工作树自动同步作为主链路。测无挂载命令、临时 Git/依赖任务后仅挂载产物、单文件读写、100 MiB 用户文件、双环境、休眠/故障恢复和写后直达回读，记录实际挂载字节、冷热延迟与对象费用；R2 FUSE 只承载所选用户资源。仅当完整任务和 BE-13/14 在这种模型下仍无法达标，才正式对照 C2（共享持久 POSIX 宿主 + 同主机隔离执行器）的跨网延时、固定主机/备份费与可用性。
- 按完整本地版的代表任务逐类验证 Worker 直达、独立持久服务、按需执行、设备授权例外；现有 Node-only manager 只作为实现盘点，不能因代码复用困难增加普通聊天的固定网络跳。若 Worker 主链路在完整能力、状态、BE-02/06/13/14 门槛下无法达标，再以同负载纵向比较每用户 Node 进程宿主 D，不缩小能力基线。

### 3. 完整本地版能力对账与统一基座

- 从同版本 Kernel 的实际 provider、Skill、模型、会话、项目、应用包、MCP、后台与设备能力盘点用户任务；逐项写明 Bibo 的直接路径、按需 OS 路径或有证据的必要例外。旧 Bibo 未开放的能力仍属于差距。
- 把能力装配、调用、授权及状态语义收敛到 NextClaw 公共入口，Node 与 Bibo 均消费；Bibo 只提供身份、限额、持久存储、网络、隔离执行器和 UI 的宿主适配。新增端口必须证明是真实变化点；本地产品行为与数据升级合同保持，仓库内旧 Harness SDK 调用同步迁移，不为无人使用的已发布 API 加兼容层。
- 用户持久资源、可恢复软件环境、后台任务及确有的长期服务需要明确单一 owner、版本、授权、唤醒、观察、取消、恢复和回收；未挂载环境文件明确为临时，不假称持久。环境与挂载的能力合同属于通用 NextClaw 基座，由 Agent 触发、宿主实施权限/隔离/预算/租期和兜底回收。纯聊天零容器与 OS 按需路径在同账号同会话完成。设备专属能力只能按具体任务、权限及替代路径列必要例外。
- 每类能力在 Node 和 Bibo 做成功、失败、重启恢复与用户可见反馈的正向见证；门禁对账注册能力变化与宿主映射，防止今后静默丢失。

### 4. 单一状态 owner 与可重入迁移

- Worker 方案的对话权威留在账号 DO；文件权威依 C1/C2 裁决为 DO 目录版本 + R2 字节对象，或共享持久 POSIX 文件服务，两者不可同时作为在线真相。结构化 Bibo 事项须有独立、明确 owner，不复制文件目录真相。按 BE-14 验证流/范围读写、100 MiB 双类型、执行器同版本视图、内存/延时与休眠回读；文件写入与 NCP 提交有明确失败和重试语义。若最终裁决为 D，才迁走对话权威并以同一门槛复验，绝不在线双写。
- 只读导出旧用户容器中的 Kernel journal、压缩检查点、身份/记忆与文件，结合 DO 原 UI 会话与结构化状态。按用户、会话和文件校验数量、最近内容、版本、正文摘要及模型继续输入；用迁移版本和幂等键重复运行不产生重复事件。
- 切换前保留有限旧备份；每用户有明确版本化切换点。失败时停写并用经验证的备份恢复，不允许过时快照覆盖新写入。先本地/测试环境迁移演练，再小流量灰度，最后全量；任何校验不一致暂停切换并修复。最终在线产物删除旧路径与整包快照提交，备份不作为长期运行路径。

### 5. 接通完整 Bibo 用户链路

- 新会话、已闲置一小时的旧会话、长会话压缩、普通工具、`show_file`、搜索、用户提问、文件预览、取消/刷新/重试和并发空间读取均走同一流式事件协议。用户可见的提交、保存和错误状态必须与真实持久结果一致。
- 以容器调用计数和执行轨迹证明这些请求为零，同时报告聊天启动用户进程的耗时和数量；独立 OS 工具经明确能力边界按需启动。并发版本冲突、同账号不同会话与不同账号隔离均有实际验证。
- 运行真实浏览器桌面和手机冒烟；现有 Node 包完整匹配范围 `tsc`、升级与扩展合同回归。对内容、状态、协议和持久性由 AI 自证，视觉审美再由用户评审。

### 6. 自审、主干、上线与量化复验

- 完成设计和实现 Review、diff-only maintainability、必要范围测试、迁移/恢复演练；逐项填 BE 验收账本。找出与旧版及完整本地版相比的体验退化，修复后重新验证，而不改变合同来使其通过。
- 从冻结的远程 `master` 发布同一验证产物到 Bibo Worker 与按需执行环境，记录构建、上传、切换、冒烟耗时；普通聊天更新不重建 OS 执行器镜像。若对照后裁决为 D，同样记录额外 Node 宿主的部署和运行费用。完成适用的文档站、changeset、NPM/升级合同与主干 reconciliation。
- 上线后取相同模型、地区、内容和冷/热条件的 p50/p95/p99、样本数、分段时长、错误率和每百条资源量；分别测纯聊、无需 OS 的工具及闲置后首次 OS 工具，并按真实混合负载复算三档单用户费用。只有 BE-01 至 BE-14 全部达标并经自审，才报告整体交付完成。

## 停止切换的条件

旧用户数据校验或恢复不可靠、Node 本地路径回归失败、Worker/执行器账号隔离不成立、工具/文件/问题能力缺失、生产尾延迟或成本未达到合同，均停止新路径生产切换并回到相应步骤修复，持续工作直至过线。已有假忙修复可独立保留，不能充作整体完成。
