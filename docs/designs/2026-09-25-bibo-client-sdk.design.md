# Bibo 浏览器 Client 合同

日期：2026-09-25。Bibo 页面会继续变化，但账号、会话和流式回答的 HTTP 合同需要一个独立、可测试的消费入口。现有 `bibo-chat.manager.ts` 同时保存请求路径、请求体、响应类型与 SSE 分帧逻辑；页面重做时容易复制或改坏这一层。服务端现有同站点 Cookie、Origin 校验与 `/api/*` 路径是本设计的事实边界。

## 选择与边界

建立内部 workspace 包 `@nextclaw/bibo-client`，只依赖 Web Fetch API，不依赖 React、Zustand、Cloudflare 或 NextClaw 本地 CLI。包根导出 `BiboClient`、类型与错误；账号、历史、发送、取消和清空由一个 client 实例提供。构造时可注入 `fetch` 以测试协议；生产默认调用同源 `/api/*`，发送请求保留 `credentials: same-origin`，不暴露或缓存平台 Token。

网页 Zustand store 仍拥有草稿、临时回答、保存判定后的历史与错误恢复；client 拥有请求编码、响应解码、SSE 增量事件和协议错误。删除应用内重复的传输 manager 与类型副本，不增加只会同名转发的 adapter。组件库继续仅负责展示。

最强替代是直接扩展已有 `@nextclaw/client-sdk`：它面向本地 NextClaw 服务，认证、会话模型及生命周期不同，把 Bibo 托管协议塞进去会模糊两个产品边界。另一个选择是立即生成公开跨站 SDK，但当前 Worker 拒绝非同源写请求，没有公开 Token/CORS/版本迁移合同；现在发布这类接口会给使用方错误承诺。先把真实网页消费路径提取为内部包，未来若开放外部客户端，再单独设计认证与版本合同。

## 协议与失败语义

普通请求解析 `{ user }`、`{ messages }`、`{ ok }` 等当前 Wire 格式，失败抛带 HTTP 状态的 `BiboClientError`，不把非 JSON、缺少必需字段或错误页假装成成功。聊天以 `text/event-stream` 实时解析 `accepted`、`delta`、`saving`、`committed`；文本增量到达即同步通知调用方，不能缓冲到完整回答再播放。`error` 事件、无 `committed` 的断流、非法帧与缺失 body 均拒绝 Promise；调用方继续用 `history()` 对照服务端权威历史并保留输入。部署过渡期间继续接受服务端的完整 JSON 回答，并转换为一次 `committed`。未知事件忽略以容纳向后兼容扩展，但不能绕过最终提交判定。取消仍通过现有 run ID 请求，client 不推断本轮已保存。

不修改服务端 API、持久化、限额、登录方式或真实模型流。包先标记 private；不宣称公开 SDK 或跨源支持。后续 API 版本化与外部认证需由真实第二消费场景驱动。

## 验收

1. 开发者从包根创建 client，并在无 React 环境中通过注入 Fetch 调用账号与聊天；类型检查、分块 UTF-8/SSE、错误、断流和 JSON 过渡测试通过。
2. Bibo 网页仍从正常页面发送消息，收到首个 delta 时立即展示，保存后刷新得到同一回答；失败保持原输入，停止调用 run ID。现有前端浏览器冒烟覆盖此链路；本次只改消费层，不更改模型与服务端。
3. 生产构建不包含重复的应用内网络 parser；本地 Vite 预览继续零模型成本启动。`nextclaw` 本地管理 CLI 与 NextClaw client SDK 不改变。

这是一次跨 package 的内部基础设施改造；用户可见行为应保持一致。文档交付为包 README 与 Bibo 应用开发说明。用户随后明确指出：**开发完成不等于交付完成，本次必须上线**。公开 NPM 发布仍不在本次目标内，因为服务没有跨站认证和版本合同。

## 完成交付的验收契约

- `BC1`：Bibo client 通过独立协议测试与 TypeScript 检查，网页只从包根调用它；旧应用内请求解析与类型副本已移除。
- `BC2`：同一提交进入 `origin/master`，从该冻结提交完成 Bibo 网页与 Worker 构建；发布产物能对应回提交与静态资源指纹。
- `BC3`：更新部署到 `app.bibo.bot`，线上静态资源确实包含这次 client，而不是仅有本地预览或成功的构建日志。
- `BC4`：真实账号从线上页面发起对话，正文 delta 在保存前出现；保存后刷新可继续读取该轮消息，桌面与手机没有运行错误。若生成或保存失败，仍不得把临时文字误认为已保存。
- `BC5`：原有账号、限额与 `bibo.bot/app/*` 入口不因本次客户端重构回退；若线上验证发现阻断，先恢复到先前可用版本再修正。

全部 Required 项均有与当前线上版本匹配的证据时，才报告“交付完成”。阶段切片为：冻结代码与主干 → 部署 → 真实线上验收 → 主线回流；任一阶段通过不代替整体完成。
