# Markdown 文档属性预览

日期：2026-09-14。流程：standard，风险 L2。单批完成，无独立执行计划。

## 用户链路与现状

用户从会话工作区打开带 YAML front matter 的 Markdown 文件，在预览顶部阅读文档属性，再阅读正文；点击属性标题折叠，切换源码可查看完整文件。聊天中完整 Markdown 文档使用同一渲染器，也获得一致展示。该能力减少阅读技能说明、项目文档时的格式噪声，服务长期协作中的上下文理解。纯展示能力不新增 CLI。

目前 WorkspaceFilePreviewBody 将 previewText 直接交给 ChatMessageMarkdown，后者仅注册 GFM、数学和已有自定义插件，没有 front matter 处理。源码视图独立消费原始文件，无需修改。

## 方案

由 agent-chat-ui 的 Markdown owner 注册 remark-frontmatter，仅识别文档开头的 YAML 块；局部插件将 YAML 节点映射到专门的属性组件。组件用 yaml 安全解析数据，平面对象以键值展示；复杂值、非对象或无效 YAML 保留原始 YAML 展示。限制别名展开，禁止求值，不将属性值再次解释为 HTML 或 Markdown。

选择默认展开的原生 details/summary：属性可见且可通过键盘折叠，最大高度控制长内容。使用现有主题 token、轻边框、圆角、紧凑间距和可换行布局。标题由宿主 i18n 提供，SDK 保留默认标签。原文始终可查看；格式错误不会吞正文或导致整个预览失败。

候选为仅隐藏元信息、统一显示 YAML 代码块、专门键值卡片。隐藏会丢用户信息；只显示代码块阅读成本较高；专门卡片配合原文可兼顾可读性和保真。不增加编辑器、配置状态或新的预览入口。

## 验收与审查

1. 文件预览打开含标题、布尔、数组、多行和嵌套值的文档：属性与正文分开，正文标题及目录不受元信息干扰；切源码内容不变。
2. 折叠/展开支持点击、键盘；明暗主题与窄容器正常，长字段不撑宽。
3. 普通分隔线、代码围栏中的 YAML 不误判；无效 YAML、未闭合块、别名循环和 HTML 字符串不崩溃、不执行，正文保留。

AI 以真实 ReactMarkdown 组件测试覆盖解析到 DOM，运行两个消费包 tsc 与定向 lint，浏览器验证实际渲染及折叠交互。用户只需判断视觉偏好。未发布、未提交。

方案 Review：检查主链路唯一、原始源码保真、开头识别边界、复杂数据与错误可读、国际化、键盘和主题合同；通过。实现前工作区干净，新增文件已通过 planned-path preflight。
