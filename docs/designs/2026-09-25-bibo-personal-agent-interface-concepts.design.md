# Bibo Personal Agent 界面概念：四套完整产品方案

> 2026-09-25。状态：四版交互概念已实现，待最终验证与部署。`desk-original.html` 单独保留用户喜欢的工作桌视觉初稿。此设计不是现有 Bibo 功能承诺；示例状态仅在当前页面内存保留。

## 原始问题与纠偏

现有 `app.bibo.bot` 是以对话为中心的首发页面，日程、待办、笔记、收件箱尚未形成完整的产品界面。用户希望用多套 HTML 原型比较 Personal Agent 的整体界面，同时保留有辨识度的共同工作桌方向。第一轮把四套“首页重心”误当成四个孤立模块；第二轮虽然加入对话和模块入口，却让所有入口打开同一种浅弹窗。点击后看不到导航、主操作、内容状态与回到对话的路径，不能比较完整产品。

本轮任务是设计四套**同样完整**的产品界面。用户默认进入的是概览首页；实际使用主要发生在独立的对话、收件箱、日程、待办和笔记页面。对话是最重要的一级模块，但不因此塞进每个页面。版本差异体现在概览的组织方式、整套页面的视觉系统及模块内部的阅读和操作方式，不能通过只换颜色、只展示单一模块或公用弹窗伪造差异。

## 共同产品模型与示例

四版使用完全相同的示例人、信息与任务，避免内容差异干扰视觉判断。示例：用户周五准备上线一个网站；林悦发来提前评审的邮件；陈一等待两处文案确认；日程中下午有空档，17:30 后留给自己；待办包括确认文案、回复评审时间、检查上线清单；一张笔记记着“先上线，再挑一个片段做作品集”。

共同一级入口：**概览、对话、收件箱、日程、待办、笔记**。概览是默认页，负责回答“现在值得看什么、从哪里继续”，主要承载摘要和入口；不要求在概览里写邮件、编辑笔记或进行完整对话。对话是独立的完整页面，用户可以从导航进入，也可以从概览的明确入口进入。Bibo 的主动观察可以在概览显示摘要，完整讨论进入对话；它不是第五个重复消息箱。收件箱收纳外部来信与需要用户决策的交接，二者要用发件人和类型清楚区分。概念原型不接入真实邮箱、日历或 AI，所有数据与回复都明确标为示例。

共同交互合同：每个一级入口打开当前版本内的**完整页面**，有自己的导航、内容结构、主操作、空态和返回路径；不跳到另一套版本，不用弹窗承载主模块。对话页有会话列表、消息区、输入区和与个人信息关联的来源；在足够宽的桌面空间里，右侧还有可收起的灵活工作区，能在邮件、日程、待办、笔记和草稿之间切换。对话与这些内容并排，来源可以先在右侧核对，再进入对应完整模块操作。收件箱有列表、全文与处理动作；日程有可切换的日/周视图和事件详情；待办有分组、完成与继续处理；笔记有目录、正文与编辑/关联入口。用户从模块选择“和 Bibo 讨论”时，进入独立对话页并带入所选内容的引用与对应工作区。浏览器返回键与界面返回动作方向一致。

概览与模块的区别必须在原型中实际体现：概览卡片是可读摘要和导航，模块页能连续处理多条数据、查看细节并完成代表操作。首页设计得再漂亮，也不能代替五个完整模块页面。

概览卡片的交互遵循简约原则：有明确目标的卡片以**整张卡片作为链接**，默认只呈现标题、摘要和必要状态；悬停、按下与键盘焦点提供轻量反馈。页面不在每张卡片底部重复放“打开”“查看”等显眼按钮。卡片内若有独立操作，该操作与整卡链接必须是并列可达的语义元素，不能相互遮挡；概览优先不放编辑和勾选操作，减少误触，处理动作留到模块页。

## 六个页面实际怎样用

| 页面   | 进入后看见什么                                                                     | 代表操作与可见结果                                                                                        |
| ------ | ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 概览   | 当下最重要的项目、需要回应的消息、近期安排、待办与最近笔记；一眼可找到六个一级入口 | 点整张摘要卡进入对应完整页面；从模块返回时概览仍保留原来的阅读位置                                        |
| 对话   | 会话列表、选中会话的完整消息、输入区、被引用的邮件/日程/笔记来源；一个 Bibo 身份   | 继续当前话题或新开话题；从模块带来的引用出现在当前会话中；点引用可去来源页，再回到原消息                  |
| 收件箱 | 待处理/稍后/已处理分组、发件人列表、完整邮件、附件与相关项目                       | 选邮件阅读；Bibo 可给出摘要与草稿，但发信仍由用户明确决定；处理后该项从待处理移到已处理，关联待办随之更新 |
| 日程   | 日期导航、日/周切换、事件详情；已确定安排与 Bibo 建议有不同视觉                    | 在周视图找到 14:30 空档；接受建议后才写入示例日程，拒绝则建议消失，返回原邮件时仍能看到决策结果           |
| 待办   | 今天、即将到来、按项目分组的任务；任务详情显示来源和截止时间                       | 勾选“确认两处文案”，计数和项目状态同步；点任务的来源回到相关邮件或笔记                                    |
| 笔记   | 可搜索的目录、选中笔记正文、关联的项目/来源；编辑态与阅读态清楚区分                | 打开“网站做完以后”，编辑或选中一句话，选择“和 Bibo 讨论”进入独立对话页并附上出处                          |

原型中这些操作使用同一份本地示例状态，只在当前浏览会话内演示。没有真实外部副作用。首次没有任何个人资料时，概览说明如何从一次对话开始，其他模块展示各自空态和连接入口；读取失败或不可用时保留导航与已有内容，并在对应模块说明原因，不把整站替换成空白或虚假的已完成状态。

## 方案 A：通讯优先的概览

**气质**：冷静、专业、有判断力。深色窄导航与高密度信息排布。首页先回答“谁在等我，有什么需要回应”，同时给出对话、日程、待办和笔记的概览入口。

- 首页以“待回应的三件事”为主区，旁边是今日时间、待办和最近笔记的小摘要；有一块清楚的“继续和 Bibo 对话”，但不在首页嵌入聊天窗口。
- 收件箱页采用消息列表 + 全文阅读 + 关联依据三栏；在这里处理邮件。日程页采用日/周日历 + 日期导航；待办页采用今天/稍后/项目分组；笔记页采用目录 + 正文。四页维持相同的紧凑专业视觉，但各有适合内容的布局。
- 对话页采用会话列表 + 大幅消息区 + 输入区；从邮件带入的引用以可展开来源卡呈现，不把邮件全文硬塞进聊天气泡。
- 手机端概览先显示需要回应的摘要和六个入口；模块与对话分别占用完整屏幕，返回保留列表位置。

**取舍**：最适合大量来信与需要快速处理的人；页面密度较高，对没有外部收件源的新用户需要清楚的空态。

## 方案 B：今日时间轴

**气质**：平静、克制，像把一天铺平。首页以时间关系连接消息、任务和日程，回答“今天怎样安排，哪里需要我决定”。

- 首页主区域是一条日内时间轴，旁边有收件箱、待办、笔记和对话的摘要入口。明确区分已经在日历里的安排、待办占用的时间、Bibo 尚未写入的建议；不能把建议画成已确认事件。
- 日程入口进入完整日/周视图；点击 14:30 的评审显示事件详情与相关邮件，用户可切换日期并回到今天。
- 收件箱入口进入发件人列表与邮件全文；邮件中的“查看时间”进入日程的对应日期，返回后仍是原邮件。待办入口进入完整可勾选的今天/全部清单。笔记入口进入列表与正文，能把一段笔记带回对话。
- 对话页是独立的完整会话空间，右侧可选“今天”来源栏，帮助用户讨论安排，但日程操作仍返回日程页完成。手机端时间轴纵向阅读；底部导航中的“对话”始终清楚可见。

**取舍**：适合每天高频打开，时间与注意力关系很清楚；长期目标需要一个次级区域，否则会被“今天”遮住。

## 方案 C：Bibo 的来信

**气质**：个人化、编辑感、像一个有分寸的搭档。首页是一封可读的简报概览，先回答“Bibo 发现了什么，为什么现在告诉我”。

- 首页提供两三条简短观察、依据来源和“与 Bibo 讨论”入口；这是概览，不是嵌入式聊天。点击一条观察进入其来源模块的完整页面，或者进入独立对话页并以这条观察作为讨论起点。
- 五个模块在页头稳定存在。收件箱采用舒展的两栏阅读；日程采用周视图与当天清单；待办采用“正在推进/等待他人/已完成”三组；笔记采用目录与正文；对话页像真正的通信空间，包含多个会话、消息、输入和来源引用。模块页不附加常驻聊天栏。
- 手机端用顶部标题和底部主导航。点击来源进入模块页面，返回落回原概览位置或原对话消息，而不是页面顶部。

**取舍**：最能表达长期搭档和主动判断；必须展示来源、不确定性和“稍后再说”，否则容易显得 Bibo 自作主张。

## 方案 D：共同工作桌

**气质**：触感、空间感、明确有自己的识别度。保留用户喜欢的桌面、卡片与 Bibo 形象；工作桌是**默认概览页**，不是日常处理所有事情的画布。首页先回答“我最近在忙什么，Bibo 正和我一起推进什么”。

- 工作桌展示同一项目相关的收件箱、日程、待办和笔记卡片，以及 Bibo 最近带回的一条结果摘要。卡片仅是入口与摘要，不承担完整模块功能。整张卡片可点，默认视觉不重复显示“打开”按钮；悬停与键盘焦点提供克制的边界反馈。这里**不放聊天输入框**；导航中“对话”作为独立 Tab 清楚可见。
- 点卡片后进入该模块的**完整页面**，不是弹窗：收件箱有清单和全文，日程有可切换的日/周视图，待办有分组清单与操作，笔记有目录和正文。顶部导航持续提供“概览”，模块内部不再重复一块只放标题和返回按钮的空白区域。模块以纸张、标签和桌面质感延续视觉，但真实操作采用稳定、平整的阅读布局。
- 点项目卡片进入项目工作面，能看到消息、日程、待办、笔记如何围绕同一目标组织；用户可从项目内进入任一来源，再返回项目原位置。
- 对话是同视觉体系下的独立 Tab：会话列表、完整消息区、输入区和资料引用。用户可从工作桌的结果摘要进入相关会话，但返回后仍是概览。
- 手机端先显示当前项目和 Bibo 最近的结果摘要，卡片纵向排列；进入模块后是全屏页面，底部“对话”Tab 固定。保留桌面质感，但不把桌面上的旋转纸片直接缩成难读的小卡。

**取舍**：辨识度最强，也最有“个人空间”的感觉；空间隐喻必须服从阅读与操作，不让卡片只成为装饰。

## 共同比较链路与原型验收

四版都完成相同的三条演练，才有资格比较：

1. **概览 → 对话 → 收件箱 → 日程 → 对话**：用户从默认概览进入独立对话 Tab，讨论评审时间，打开林悦邮件的完整页面，查看 14:30 的日程空档，再回到原对话决定怎样回复。成功：每一步在当前版本里有完整页面、明确返回、相关上下文没有丢失。
2. **项目 → 待办 → 笔记**：用户查看网站上线，完成“确认文案”的示例待办，打开“先上线再写作品集”的笔记，再从笔记发起对话。成功：项目、待办、笔记的关联可见，勾选与返回有反馈。
3. **手机日常进入**：390px 宽打开概览，看见独立对话 Tab 和四个模块入口，进入收件箱、打开一封邮件、切到对话。成功：主任务不被导航挤走，不横向溢出，没有桌面端才可用的操作。

原型只模拟前端状态，不发真实邮件、不修改真实日历、不保存个人数据。所有非真实能力必须在页面内标注。AI 自验负责实际点击、视觉渲染、返回链路和状态连贯；用户判断哪种空间感、信息密度与 Bibo 存在感最合适。

## 同类产品借鉴与边界

- [Meta Muse](https://ai.meta.com/muse/) 把对话作为主要入口，并强调建议、关键操作前的批准和可追溯的操作记录。Bibo 借鉴的是「建议、待用户决定、已执行」的状态区分，不照搬聊天覆盖所有工作的形态。
- [Grok Bot](https://docs.x.ai/grok-bot/overview) 把长期对话、工具活动、文件结果和需要用户注意的事项放进同一工作脉络。Bibo 的对话页因此在回答下方显示来源和一条轻量活动记录；这是本地预设示例，不暗示真实执行。
- [Today.ai](https://today.ai/articles/blog/what-is-today) 以当天安排和主动信号作为常用入口，也让用户检查长期记忆与执行前决定。Bibo 的今日节奏版验证时间导向，但另外三版仍保留不同默认入口，以比较哪一种最适合个人搭档。

三者共同提示了一个比「做一个好看的聊天窗口」更重要的问题：个人 agent 的观察、证据、建议和动作必须让用户区分。原型用日程中的已安排、待确认、Bibo 建议三种状态，以及对话里的来源和一行待确认状态体现这一点。ChatGPT Canvas 的[并排协作模式](https://openai.com/zh-Hans-CN/index/introducing-canvas/)提供另一个结构参考：讨论与可编辑内容并列，但只有在有具体内容时才打开旁侧工作区。这里参考的是空间关系，不是照搬其视觉。

## 实现自审：桌面端真实问题与修正

每次迭代至少列出五个具体可见问题，再复看改动。已发现并处理：

1. 待办四条任务占满超过 1200px 的白色画布，视线移动过远；任务区收至约 1040px，画布高度随内容收起。
2. 待办、侧栏、表单的 10–12px 中文在桌面端难读；提升主要任务文字、列表标题、输入和辅助链接字号。
3. 周日程原来仅是七列文字清单，无法看出时间；改为有时间刻度的周网格。
4. 周五 14:00 的建议与 14:30 待确认事件在周网格重叠；15 分钟建议缩至对应时间高度，短标题单行显示。
5. 对话只有回答和来源，看不出还等用户决定什么；增加轻量状态，同时明确日程尚未改动。第一版活动卡重复了回答和来源，按删减审查改为一行状态。
6. 不认识的 `view` 参数会隐藏首页并显示空白；现在回退到概览。
7. 工作桌项目卡原先落到普通待办，缺少项目语境；增加独立项目工作面及来源入口。
8. 对话原先只能通过来源链接跳离当前页，不适合边讨论边核对内容；增加右侧灵活工作区，支持来源预览、草稿编辑与收起，并保留完整模块入口。
9. 每个模块顶部都有约 100–150px 的标题带，仅显示重复的栏目标题、英文路径和“返回概览”；导航已提供当前位置和概览入口，删除整个标题带，让模块主内容直接出现。
10. 对话工作区曾同时显示五个类型标签、标题栏关闭键与会话栏收起按钮；改为从回答中的来源切换右侧内容，只保留工作区关闭键，关闭后才出现重新打开入口。
11. 收件箱邮件详情的“收件箱 / 发件人”、日程页英文月份、待办页解释关联关系的句子和笔记页编辑提示没有提供新信息；删掉，让主题、时间、正文和主操作上移。

这次删减按项目内 [UI 设计挑刺 skill](../../.agents/wiki/skills/frontend/ui-design-critique/SKILL.md) 进行。参考资料来自官方公开页面和文档，足以比较信息结构与交互意图；未取得这些产品同视口的真实应用截图，因此不宣称完成像素级视觉对标。

本演示仍有意识地只模拟代表性操作：没有真实邮箱附件、跨页面持久化、完整日期导航、拒绝建议、通用搜索、离线与错误态。它可以评估空间结构、视觉和主要路径，不能作为这些能力已经实现的证明。设计表格中的这类项目保留为产品方案要求，进入真实开发前需另行实现与验证。

## 实现与交付边界

每版可共用同一份示例事实，但拥有独立的首页布局、五个模块页面和页面状态；不把一套通用弹窗当成四版的模块实现。概念演示放在 `concept-demos/bibo-personal-agent/`，独立 Cloudflare Worker 仅发布静态原型，不触碰正式 `bibo.bot` 与 `app.bibo.bot`。先重做并验收本地四版，再部署公开概念演示。用户认可的工作桌初稿一直保留，不因重做覆盖。
