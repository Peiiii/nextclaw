# 会话发送后的阅读空间

日期：2026-09-13。类型：feature，standard / L2。单批实现，不另建 plan。

## 用户链路

用户在会话底部（距离底部不超过 80px）发出新消息，新消息上移到阅读区顶部下方 24px，回复在其下自然展开。回复未填满阅读区时视口不持续移动；填满后沿现有底部跟随继续阅读。短回复结束保留余下空间，避免回弹。

用户正在历史位置阅读时，新用户消息和回复不夺走视口；主动滚离底部立即取消已排队的自动滚动。点击现有回到底部按钮恢复跟随。切换会话仍尊重已有阅读位置恢复。

这项纯视口行为尊重用户当前阅读状态，不新增 CLI、配置或服务语义。

## 证据与选择

现有 `ChatConversationContent` 使用公共 `useStickyBottomScroll`；后者根据内容变化和 ResizeObserver 跟随底部。消息列表使用 TanStack 虚拟化，已有尺寸变化和历史前插锚定，默认不启用 followOnAppend。

选择由既有滚动 hook 管理可选的本轮留白：宿主提供最新用户消息 key、该行 DOM ref 和独立尾部 spacer ref；最新用户行通过现有 pinned range 保持可测量。key 增量区分新轮次与流式更新，加载历史和会话切换建立基线，不提升已有消息。是否跟随复用插入前最近一次滚动状态，不能用插入后增长的 scrollHeight 决定。DOM 留白和尺寸测量同属滚动同步 owner，不增加业务 manager。

固定 padding 会在长回复后留下额外空白；持续将用户消息强制锚在顶部会阻碍用户浏览。动态留白只补足本轮未占满的视口，复用原底部跟随路径。

## 不变量与验收

- 新轮次：底部与 80px 内触发，历史位置不触发；初次载入已有消息不提升。
- 流式输出：内容高度增加时留白等量减少，未填满前 scrollTop 稳定；超过一屏后正常跟随。
- 主动滚离：取消排队滚动；后续内容增长不夺焦点。
- 完成、取消、错误：不因运行状态终止清空留白；下一轮更新锚点。
- 历史前插、会话切换与恢复：沿原有虚拟化/恢复合同，不将历史当新发送。
- 覆盖连续发送、长消息、视口 resize 和小视口；匹配 package tsc、定向 DOM 回归和真实页面检查。

黄金验收：在底部发消息观察回复填充；翻到历史再发消息观察阅读位置；回复期间上滚确认停止跟随。空间大小属于用户可继续确认的视觉偏好。

## 方案审查

design-review: passed。复用单一滚动 owner 与现有虚拟化，留白不参与自然内容 ResizeObserver 测量，避免反馈循环；无公共协议或持久化变更。交付为当前工作区未提交修改，不发布。

## 实测修正与消息折叠动画

真实页面发现：typing 行替换为短回复时，虚拟列表会瞬间缩小，独立 spacer 尚未被 ResizeObserver 更新前浏览器就会夹住 scrollTop。最终使用外层 frame 的 min-height 保持“锚点 + 一屏”下界，自然内容在内部增长，空白由布局自动消耗，消除该时间窗。

进一步取证确认 TanStack `resizeItem` 在 `anchorTo=end` 下优先按虚拟内容末端补偿尺寸差，绕过 `shouldAdjustScrollPositionOnItemSizeChange`，实际将短回复视口上移了 105px。`scrollEndThreshold=-1` 禁止这个自动末端补偿（内部距离下界为 0），同时保留前插锚定；唯一底部跟随 owner 仍为 `useStickyBottomScroll`。补充末端内外位置与增长/缩小的回归矩阵。

用户补充要求覆盖消息内部所有折叠入口，包括已处理、思考过程、工具组以及命令、文件、搜索和通用工具详情。统一使用 `ChatCollapsibleContent`：200ms 高度过渡，快速反向操作从当前高度继续，收起完成后卸载，关闭即 aria-hidden/inert，减少动态效果时直接切换。内容以 render callback 懒构建，不提前格式化所有工具载荷。箭头同步采用 200ms 过渡。

方案补充审查通过：直接条件卸载不能产生退场动画，始终挂载会增加历史工具渲染成本；统一管理动画存续期保留原有懒加载边界，不建立多个计时状态 owner。增加中断/反向、DOM 身份、减少动态效果和真实已处理/工具组/工具详情验证。
