# 页面操作层级与行内反馈

日期：2026-09-13。范围：UI 公共页面操作入口及其全部调用位置。风险 L2，standard。

## 问题与目标

统一资源操作接入后，普通路由页出现无标题工具栏，布局命令抢占业务菜单首屏，收件箱菜单被插入正文流，侧栏选中背景没有覆盖更多按钮。目标是让用户优先处理内容，降低工作台布局管理的干扰，服务长期搭档的统一体验。

## 冻结方案

- 移除普通路由页独立的 CurrentPageActions 栏；设置仍由设置导航承载，资源链接兼容保留，不改持久化。
- 业务操作优先。添加到聊天、复制链接为资源操作；打开位置和固定页面归入“布局与位置”二级菜单。复用公共 ContextMenu 模型和渲染，不在业务页复制动作。
- 更多按钮在工具栏业务操作末尾；关闭是独立容器控件，可保留最右侧。标题与右侧控件分成两个区域，不使用三个项目的 justify-between。
- 列表导航和菜单为兄弟控件，整行共同承载 hover、选中、焦点反馈；菜单在行内右侧，长标题可截断，不占独立一行。
- 二级菜单采用保留父菜单的侧向级联，悬停/点击/右方向键打开，左方向键/Escape 退当前层；禁止替换父菜单的导航页。窄屏自动换边、按可用宽度收缩，不裁切操作。

## 选择与审查

拒绝仅在截图位置补 CSS：通用菜单优先级仍会污染其它入口。拒绝取消所有资源操作：真实资源仍需移动和引用。复用既有资源 manager，不新增业务状态或配置。

方案 Review：已核对 ContextMenu、PageResourceActionItems、路由壳、收件箱、侧栏、会话和应用工具栏；保留已有动作回调与授权语义。设计审查通过，键盘/焦点与嵌套点击纳入验收。

## 验收与交付

设置桌面/移动壳无空操作栏；收件箱长标题菜单同一行且不误导航；阅读弹窗菜单紧靠右侧控件；侧栏整行反馈；会话/应用更多为最后业务按钮；业务动作先于资源辅助动作且布局默认收起。检查全部公共入口，运行 UI tsc、定向测试与实际渲染检查。纯 UI 调整无 CLI 新增。同步中英文用户说明；交付隔离 worktree，未授权提交或发布。

## 调用位置排查与复盘

已检索 UI 源码全部 PageResourceActionsMenu、PageResourceActionItems、usePageResourceActions 和 MoreVertical/MoreHorizontal/Ellipsis 入口。修正范围覆盖普通路由壳、桌面与移动壳、收件箱列表及阅读弹窗、左侧页面导航、会话标题工具栏与工作台标签菜单、应用工具栏、Agent 列表和详情、定时任务行、服务应用、MCP 卡片与项目技能卡片。

### 级联菜单纠偏

上一版错误地采用父菜单替换式导航，原验收只覆盖了折叠与键盘，漏掉父子菜单空间关系。删除该路径；在同一 context-menu 模块拆出唯一 items renderer，内部复用现有 Radix Popover 的定位、碰撞与浮层生命周期，未引入新依赖或平行业务菜单。普通资源、会话、应用、Agent、定时任务及服务应用均消费同一渲染，父子 surface 与嵌入式菜单 variant 复用同一样式定义。

按 [Radix Popover 合同](https://www.radix-ui.com/primitives/docs/components/popover)定制方向、自动焦点和可用空间；真实验证覆盖侧栏资源与会话浮层两个宿主、右侧边缘向左展开、390×844 窄屏、Escape 退层及父条目焦点。新增 hover/点击切换测试证明父子同时存在，不再用“二级已隐藏”替代级联验收。用户要求的“共享组件 + skill + 失败路径回归”闭环已合并到原交互质量 skill，不新建同类规则。
