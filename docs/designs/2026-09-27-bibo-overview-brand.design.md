# Bibo 概览品牌形象

日期：2026-09-27。来源：用户要求把官网形象带入应用概览，增强趣味与品牌辨识度，并明确要求落地上线。

## 现状与方案

现网 `https://bibo.bot/` 使用紫色大眼睛、圆润身体和搭边双手的角色；源为 `apps/bibo-camera-site/dist/index.html` 与 `styles.css`。应用 `https://app.bibo.bot/` 的概览由 `Overview` 展示，摘要来自现有 space store，当前仅用星号作标记。本地主工作区版本较旧，以已拉取的远程 master 为基线，隔离工作区实现，不改其它任务草稿。

用户上线后纠偏：「不应该被当做某个跳转的触发」「放到欢迎语的旁边」「不要耦合」。据此替换最初的摘要卡内展示方案：角色与「日常，多一个我。」放在顶部欢迎区，和日期问候并列；欢迎区没有点击、链接、焦点或悬停动作。角色使用应用内 SVG 表达官网相同造型及颜色，不依赖外站请求，也不读取摘要、任务或运行状态。

品牌和文案归 Bibo 应用，领域数据仍归 space store；摘要导航独立位于欢迎区下方，使用 Router Link，保留真实 href 与既有目标选择。角色无 props、事件、业务状态或路由依赖；不通过通用标题的 action 槽放置角色。桌面角色在欢迎语右侧；手机缩小且不挤占下方摘要。经典和简约主题沿用各自表面及文字 token，紫色保留为固定品牌资产色。

## 用户链路与验收

1. 登录打开 `/`，欢迎语旁显示官网同款角色。点击或悬停角色不跳转、不触发摘要反馈，角色不进入键盘 Tab 顺序；它没有交互祖先。下方真实摘要入口仍进入原收件箱／任务／对话；返回概览，原数据与卡片仍可用。
2. 空空间进入概览，也能看到角色和开始对话入口；不显示虚构任务、记忆或运行状态。加载与失败继续使用现有反馈。
3. 桌面、390px 和 320px 手机宽度检查欢迎区、卡片、角色、文字、摘要键盘入口，没有横向溢出；两种主题可用。角色无动画，无需额外减少动态效果分支。

运行应用三个 tsc、客户端构建、既有桌面／手机产品冒烟；对概览补实际截图和入口检查。发布走现有 `deploy:client`，不滚动未变容器；冻结远程 master 后发布，并核验部署版本、线上角色、真实账号概览与导航。此次是纯展示改动，无存储迁移、NPM 或 Desktop 发布，也不增加 CLI。
