# 侧边栏上下文悬浮信息卡片设计

## 背景与用户任务

用户在桌面端浏览会话侧边栏时，希望项目行与会话行默认保持简洁；当指针停留在某一行时，再快速确认这个对象的关键上下文，而不必进入会话概览页。成功表现为：项目行不再常驻显示会话数量，展开图标只在 hover 或键盘聚焦时出现，项目与会话都能显示来源可信的悬浮信息卡片。

## 当前事实与约束

- 项目行由 `ChatSidebarProjectGroups` 渲染，现有固定数字来自 `group.items.length`。
- 会话列表已经从会话查询中得到项目归属与父子会话关系。
- 会话概览页的定时任务来自全局 cron 查询，并通过 `payload.sessionId` 与会话关联。
- 项目折叠、创建、置顶与会话选择、编辑等动作已有独立按钮；悬浮信息不能嵌套交互控件或抢占这些动作。
- 当前范围只增加只读信息透出，不改变会话、项目、cron 的 owner、持久化与服务协议。

## 方案选择

### 候选 A：使用现有 Radix Tooltip 承载只读富内容（采用）

Tooltip 原生支持 hover、focus、Portal、碰撞避让和延时展示，适合不可交互的只读摘要。触发器只包裹现有主按钮，避免交互元素嵌套；卡片本身不承载操作。代价是卡片不能被点击，但本次需求只是快速透出信息，正好保持侧边栏主任务不分叉。

### 候选 B：使用 Popover 并自行管理 hover 开关（不采用）

Popover 适合可交互内容，但 hover 开关需要额外计时、hover bridge 与焦点状态，且容易和行内新建、置顶、更多菜单竞争。当前没有卡片内操作，不值得引入这套状态。

### 候选 C：绝对定位 CSS 卡片（不采用）

实现最短，但会受侧边栏滚动容器裁剪，需要自己处理视口碰撞、层级与键盘路径，重复现有浮层 primitive 的职责。

## 冻结设计

- 在侧边栏层只执行一次 `useCronJobs({ all: true })`，生成 `sessionKey -> cron count` 映射；不在每一行发查询。
- 会话卡片消费当前行已有的标题、项目名、子会话数量和映射后的定时任务数量。
- 项目卡片消费 `group.items`，会话数取当前分组长度，定时任务数按分组内会话 key 聚合；项目路径仅作只读上下文。
- 使用现有 Tooltip primitive，统一右侧弹出、短延时、圆角边框和轻量阴影；内容 `pointer-events: none`，不会吞掉行内动作。
- 卡片采用单一纵向信息流：只保留一个标题，项目、路径与数量都进入后续的同构信息行，统一使用相同字号、行高、图标尺寸和“字段名在左、值在右”的布局。禁止副标题、嵌套指标卡、双列网格或标签/数值两级排版，避免少量信息产生过多几何变化。
- 项目展开/收起图标保留在项目主按钮内，但默认透明且不占据视觉注意力；hover、focus-visible 或卡片开启时可见。项目固定数量从主行删除。
- 会话行不再额外显示“子会话数量”快捷按钮；该数量只在悬浮卡片中出现。hover 时标题区只为置顶、编辑和更多操作预留空间，避免重复信息与操作组重叠。
- 会话和项目行的原点击语义、独立动作按钮、折叠状态、筛选与排序均保持不变。

## 验收标准

1. 项目默认行不显示会话数量，展开图标默认不可见，hover 或键盘聚焦时出现。
2. 项目 hover 卡片展示项目名、路径、会话数与关联定时任务数。
3. 会话 hover 卡片展示标题、项目上下文、子会话数与关联定时任务数；无数据时显示 0。
4. 项目折叠、新建、置顶和会话选择、编辑、更多操作均无回归；DOM 中不存在交互元素嵌套。
5. 定向组件测试、`nextclaw-ui` TypeScript 检查和真实页面视觉检查通过。

## 非目标

- 不给卡片增加跳转、编辑或快捷操作。
- 不新增后端 overview API，不改变 cron 与 session 的关联协议。
- 不在本次扩展更多概览指标；后续只有出现稳定用户需求时再增加。
