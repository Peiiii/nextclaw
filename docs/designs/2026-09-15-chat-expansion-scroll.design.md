# 展开内容时保留阅读位置

## 问题与用户链路

用户在会话底部展开工具组、单条工具或过程详情，是要从当前标题往下阅读。现有 `useStickyBottomScroll` 的 ResizeObserver 将展开动画、异步详情加载与流式增长统一执行贴底，导致阅读位置跳走。

修复后：用户在底部点击或用键盘展开 → 原滚动位置保留 → 动画、详情加载及后续流式输出不抢回视口 → 用户滚回底部阈值或点击回到底部按钮后恢复跟随。普通流式输出仍遵守既有阈值。

## 决策

- bugfix，L2；状态 owner 保持在现有滚动 hook，单批实现，不另建 plan。
- 在滚动容器捕获展开控件的激活动作，在组件更新高度之前取消排队滚动并退出 sticky 状态。覆盖 `aria-expanded=false` 的行内展开控件与原生 details/summary；排除 popup 和行内独立交互控件。
- 键盘 Enter/Space 同样处理，兼容工具标题的自定义 role=button。
- 不使用短暂超时屏蔽：展开动画和异步加载可能超过超时，后续输出仍可能重新拉到底部。
- 不分散给每个工具组件维护滚动状态，也不新增公共 SDK API。
- 纯滚动交互，不适用 CLI、持久化和迁移。

## 验收与方案审查

覆盖底部/阈值内展开、长动画多次 resize、异步详情及并发流式更新、已排队滚动、键盘、原生 details、独立子控件、普通流式跟随、手动恢复和会话切换。用回归测试复现修前错误，并在本地实际会话验证工具组和单条工具展开及恢复。

方案 Review：现有共享滚动 owner 足以承接，各展开入口已有语义属性；捕获阶段先于组件状态更新。无新增平行状态，恢复沿既有入口，方案通过。

## 补充：工具组高度与边缘提示

用户补充要求长工具列表约半屏高度。工具组标题保留在外，展开内容最大高度为 `50dvh`，短列表不填满；长列表内部滚动，到顶/底后继续向同方向滚动时由外层自然接续。保留每批 40 项机制。

边缘 mask 根据真实溢出和滚动位置更新：顶部还有内容时上渐隐，底部还有内容时下渐隐，无溢出不渐隐。ResizeObserver 同时观察视口与内容，覆盖嵌套工具展开、异步详情及窗口变化。滚动区可键盘聚焦，名称复用工具组摘要。

选择动态渐隐而非常驻双侧渐隐，避免到底仍暗示有内容；选择局部工具组组件而非改全部折叠容器，避免限制正文和所有单工具详情。此次不声称复刻或已对照 Codex 当前版本。

补充方案 Review 通过：新增边界只负责工具组 DOM 滚动呈现；外层 sticky 状态仍归原 owner。验收追加短/长列表、顶/中/底渐隐、内部滚轮、嵌套展开、窄屏和键盘滚动。无后端和协议变化。

## 补充：消除嵌套动画接力

现有折叠容器在初次挂载为 open 时也从零动画；父容器观察子元素动画的每次高度变化，又完整重启 200ms 过渡。已经展开的祖先也继续对后续尺寸变化做相同动画，造成多层接力。

保留共享 `ChatCollapsibleContent`：首次挂载直接呈现当前状态；用户切换才动画。切换期间内容尺寸改变，从当前画面重定向但只使用原 200ms 截止时间内剩余时长；完成后恢复 auto，不再为子元素高度变化追加父层动画。保留快速反向的 DOM 身份、关闭时 inert 和 reduced-motion。

方案 Review 通过：去掉持续被动动画职责，不引入第二动画 owner。验收补默认打开子层不单独入场、展开后异步增长不重播、切换期尺寸变化不延长总时长和快速开关不卸载内容。

## 用户纠偏与恢复

- 输入面板越界：在现有 Chrome 页面测得模拟视口 1440×900、真实窗口 1512×827。清理残留模拟尺寸后两者重新一致，输入面板下沿 811px，小于 827px。当前布局没有对应源码缺陷，不添加尺寸补丁。
- 初版工具组误用了 overscroll containment，用户要求边缘自然传递；已删除，并同步清理普通内嵌项目工作项和模型建议列表。独立弹窗/浮层边界继续隔离背景，画布滚轮缩放不改。规范落在原前端交互 owner，不新增发现入口、脚本或 baseline；AGENTS、skill 数、description 和常驻 discovery 体积不变。未来只在明确改变产品滚动交互时复核该规则。

- 动画回归证明默认展开不再启动动画；150ms 时收到新尺寸只剩 50ms 过渡，完成后内容增长不再重播。快速反向保持同一 DOM，关闭 inert 与减少动态效果保留。
