## 目标与事实

用户在现有会话视图切换入口选择“定时任务”，能单独查看定时任务创建的会话并打开结果；搜索、置顶、翻页和刷新维持该范围。这让长期自动化工作更容易追踪，不复制定时任务配置管理页。

现有 `createCronJobHandler` 默认使用 `cron:<jobId>`，并传递 `session_origin=cron`、`cron_job_id` 和任务名称；kernel 创建会话时保存该 metadata。同一任务复用一条会话，列表不是单次执行日志。显式绑定已有会话时 kernel 复用原身份，不改变该会话来源。已有 UI 也通过 `cron:` 前缀识别历史定时会话。

已询问是否包含绑定的普通会话；未收到偏好时按推荐范围实现：专属会话及来源明确的定时会话。已有普通会话不会仅因某个定时任务绑定它就改分类。定时任务尚未产生会话时本视图不展示空任务对象，配置、启停与手动触发仍在原定时任务页。

## 方案与主链路

保留既有会话列表和唯一设置 owner；增加 `scheduled` 视图，前端 store 保存视图偏好。后端会话查询接收 `scheduledOnly=true`，SQLite 目录在 COUNT 与 LIMIT 之前用同一条件筛选：来源为 cron、非空文本 cron_job_id，或历史 cron: 会话 ID。名称或消息包含“cron/定时”不作为分类依据。保留置顶优先和活动时间排序。

会话分页 filter 复用 kernel 公共类型；将已有 peerId 参数并入同一分页查询，支持与定时筛选及搜索组合，不保留绕过筛选的 peerId 分支。普通 listSessions 工具入口保持原行为。SDK 序列化布尔值；HTTP 对非法值返回 400。

UI infinite query key 包含筛选范围，切换模式从第一页读取；定时范围的摘要事件使该范围重新查询，不能将普通摘要写入定时缓存。桌面分段按钮、手机菜单和标题切换器统一使用 `ChatSessionListMode`。定时视图沿用日期及置顶分组，空列表和搜索无匹配有明确提示；手机标题显示当前定时范围。

候选比较：只在前端过滤已加载页面会漏旧记录；另建任务面板会复制配置与会话入口。复用会话目录的服务端过滤满足当前入口，新增参数和 mode 均有消费者，不建设通用分类 registry 或新 service。

公开变体传播：scheduled mode → store 解析/持久化 → manager → 桌面/手机/标题控件 → query scope/key → SDK → HTTP → kernel filter → SQLite 条件/计数/分页。运行时类型、会话写入格式和安装迁移均无变更；旧 time/project 值继续有效，非法存储值回默认 time。新查询省略或 false 时是原范围。

共享持久化合同的另一实现 `CloudflareSessionStore` 同步支持 peerId 和 scheduledOnly，在计数及分页前组合筛选。当前 Bibo 产品没有调用该分页筛选的新参数，本批只保持存储合同兼容，不新增 Bibo 页面或安排 Bibo 部署；适配器测试及其应用 tsc 已覆盖该实现。
