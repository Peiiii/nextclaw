# Bibo 对标 Typora 的正文编辑

## 原始输入与对齐

用户在上一版上线后指出体验不足，本次明确要求 AI 自己制定目标、集中排查、高效一次性优化，减少人工介入，并以 Typora（语音“Tara”）为标杆。原话：“你自己给自己设定一个目标……最节省投入的方式……一次性排查清楚……直接达到 Tara 的这个水准”。本次是体验纠偏，继承上线授权；不要求用户逐项指导。

有效标准：[BT-01..08](../work/2026-09-28-bibo-typora/acceptance-contract.md)。参考 [Typora Markdown Reference](https://support.typora.io/Markdown-Reference/)（2026-09-28 查询）与 [Crepe 官方文档](https://milkdown.dev/docs/guide/using-crepe)，包版本 7.22.2。本文替代上一设计中“以源码装饰提供主编辑”的选择；保留 store、版本与草稿保护合同。

## 用户链路

已有文件打开仍阅读。点编辑后在排版正文中输入，标题/粗体/列表是文档结构，表格单元格可直接修改，图片可插入，链接能调整；代码和公式有专门编辑呈现。常用格式按钮可见，低频插入收进菜单。阅读/编辑为主模式，源码是次级操作。阅读往返保留实例、选区和历史，保存继续使用既有按钮及快捷键，并显示真实状态。

混合旧文档进入编辑不能立刻变脏；不认识的语法作为可见的原文结构保留并可修改，不能在序列化时消失。源码修改仍可用；转换可规范化 Markdown 排版，但不得改变内容语义。保存失败/冲突、刷新草稿沿现有 store 和版本合同。

## 方案取舍与 owner

最终选择 Tiptap 3.31.3 + ProseMirror；源码编辑保留 CodeMirror。用户追加明确优先级：“用户体验是第一位的……开发成本是比较小的”，因此撤销仅凭现成组件多/接入成本低而冻结 Milkdown 的结论。隔离对比见[选型实验](../logs/2026-09-28-bibo-markdown-editor/artifacts/2026-09-28-editor-benchmark.md)：长文、CPU 4x 下 Tiptap 事务 p95 4.4ms、转换 p95 20ms，Milkdown core 分别 17.3ms/152.1ms。基础挂载 Milkdown 更快，未声称全指标领先；选择依据为日常输入与转换优势。移除 Milkdown 试验实现和依赖。

首要比较：输入响应、中文输入、跨段操作/历史、长文性能、冷启动、手机响应、内容保真。开发维护成本只能在体验相当时决定。两者共用 ProseMirror 不证明性能相同；Crepe 的 Vue 节点视图、全量序列化和资源体积需要实测；Tiptap 官方 Markdown 扩展标记 Beta 是风险，不是自动淘汰理由。使用相同文档、功能集合与浏览器环境，分别记录基础内核与完整集成的开销，禁止拿裸 Tiptap 对完整 Crepe 的数字直接宣布胜负。

公开 MarkdownEditor 仍为唯一宿主入口；富文本内核的创建、外部同步、事务与销毁由编辑 manager 统一管理，React 负责挂载和展示，不建第二份业务文档 store。读取 value 不写回；只有实际用户事务才更新父级。读写互切不销毁实例。外部冲突恢复与源码更新通过显式替换进入编辑内核，不伪装成用户输入。两种内核分别按需加载；键入时由内核更新，停顿 250ms 后同步 Markdown；失焦、指针操作、保存快捷键、卸载和离开页面时立即同步。快捷键保存读取 store 最新状态，防止 React 闭包落后。Mermaid 预览独立 React root 延迟卸载，避免嵌套提交冲突。

保存仍是 Markdown。先验证 commonmark/GFM/math 对应；针对不被内核表示的 frontmatter、HTML、脚注等，保留原文节点并注册相应 parser/serializer，不允许忽略。图片支持 HTTPS 地址插入和点击改址，当前 Bibo 文件服务没有二进制上传合同，不凭空引入另一套存储；不持久化 blob URL。代码图表复用既有安全 renderer；不引入远程内容执行。

样式归共享 UI，宿主不补内核 DOM CSS。统一正文宽度、字体与间距；编辑工具栏占用受控，手机和窄工作区仍能操作。中文文案由宿主 labels 注入。编辑器按需加载，不让默认阅读承担完整初始化成本。

# 第三轮：连续写作与呈现一致性

块边界补充（用户 2026-09-28）：代码/图片等块须有整块选择、删除、撤销和前后继续写作路径。保留 PM NodeSelection/GapCursor，不用弹窗承担选择；代码框边缘与独立整块选择入口，图片单击先选中再显式编辑。块后有段落时进入段落起点，无段落时使用 gap cursor；键盘删除/撤销回归。预览样例追加图片，不能覆盖用户草稿。此局部交互补全通过方案审查，数据与保存 owner 不变。

表格方案纠偏（用户截图 c7caf6c7）：禁止点击单元格自动展开四按钮面板。对照 Notion 官方 Format your page / Simple tables（2026-09-28 读取，https://www.notion.com/help/columns-headings-and-dividers）：底边 + 增行，右边 + 增列，对应行列手柄打开上下/左右插入及删除菜单。采用原 TableView 扩展局部控件，PM 继续拥有表格/尺寸/选区，React 只拥有非编辑控件；不新增全局坐标追踪器。普通输入不打开菜单、不遮挡单元格；菜单明确操作范围并可撤销。下文“表格附近呈现增行增列和删除入口”以此为准，原自动浮层退出。受影响方案 review: passed，需边缘控件/作用行列/键盘/手机实测，不接受仅按钮存在的验收。

用户最新原始反馈要求：预览/编辑的几何和颜色几乎一致；必须有 slash command；表格增删行列可发现；公式不依赖模态弹窗；链接可就地编辑和取消；“正在打开编辑器…”在内容区域正中央。此前功能通过不能证明这些体验达标。

沿用 Tiptap/Markdown store 单一链路。文档排版抽为共享样式，同时作用于阅读渲染与 ProseMirror；聊天排版保持独立。对正文、标题、列表、引用、表格、代码、公式测量 computed style 和相对位置，差异超过 2px 必须解释或修正。编辑操作 chrome 可以不同，正文几何不能因它额外漂移。

黄金链路：打开阅读→编辑（延迟加载时中央状态）→空段输入 `/`→键盘搜索/选择表格→单元格附近增行增列→点击链接修改或取消→点击公式就地编辑并实时预览→Esc 返回正文→预览核对→保存刷新。桌面与窄屏都必须完成，焦点和撤销由 PM owner 保持。

交互选择：命令面板靠光标、不抢输入焦点，真实键入斜线触发，支持过滤/上下/Enter/Esc，退出后不因 selection 自动复活。表格附近呈现增行增列和删除入口，沿用 PM 命令。链接/公式使用非模态上下文编辑面板，公式实时预览，取消不写入，确认后恢复编辑焦点。共享 Popover primitive 承担避让和外部关闭；编辑器 manager 拥有位置与动作语义。不引入另一套持久化或编辑内核。

设计审查：对取消、失焦、中文组合输入、撤销、窄屏避让、源文本保留及保存时机逐项核对，设计覆盖当前反馈；design-review: passed（单代理）。design-document: required；plan: not-required，沿用验收合同逐项收敛。加载居中为独立显然修复，提前定向验证；其余按本修订实施。

### 用户 Notion 截图纠偏：统一块手柄（由下节完整能力合同细化）

来源为用户截图 `codex-clipboard-2ac198e5-ccb6-46c9-bc88-e5b62e09ff16.png`。用户明确撤回“通过块尾光标删除”的先前假设，要求采用 Notion 左侧六点手柄→块菜单→删除。此要求替代 BT-12 中自定义块尾点击和两次退格删除主路径；正常内核光标/撤销仍保留。图片选中描边贴合图片边缘，不保留外偏移白缝。

统一浮动手柄跟随悬停或键盘所在的正文块，打开菜单时锁定目标并显示整块选中态。菜单按截图约 280px 的实际 CSS 宽度、搜索框、块类型标签、图标加文字行、分隔线排列，优先出现在手柄左侧，空间不足避让。提供可搜索的现有动作：复制代码/更换图片或编辑公式（适用时）、创建副本、在前后插入段落、删除。无对应 Bibo 能力的评论、AI、跨页移动和持久化块链接不做空壳按钮。匹配截图的布局与操作范式，不声称截图缩放未知时所有设备物理像素一致。

PM 拥有节点与事务；专用块 manager 只管理目标位置、菜单状态和块操作，事务映射防止删除错块。仅一个浮动组件，不为长文每个节点挂 React root。原代码选择/继续写、图片删除/继续写、整表独立菜单移除；表格内部行列控制保持原 owner。块复制与删除各为独立可撤销事务，关闭菜单恢复正文焦点。图片保留 inline schema，修正上游 paragraph Markdown parser 对独立图片的错误解包，不引入第二 serializer。

黄金链路：悬停代码/表格/图片/段落→左侧手柄→搜索“删除”→整块删除→撤销恢复→创建副本→保存刷新；窄屏选中块后使用同一手柄与菜单，菜单可滚动、不出视口。另验证图片混排后回车和 slash，防止非法根节点破坏后续输入。design-review: passed（单代理，核对用户截图、位置映射、菜单焦点、撤销及长文单实例）；plan: not-required，原单批交付继续。

### 2026-09-29 完整块操作能力合同（现行）

用户追加代码工具栏内手柄截图，并明确要求按 Notion 整体设计、实现与验收。定级为能力面缺失：同一块操作由代码、图片、表格各自承担，修改单个坐标不能消除其它入口重复。编辑内核、保存与持久化模型没有冲突，不升级为全系统重构。产品目标是减少用户理解不同内容操作方式的负担，符合长期搭档愿景。

依据：用户两张 Notion/现状截图；Notion Writing & editing basics（https://www.notion.com/help/writing-and-editing-basics，2026-09-29 查询）定义左侧手柄、点击菜单与拖动移动；Tiptap Drag Handle 官方合同（https://tiptap.dev/docs/editor/extensions/functionality/drag-handle）提供统一定位、嵌套规则、目标变更、锁定及拖动生命周期。采用官方扩展而非各 NodeView 定位，也不自行维护第二套拖放引擎；Bibo 只拥有块动作语义、菜单展示和本 schema 的嵌套策略。此前草拟的纯顶层 pointer 扫描退出。

块集合：正文、标题、代码（含 Mermaid）、表格、独立图片段落、块公式、分隔线及保真原文块均为独立块；列表的单个 listItem/taskItem 可操作，嵌套项跟随实际层级；引用整体可操作。表格单元格、行内公式、链接、粗体是块内内容，不再出现第二个块手柄。列表项删除/复制包含其子列表，不误操作整个列表；最后一项删除保持文档合法。特殊节点只贡献适用动作，不拥有另一套手柄。

统一行为：左侧留白六点手柄，悬停目标显示，键盘/触屏选择也有入口；单击选中并打开菜单，拖动通过上游内核移动，释放有落点反馈并可撤销。菜单打开锁定目标，文档事务映射目标，删除/外部替换失效时关闭；滚动/缩放重定位，离开可视区域不悬浮到工具栏。读模式无手柄。菜单复用共享 Popover 的焦点与碰撞处理，搜索、上下键、Enter、Esc、外部点击可用。

菜单按 Notion 紧凑图标加文字布局：适用的转换类型、编辑图片/公式或复制代码；通用创建副本、在前后插入、删除。转换仅暴露可无损完成的文本类目标，不把表格/图片强制变正文丢内容。复用格式命令，不新造转换器。拖动和复制保留节点属性、嵌套结构与文本；所有内容变更进入同一 PM 事务和历史，并走既有 Markdown 保存。暂不扩展 Notion 数据库、评论、权限、AI、跨页移动或块永久链接；当前文件模型无其合同，不以空壳仿制。

空间密度补充（用户 2026-09-29）：块手柄与表格行列手柄均用编辑器专用紧凑尺寸，复用行为组件但不继承通用工具栏的 padding/min-size/32px 悬停伪元素。块按钮 20×24px、图标 16px；行列按钮与底色 18×18px、图标 12px，padding 0。热区不得侵入正文、列表标记或相邻操作，三宽度实测几何和可点击性；表格行列与整体块入口分别表达作用范围。

后续纠偏合同：表格行列插入以新建单元格为事务选区，菜单关闭不恢复旧单元格；块轮廓内贴边，不用正 outline-offset 形成白缝。公式快捷入口支持空段 `$$` 后按空格或 Enter（Typora 官方 Math 文档 https://support.typora.io/Math/ 使用 Enter，空格为用户明确要求）。就地编辑确认时原子替换该段为 blockMath，取消保留 `$$` 原输入；组合输入/代码/普通行内双美元不误触。textarea Enter 保留换行、Cmd/Ctrl+Enter 确认；提供 aligned 多行示例并验证保存与预览，空格换行本身不擅自改写 LaTeX 语义。局部设计 review: passed，沿用编辑 manager/现有 inspector，无第二公式状态 owner。

公式类型入口补充：slash 与更多格式均明确区分「行内公式」和「公式块」，搜索 math/equation/latex/公式均可找到；前者执行 insertInlineMath、后者 insertBlockMath，编辑器标题跟随 inline 标志。`$$` 快捷入口固定为公式块。验证两者 DOM 位置、Markdown 序列化、阅读往返和取消，不以一项「公式」隐藏两种语义。

删除项：代码工具栏的六点选择和块后写入、图片独立删除/写入、表格整块专用菜单、自定义块尾点击与 Backspace 选前块。保留项：代码语言/复制/图表切换、表格内部行列菜单与增行列、图片贴边选中轮廓、标准光标历史、读写共用排版。抽象仅为当前所有块共享的单个控制器/浮动入口，无跨应用 registry。
