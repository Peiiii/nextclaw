# Bibo 对标 Typora 的正文编辑

## 原始输入与对齐

用户在上一版上线后指出体验不足，本次明确要求 AI 自己制定目标、集中排查、高效一次性优化，减少人工介入，并以 Typora（语音“Tara”）为标杆。原话：“你自己给自己设定一个目标……最节省投入的方式……一次性排查清楚……直接达到 Tara 的这个水准”。本次是体验纠偏，继承上线授权；不要求用户逐项指导。

有效标准：[BT-01..08](../work/2026-09-28-bibo-typora/acceptance-contract.md)。参考 [Typora Markdown Reference](https://support.typora.io/Markdown-Reference/)（2026-09-28 查询）与 [Crepe 官方文档](https://milkdown.dev/docs/guide/using-crepe)，包版本 7.22.2。本文替代上一设计中“以源码装饰提供主编辑”的选择；保留 store、版本与草稿保护合同。

## 用户链路

已有文件打开仍阅读。点编辑后在排版正文中输入，标题/粗体/列表是文档结构，表格单元格可直接修改，图片可插入，链接能调整；代码和公式有专门编辑呈现。常用格式按钮可见，低频插入收进菜单。阅读/编辑为主模式，源码是次级操作。阅读往返保留实例、选区和历史，保存继续使用既有按钮及快捷键，并显示真实状态。

混合旧文档进入编辑不能立刻变脏；不认识的语法作为可见的原文结构保留并可修改，不能在序列化时消失。源码修改仍可用；转换可规范化 Markdown 排版，但不得改变内容语义。保存失败/冲突、刷新草稿沿现有 store 和版本合同。

## 方案取舍与 owner

最终选择 Tiptap 3.31.3 + ProseMirror；源码编辑保留 CodeMirror。用户追加明确优先级：“用户体验是第一位的……开发成本是比较小的”，因此撤销仅凭现成组件多/接入成本低而冻结 Milkdown 的结论。隔离对比见[选型实验](../logs/2026-09-28-bibo-markdown-editor/artifacts/2026-09-28-editor-benchmark.md)：长文、CPU 4x 下 Tiptap 事务 p95 4.4ms、转换 p95 20ms，Milkdown core 分别 17.3ms/152.1ms。基础挂载 Milkdown 更快，未声称全指标领先；选择依据为日常输入与转换优势。移除 Milkdown 试验实现和依赖。

首要比较：输入响应、中文输入、跨段操作/历史、长文性能、冷启动、手机响应、内容保真。开发维护成本只能在体验相当时决定。两者共用 ProseMirror 不证明性能相同；Crepe 的 Vue 节点视图、全量序列化和资源体积需要实测；Tiptap 官方 Markdown 扩展标记 Beta 是风险，不是自动淘汰理由。使用相同文档、功能集合与浏览器环境，分别记录基础内核与完整集成的开销，禁止拿裸 Tiptap 对完整 Crepe 的数字直接宣布胜负。

公开 MarkdownEditor 仍为唯一宿主入口；富文本内核的创建、外部同步、事务与销毁由编辑 manager 统一管理，React 负责挂载和展示，不建第二份业务文档 store。读取 value 不写回；只有实际用户事务才更新父级。读写互切不销毁实例。外部冲突恢复与源码更新通过显式替换进入编辑内核，不伪装成用户输入。两种内核分别按需加载；键入时由内核更新，停顿 250ms 后同步 Markdown；失焦、指针操作、保存快捷键、卸载和离开页面时立即同步。快捷键保存读取 store 最新状态，防止 React 闭包落后。Mermaid 预览独立 React root 延迟卸载，避免嵌套提交冲突。

保存仍是 Markdown。先验证 commonmark/GFM/math 对应；针对不被内核表示的 frontmatter、HTML、脚注等，保留原文节点并注册相应 parser/serializer，不允许忽略。图片支持 HTTPS 地址插入和点击改址，当前 Bibo 文件服务没有二进制上传合同，不凭空引入另一套存储；不持久化 blob URL。代码图表复用既有安全 renderer；不引入远程内容执行。

样式归共享 UI，宿主不补内核 DOM CSS。统一正文宽度、字体与间距；编辑工具栏占用受控，手机和窄工作区仍能操作。中文文案由宿主 labels 注入。编辑器按需加载，不让默认阅读承担完整初始化成本。

## 验证与 Review

按合同黄金链路，在真实页面做输入/跨段选择/删除/undo/redo、表格增删行列、列表缩进退出、链接图片、代码/公式图表、混合原文保留与 source 往返；覆盖 IME、快速切换、保存中继续输入、错误和冲突、长文与 1440/390/320 容器、主题。原旧 smoke 的 DOM 断言需换成用户行为与持久内容断言，不能用脚本填值替代直接编辑验收。

方案 Review：用户补充体验优先级后重做对比与保真实验，Tiptap 选型及输入同步主链路 design-review: passed。最大风险是转换丢内容、异步创建后过期写回和嵌套代码历史，列为必验而非豁免。保留现有状态 owner，无通用框架/无关 CLI 扩张。plan: not-required，单批交付，current-state 用于跨上下文恢复。
