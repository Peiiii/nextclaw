# 项目产物浏览与文件预览设计

## 背景

项目的 `artifacts` 由 `.nextclaw/project.yaml` 中的分类和 glob 规则观察得到。当前页面把所有产物平铺成相同卡片；真实 NextClaw 项目一次可观察到近两千条文件，分类已经存在，却没有成为用户可见的导航结构。页面同时在概览、工作约定等位置暴露项目文件路径，但这些路径不能直接打开。

用户任务：用户从项目页进入产物或看到任意项目内文档引用时，能按项目自己的分类快速定位文件，并在不离开当前项目页的情况下打开右侧预览。

## 现状与约束

- 观察快照中的 `ObservedArtifact` 已有 `categoryId`、`categoryLabel`、`path`、可访问状态和文件引用。
- 分类来自用户项目配置，适用于开发、研究、写作等广义项目；不能写死“设计/计划/日志”等开发目录。
- Skills 已复用会话工作台的右侧文件预览；项目内文档应复用同一条 `openFilePreview` 链路，而不是新增抽屉、modal 或第二个预览器。
- 项目当前是只读观察能力；本次不新增文件管理、标签编辑或数据库。

## 候选方案

| 方案 | 体验 | 优点 | 问题 |
| --- | --- | --- | --- |
| A. 单一平铺列表，加搜索/排序 | 像文件搜索结果 | 实现最少 | 失去项目语义；数百条后无法浏览；正是当前缺口的变体 |
| B. 按配置分类的可折叠分组列表 | 先看到“设计文档 128”“迭代记录 64”等，再展开文件 | 分类来自项目本身，适用于任何领域；层级浅；与 Linear 的属性分组、可折叠组头和计数一致 | 交叉匹配规则需规定唯一归属 |
| C. 目录树为默认入口 | 像 IDE 文件浏览器 | 精确反映磁盘位置 | 用户必须先懂目录；对研究、小说等项目并不表达“这是什么产物”；与项目配置分类重复 |
| D. 可自定义多视图（分类、目录、时间、标签） | 类似 Notion/Linear | 长期最灵活 | 需要保存视图、筛选/排序合同和状态管理；当前只读观察阶段成本过高 |

## 决定

采用 **B：按配置分类的可折叠分组列表**。

默认按 `project.yaml` 的 `observation.artifacts` 声明顺序显示分组；每个组头显示标签、数量和展开/收起状态。组内默认按**最近更新时间优先**，并以人性化相对时间（如“刚刚”“3 小时前”“昨天”）显示更新时间；悬停显示完整时间。正常可读文件不展示“文件已观测”之类的内部采集状态；点击可读文件行，打开现有会话工作台右侧的 Markdown/文件预览；右侧已打开另一个文件时按该工作台已有的替换/标签行为处理。

项目页中所有可访问的项目内文档引用都遵循同一规则：

- 产物页的文件行；
- 概览中展示的产物；
- 工作约定中的 `project.context` 来源；
- 后续任何携带 `ProjectObservationReference.projectRelativePath` 且可读的项目文件。

不可访问、仅会话引用或非文件来源保持普通文本/会话链接，不提供失效的点击入口。

### 唯一分组规则

同一文件命中多个 artifact glob 时，按配置声明顺序归入第一个分类；不在多个组重复出现。配置顺序因此是轻量且可解释的优先级，而非新增元数据。这条规则应在观察层收敛，UI 只消费唯一归属的产物集合。

### 大数据默认态

分组先承担浏览，不新增“保存视图”机制。每个组默认展示首批紧凑行和“显示更多”，避免近两千个 DOM 节点同时渲染；搜索作为同页定位能力时，在匹配项所属分组内展示结果并保留组名。折叠状态仅是当前页面交互状态，不写入项目配置或 kernel。

### 时间与排序

文件观察记录创建时间和更新时间。完整产物页提供单个轻量排序控件：最近更新（默认）、最早更新、最近创建和文件名；排序只改变每个分类组内的文件顺序，不改变项目配置赋予的分类顺序。创建时间在旧运行实例尚未提供时不显示该选项，避免把更新时间伪装成创建时间。

概览页不继承用户的临时排序选择，而是固定取最近更新的少量产物，同时将最近活动按发生时间倒序展示。概览的职责是回答“项目最近发生了什么”，不是承担完整文件浏览。

## 交互功能地图

| 场景 | 可见结果与动作 | Owner |
| --- | --- | --- |
| 首次进入产物页 | 依项目配置顺序看到分类、数量与首批文件 | `ProjectArtifacts` presenter/view |
| 展开或收起分类 | 只改变当前页面可见行，不改变观察数据 | 前端局部视图状态 |
| 点击可读文件 | 打开现有右侧工作台文件预览 | `chatThreadManager.openFilePreview` |
| 搜索 | 在分类语义下定位匹配路径；无结果给出本页空态 | 前端局部视图状态 |
| 排序 | 默认最近更新；可临时切换最早更新、最近创建或文件名；分类顺序不变 | 前端局部视图状态 |
| 文件不存在/不可读 | 保留路径和明确异常说明，不可点击；正常文件不显示采集状态 | 观察快照的 `exists`/reference |
| 刷新/重新进入 | 重取观察快照；默认分组不依赖缓存写入 | 项目观察接口 |

## 参考与取舍

Linear 将分组、计数与可折叠组头作为列表浏览的基本能力，而不是把所有对象平铺；它也把分组作为视图选项逐步扩展。Notion 证明同一集合可有多种呈现，但多视图依赖属性和持久视图管理。Asana 的 section 说明分组应服务项目自己的类别或流程。

因此本次取 Linear/Asana 的“显式分组 + 计数 + 折叠”作为最小闭环，不提前引入 Notion 式用户自定义数据库视图。目录树可在用户明确需要文件系统导航时作为后续独立视图，而不是替代分类浏览。

## 非目标

- 不创建、移动、重命名或编辑项目文件。
- 不把 artifact 分类升级为全局标签系统。
- 不新增独立文件预览架构。
- 不在本批保存个性化视图、复杂筛选组合或多维分组。

## 验收标准

1. 任意配置分类在产物页形成一个带数量的可折叠组，顺序与配置一致。
2. 同一文件只出现一次，重叠规则按首个配置分类归属。
3. 产物与项目上下文中的可读文件均可点击，并在右侧复用现有文件预览。
4. 不可读/不存在文件不触发预览。
5. 大量产物初始渲染不一次性创建全部文件行；搜索与展开后仍保留分类语义。
6. 每组默认把最近更新的文件放在前面；概览中的产物和活动始终按最新事件优先，并显示人性化时间。

## 后续升级条件

只有用户明确需要按目录、时间或自定义属性反复切换，并且分类浏览无法满足定位任务时，才升级为可保存的多视图设计。
