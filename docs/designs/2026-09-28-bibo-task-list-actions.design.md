# Bibo 任务列表滚动与删除入口

## 问题与依据

正式工作台 `/tasks` 的外层工作区禁止滚动，任务列表所在容器没有占据剩余高度，任务超出视口时底部内容被裁切。删除任务目前只能先打开详情。Todoist 桌面版在任务行右侧的更多菜单提供删除，Microsoft To Do 则从详情页删除；两种方式都有成熟产品先例。本页已有行内完成按钮与共享操作菜单，采用列表中的更多菜单可以减少删除的操作层级，并保留详情入口。

## 交互与 owner

任务列表占据快捷添加和筛选栏以下的剩余高度，由列表本身纵向滚动；页头和筛选栏保持可见。行内更多按钮与完成按钮、打开详情的行按钮并列，避免嵌套交互元素；菜单显示「删除任务」。行级更多入口遵循共享交互合同：桌面悬停整行或键盘焦点进入整行时出现，触控设备保持可见，隐藏时不占独立操作列且不接收鼠标事件。任务行复用主干已有的 `RowActionTray`，与会话、文件树、文件搜索及笔记行遵循同一显隐合同；全局菜单保持常显。确认弹窗说明任务及子任务会删除且当前不可撤销。删除仍通过现有 `task.delete` 行为和版本字段提交，失败保留弹窗与错误，成功后由任务 store 更新列表。详情里的删除路径继续使用相同的行为。

## 验收

在桌面和窄屏任务页，任务数超出视口后可滚动到最后一项，页头与筛选仍可操作；滚动到上下边界不吞掉页面外层滚动。鼠标、键盘和触控都能从列表行的更多菜单进入删除确认，取消不改变任务，确认后仅目标任务从列表消失；点击更多不会打开详情，完成按钮仍独立可用。删除失败时错误留在确认弹窗，可重试。列表和看板复用同一行操作。
