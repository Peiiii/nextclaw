# 官网首屏产品实证设计

## 目标

首次访问 NextClaw 官网的用户，无需滚动或理解技术配置，就能同时看见：产品定位、具体工作方式、下一步行动和真实产品界面。

近期样本、原始截图与筛选过程见 [NextClaw 官网首屏近期参考调研](../thoughts/2026-08-26-landing-hero-reference-research.thought.md)。本设计不再引用模型记忆中的宽泛“顶级产品”，只接受调研中有日期与现场截图的证据。

## 冻结基线

- 主验收视口：`1512 × 827` CSS 像素，对应用户提供的 `3024 × 1654` Retina 截图。
- 桌面冻结为左右结构：左侧定位与行动，右侧真实产品界面。相同截图与视口的 A/B 已证明 VoiceOS 式纵向结构会把工作台压到折线下，不再保留该结构候选。
- 中文主标题固定为视觉两行；移动端自然收敛为两行。
- 产品图使用整体浅色、信息密度均衡的工作台截图，不使用大面积空白或黑白割裂的子应用截图。
- Hero 不设置固定像素高度；首页主区域使用动态视口最小高度 `100svh`，保证首屏独占第一个视口，内容超过可用高度时仍可自然增长。
- 下一节从首屏折线以下开始，不在首屏截图中露出“一页半”；背景效果不得在 section 边界硬裁断。

## 内容层级

1. 主标题：`NextClaw，你的长期个人智能搭档`
2. 能力说明：说明 NextClaw 会使用设备上的文件和工具完成工作，结果仍由用户检查和继续完善。
3. 主要行动：下载桌面版。
4. 次要行动：查看任务案例。
5. 补充入口：平台支持信息和全部安装方式文字链接，统一进入“下载与安装”页。

不在首屏解释 API Key、模型配置或其它实现细节；这些内容属于安装和文档页面。

顶部导航保留“加入社群”一级入口，统一指向首页微信社群区。官网社群入口只提供微信群，不并列 Discord 或其它社群渠道；Discord 作为产品可接入的消息渠道仍可出现在能力说明中。

## 下载与安装信息架构

- 用户任务只有一个：把 NextClaw 安装到目标设备并开始使用。官网只保留一个一级入口“下载与安装”。
- `/zh/download/` 和 `/en/download/` 是唯一事实源：先提供适合大多数用户的桌面版，再提供 npm 和 Docker 选项。
- 三种安装方式使用内容区顶部的全宽分段导航；导航在滚动时固定于官网顶栏下方，并随当前内容更新高亮。禁止使用会被内容一起滚走的小型孤立左栏。
- “首次打开说明”是桌面版的从属信息，以折叠区收在桌面版面板内，不与三种安装方式并列。
- 首页、导航和集成页的安装入口统一指向合并页；不再让用户在“下载”和“安装方式”之间往返。
- 旧 `/install/` 地址仅作兼容跳转，设置 `noindex` 并将 canonical 指向合并页，不再承载第二套内容。

## 产品截图

- 中文页使用浅色工作台截图，直接展示会话、数据结果和项目资料并置的工作形态。
- 英文页不得使用主体内容为中文的截图；使用英文项目工作区截图。
- 图片是产品证据，不伪装成无提示的整图链接。
- 图片使用可理解的本地化替代文本。
- 首页后续的普通产品实证使用无框编辑式排版：桌面端按“左文右图 → 左图右文”交替，移动端统一回到上文下图。禁止把标题和截图共同包进有边框的大卡片。
- 产品截图的媒体父层不留“相框”内边距，图片本身不重复加边框和内层圆角；只允许在最外层裁切必要的圆角并使用轻量投影。
- 旧版小猫开宝箱氛围图 `apps/landing/public/nextclaw-hero-atmosphere.webp` 暂不用于当前 Hero，但作为候选品牌资产继续保留；首屏替换、截图整理或未引用资源清理不得顺带删除。

## 近期产品基准提炼

结构 owner 是经 A/B 验证后的 NextClaw 左右基线。VoiceOS 只约束行动层级，Siri AI 只约束首屏视觉层级和折线边界，Krea 只约束截图与页面背景的融合质感，Gemini、Qwen 与 Oboe 只约束内容减法。保留 NextClaw 必须首屏展示真实工作界面的要求，不机械复刻任何竞品的品牌皮肤。

## 验收标准

- `1512 × 827`：标题、说明、两个行动和完整产品主体同时可见；Hero 独占首个视口，下一节从折线以下开始。
- `1100 × 900`：左右结构成立，标题两行，无横向溢出。
- `390 × 844`：标题两行、按钮易点击、产品图完整出现，无横向溢出。
- 中英文页面的截图主体语言与页面语言一致。
- CTA 分别进入“下载与安装”合并页、任务案例页，以及合并页内的安装方式定位。
- TypeScript、生产构建和定向 lint 通过；现存 warning 需明确区分于本次新增问题。

## 迭代止损规则

每个候选方案必须先在主验收视口与当前基线并排比较。没有同时改善产品可见度、信息层级和整页节奏的方案不进入实现；结构候选最多两轮，之后回到基线重新判断，不做无目标像素微调。
