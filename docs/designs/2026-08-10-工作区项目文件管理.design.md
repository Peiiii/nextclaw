# 完整会话工作台与共享 Workspace Explorer 设计

## 文档状态

- 状态：已确认方案，作为本轮实现与验收的唯一功能清单
- 讨论原型：[完整会话工作台 + 共享 Workspace Explorer 原型](./2026-08-11-shared-workspace-explorer.prototype.html)
- 适用范围：NextClaw 会话工作台、项目文件 Explorer、文件预览、项目文件写操作
- 核心结论：保留现有完整工作台语义；“项目文件”是管理首页；所有文件预览复用同一棵可收起 Explorer

原型负责表达信息架构和交互手感；本文负责冻结功能范围、状态归属、失败边界、代码落点和验收标准。实现是否完成以本文的功能矩阵为准，而不是以页面是否“看起来像”原型为准。

## 一、用户场景与目标

### 1. 工作台连续浏览

用户从聊天头部打开会话工作台，先看到概览，再进入项目文件。打开文件后形成动态 Tab，但目录上下文不消失；用户可以连续打开、切换和关闭多个文件，而不是在“目录页”和“预览页”之间来回跳转。

### 2. 成熟的项目文件管理

用户应能按 VS Code Explorer 的已有心智完成新建文件、新建文件夹、刷新、折叠、重命名、删除、复制路径和在系统文件管理器中显示。没有 NextClaw 产品理由的地方不重新发明交互。

### 3. AI 协作与交付物

用户可以把文件或文件夹加入聊天上下文，把本地文件上传到项目目录，并直接下载 AI 在工作区生成的文件。这些是 VS Code 不具备、但 NextClaw 必须增加的能力。

### 4. 安全且可解释的写操作

所有写操作必须被限制在项目根目录内；默认不覆盖同名目标；危险删除必须确认；失败时保留可重试的输入和工作台上下文。

## 二、设计原则

1. **现有工作台语义优先**：新增 Explorer 不能把会话工作台降级成单一文件编辑器。
2. **一个文件系统 owner**：宿主文件系统是事实 owner；React Query 是可丢弃投影，不建立第二份文件树数据源。
3. **一个 Explorer 实例**：同一工作台只挂载一棵项目树，在项目文件首页、文件预览侧栏和窄屏抽屉之间改变布局，不复制状态。
4. **VS Code 为默认基线**：新建目标解析、树内命名、空白区右键、选择语义、键盘语义和菜单分组直接对齐。
5. **NextClaw 只做必要增强**：添加到聊天、上传、下载、AI 交付物和窄工作台抽屉是明确增强。
6. **入口和结果在同一空间**：新建发生在目标目录内；成功结果成为选中项并滚动可见。
7. **危险动作显式**：没有废纸篓或 Undo 之前，删除使用永久删除文案和强确认。

## 三、方案比较与最终选择

| 方案                                        | 工作台语义          | 文件连续性 | 目录状态       | 实现代价 | 结论                         |
| ------------------------------------------- | ------------------- | ---------- | -------------- | -------- | ---------------------------- |
| A. 项目文件页与文件预览完全切页             | 保留                | 差         | 返回时可能丢失 | 低       | 不选，体验割裂               |
| B. Explorer 在所有工作台页面常驻            | 破坏概览/子会话语义 | 好         | 连续           | 中       | 不选，无关页面被文件语境污染 |
| C. 项目文件管理首页 + 文件预览共享 Explorer | 保留                | 好         | 连续           | 中高     | **选定**                     |
| D. 每个文件 Tab 各自挂载 Explorer           | 表面保留            | 一般       | 多份状态会漂移 | 高       | 不选，违反单 owner           |

最终结构：

- 概览、子会话、定时任务、项目文件是固定页面。
- 子会话详情和文件预览是动态、可关闭的 Tab。
- 项目文件固定页显示完整宽度 Explorer。
- 文件预览激活时，同一 Explorer 变为左侧栏；窄宽度时变为覆盖式抽屉。
- 概览、子会话、子会话详情和定时任务不显示 Explorer 开关。

### 结构视觉锚点（实现不得自行改层级）

1. 文件预览中的“项目文件”展开/收起按钮必须位于现有面包屑同一行、同一高度，作为面包屑的 leading action；禁止为它新增独立工具栏行、竖向分割线或单独底色分区，图标与面包屑只用自然留白衔接。
2. 工作台最上方仍只有一条现有 Tab / 历史 / 刷新 / 最大化 / 关闭栏；Explorer 不再增加第二条工作台级导航。
3. Explorer 自己的标题与五个文件操作位于 Explorer 内部同一行；它们不进入文件预览面包屑。
4. 项目文件固定页和文件预览侧栏复用同一个 Explorer DOM 实例，只改变容器布局。
5. 实现完成后必须分别截取“概览、项目文件完整页、文件 + Explorer 并列、Explorer 收起、窄屏抽屉”五个锚点截图，与原型逐项对照；结构不一致不能以功能测试通过代替。

## 五、精确入口与菜单合同

### 1. Explorer 顶部工具栏

从左到右：

1. 新建文件：文件 + 加号图标，tooltip“新建文件”。
2. 新建文件夹：文件夹 + 加号图标，tooltip“新建文件夹”。
3. 刷新 Explorer。
4. 全部折叠。
5. 更多：打开根目录菜单。

图标必须能独立表达文件与文件夹，不使用一个无法判断语义的通用加号。窄侧栏仍保留图标和 tooltip，不改成文字按钮。

### 2. 根目录最外层空白右键菜单

分组顺序：

1. 新建文件；新建文件夹；上传文件。
2. 刷新 Explorer；全部折叠。
3. 在系统文件管理器中显示；复制路径。

空白右键的目标始终是项目根目录，不复用上一次文件夹 context。

### 3. 文件夹右键菜单

分组顺序：

1. 添加文件夹到聊天。
2. 新建文件；新建文件夹；上传文件到此处。
3. 在系统文件管理器中显示；复制路径；复制相对路径。
4. 重命名。
5. 删除。

### 4. 文件右键菜单

分组顺序：

1. 打开。
2. 添加文件到聊天；下载文件。
3. 在系统文件管理器中显示；复制路径；复制相对路径。
4. 重命名。
5. 删除。

“删除”永远在末组并使用危险色。“添加到聊天”和“下载”是 NextClaw 增强，但不改变 VS Code 核心项的含义。

## 六、关键交互状态机

### 1. 打开工作台

关闭 → 用户点击工作台入口 → 打开并激活概览。

若用户从消息中的文件链接直接打开文件，则允许工作台直接激活该文件 Tab；这属于显式文件意图，不改变普通工作台入口默认概览的规则。

### 2. 从项目文件打开文件

项目文件管理首页 → 单击文件：

1. 记录树选择。
2. 已有匹配 Tab 则激活；否则创建动态文件 Tab。
3. Explorer 从完整页模式变成侧栏模式。
4. 宽屏保持展开；窄宽度抽屉自动收起。
5. 目录展开、滚动和选择不变。

### 3. 新建文件或文件夹

idle → resolve target → expand parent → insert editable item → reveal → focus：

- Enter 且校验通过：pending → 服务端创建 → refresh parent → select/reveal real item → idle。
- Escape：移除临时项 → 恢复发起前选择 → idle。
- 服务端失败：保留编辑态与输入，显示行内错误，允许修正重试。

### 4. 重命名

selected → F2 或菜单 → inline editing：

- Enter：服务端原子 rename；成功后刷新父目录、保持选择，并同步已打开文件 Tab 的 path/title/key。
- Escape：恢复原名，不发送请求。
- 目标已存在：保留输入并显示冲突错误，不覆盖。

### 5. 删除

selected → 菜单删除 → 强确认：

- 取消：无状态变化。
- 确认：pending → 服务端边界校验 → 删除 → 刷新父目录。
- 若删除已打开文件：关闭对应动态文件 Tab；若是目录，关闭该目录内的文件 Tab。
- 当前无废纸篓或 Undo，因此确认文案明确“永久删除”。

### 6. 上传

select target → native file picker → preflight：

- 无冲突：写入全部文件 → 刷新目标目录 → 数量反馈。
- 有冲突：不写入任何文件 → 显示冲突数量 → 用户确认后整体 overwrite 重试。
- 用户取消选择器或覆盖确认：不改变目录。

## 七、状态归属

| 状态                           | Owner                                       | 生命周期                   |
| ------------------------------ | ------------------------------------------- | -------------------------- |
| 文件/目录事实                  | 宿主文件系统                                | 持久                       |
| 目录读取投影                   | React Query server-path-browse              | 可失效、可重建             |
| 工作台当前页面、动态 Tab、历史 | chat-thread manager/store                   | 现有持久化合同             |
| Explorer 展开状态              | 单一 Explorer 组件实例                      | 当前工作台与项目根生命周期 |
| Explorer 滚动位置              | 单一树滚动容器                              | 当前工作台与项目根生命周期 |
| Explorer 选择与创建目标        | useWorkspaceProjectFilesController          | 当前工作台与项目根生命周期 |
| Explorer 开关、抽屉模式        | ChatSessionWorkspacePanelContent 布局 owner | 当前工作台生命周期         |
| Explorer 侧栏宽度              | chat-thread store                           | 版本化持久，刷新后恢复     |
| 单个目录查询                   | 对应目录行的 useServerPathBrowse            | 展开时启用                 |
| mutation pending/error         | useWorkspaceProjectFilesController          | 单次操作                   |

禁止：

- 为每个文件 Tab 建立一份 Explorer state。
- 把稳定项目根、selection owner 拆成多层同名 proxy。
- 用前端路径字符串判断替代服务端真实路径边界校验。

## 八、服务端与客户端合同

### 1. 新建文件

新增 POST /api/server-paths/file。

请求字段：basePath、parentPath、name。

语义：

- 创建空文件，使用 exclusive create，默认绝不覆盖。
- name 必须是单一文件名，不得为点目录或包含路径分隔符。
- 返回 name、path、kind=file。

### 2. 新建文件夹

沿用 POST /api/server-paths/directory，并要求项目文件入口始终传 basePath。

### 3. 重命名

新增 PATCH /api/server-paths/entry。

请求字段：basePath、path、name。

语义：

- 只允许在原父目录内修改名称。
- 默认不覆盖同名目标。
- 项目根不可重命名。
- 返回旧路径、新路径和 kind，供 UI 同步动态 Tab。

### 4. 上传

沿用 POST /api/server-paths/files multipart：

- basePath
- targetPath
- overwrite
- files（多个）

### 5. 删除

沿用 DELETE /api/server-paths/entry?basePath=...&path=...。

### 6. 通用安全不变量

1. 服务端对 basePath、parentPath、targetPath、path 重新解析和 realpath 校验。
2. 所有目标必须位于项目根内；项目根自身禁止删除或重命名。
3. symlink 不得用于逃逸项目根。
4. 新建、重命名、上传默认不覆盖。
5. 批量上传写入前完成完整预检，避免部分成功。
6. 错误返回稳定 code 和可选 details，UI 不解析英文 message 判断分支。

建议稳定错误码：

- SERVER_PATH_OUTSIDE_BASE
- SERVER_PATH_ROOT_PROTECTED
- SERVER_PATH_NAME_INVALID
- SERVER_PATH_ENTRY_EXISTS
- SERVER_PATH_ENTRY_NOT_FOUND
- SERVER_PATH_FILE_EXISTS
- SERVER_PATH_PARENT_INVALID

## 十、响应式与尺寸合同

| 内容区宽度     | Explorer 模式 | 行为                                               |
| -------------- | ------------- | -------------------------------------------------- |
| 560px 及以上   | 并列侧栏      | 默认 224px，192–400px 可调并持久化；预览占剩余空间 |
| 559px 及以下   | 覆盖式抽屉    | 宽度 min(320px, 86%)；带遮罩；选中文件后关闭       |
| 项目文件固定页 | 完整页        | 不受侧栏宽度影响，占满内容区                       |

切换宽窄模式只改变呈现，不卸载 Explorer，不清理树状态。

紧凑密度参考 Cursor / VS Code，但不照搬主题：树行高约 26px，层级缩进 12px，展开符、文件图标和文字间距 4px。文字保持 13px，长名称截断并保留 title；行操作只在悬停、焦点或菜单开启时显示。

## 十一、无障碍与键盘合同

1. 树容器使用 role=tree；节点使用 treeitem/group 和 aria-expanded。
2. 工具栏图标必须有 aria-label 和 tooltip。
3. 新建文件与新建文件夹的 accessible name 必须不同。
4. Context menu 支持方向键、Enter、Escape 和焦点恢复。
5. F2 对选中对象触发重命名；Escape 取消命名或关闭抽屉/菜单。
6. pending 时禁用会产生冲突的 mutation，不禁用浏览和复制路径。
7. 危险项使用颜色之外的明确“永久删除”文案。

## 十二、明确非目标

以下能力不在本轮，不得在 UI 或交付说明中伪装完成：

- 多选。
- 拖拽移动。
- 剪切、复制、粘贴文件对象。
- 废纸篓、Undo、版本历史。
- 文件系统实时监听。
- 上传整个本地目录。
- 压缩、解压或批量下载目录。
- 跨目录移动或在重命名输入中改变父路径。
- 应用重启后恢复 Explorer 展开和滚动状态。

## 十三、验收矩阵

### 1. 工作台与共享状态

- 普通入口打开工作台后激活概览。
- 四个固定 Tab 始终存在，动态文件/子会话 Tab 可关闭。
- 项目文件页显示完整 Explorer。
- 打开文件后同一 Explorer 变为侧栏，树 DOM 实例不重建。
- 切换两个文件 Tab 后展开、滚动、选择和开关状态保持。
- 切到概览/子会话/定时任务时 Explorer 隐藏且无开关。
- 窄宽度为覆盖抽屉，选中文件后关闭；返回文件后可再次展开。
- 工作台后退/前进、最大化、关闭、文件刷新保持现有行为。

### 2. Explorer Core

- 工具栏同时存在可区分的新建文件与新建文件夹图标。
- 工具栏目标解析覆盖：选中目录、选中文件、无选择。
- 根空白、文件夹、文件三类右键菜单逐项匹配本文合同。
- 新建文件/文件夹自动展开、滚动、聚焦；Enter/Escape 和校验正确。
- 创建成功后选中并再次定位。
- 刷新不清理展开状态；全部折叠关闭所有目录。
- 重命名成功同步树和已打开 Tab；冲突不覆盖。
- 删除确认、根保护、已打开 Tab 清理正确。
- 复制路径、复制相对路径、Reveal 在支持宿主上正确。

### 3. NextClaw 增强

- 文件和文件夹添加到聊天生成正确结构化引用。
- 根目录与子目录多文件上传成功；冲突确认前零写入。
