# 最小核心（阿米巴模型）设计

> 日期：2026-09-06
> 提出者：用户（2026-09-05 补充到长期计划）
> 状态：设计完成，实现待后续 PR

## 核心原则

借鉴阿米巴模型：即使所有高级功能全部崩溃，最小核心依然能跑通基础功能，并在此基础上实现自我修复。

## 最小核心边界

**核心层（必须始终可用）：**
- 纯文本对话（LLM 调用 + 基础 prompt）
- 基础工具调用（文件读写、命令执行）
- 会话管理（会话创建、历史、上下文）
- 配置读取（API key、模型选择）

**可降级层（故障时可关闭）：**
- 渠道扩展（dingtalk/discord/email 等）
- 插件/技能系统
- 复杂 agent 功能（subagent、memory、cron）
- UI 渲染增强（桌面端、web UI）

## 降级策略

1. **启动时**：检测核心依赖（LLM provider、文件系统），跳过不可用的高级功能
2. **运行时**：每个高级功能注册健康检查，失败时自动禁用并记录
3. **恢复**：定期重试禁用的功能，成功后自动重新启用

## 自愈机制

1. **健康检查**：核心服务定期心跳（每 30s）
2. **故障检测**：连续 3 次心跳失败 → 判定为故障
3. **自动重启**：故障服务自动重启（最多 3 次/小时）
4. **降级兜底**：重启失败 → 降级到最小核心模式

## 实现路径

- PR-1：核心健康检查契约（core feature：health-check）
- PR-2：降级开关配置（config schema 扩展）
- PR-3：自愈重启逻辑（service restart + 状态恢复）
