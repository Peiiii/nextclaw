# 聊天公式的流式展示

## 问题与范围

数学公式生成到 `\frac{` 等片段时，现有 remark-math 会把未闭合的独立公式交给 KaTeX，产生临时红色错误。此前只验证静态和简单行内补全，遗漏了这个局部展示合同。风险为 L2；不改变传输、持久化或消息状态 owner。

## 决定

保留现有 `ChatMessage -> ChatMessageMarkdown` 的 `isStreaming` 主链路。在 Markdown AST 上识别未闭合的独立公式，生成中以中性省略号占位，闭合后才交给 KaTeX。生成期间其它公式解析错误也显示中性占位；生成结束后恢复 KaTeX 的错误显示。行内公式继续遵循原有语法，未闭合时是普通文本，闭合后排版。普通代码、转义美元与技能引用保持各自解析规则。

不采用逐帧补括号或猜测 LaTeX 命令，也不缓存上一份公式作为当前内容；这两种方式会呈现模型尚未输出的结果。取舍是独立公式完整闭合前暂不预览内部内容。

## 生命周期与边界

- 占位只属于视图，不改消息原文和复制数据。
- 中止或完成使 `isStreaming=false`，不得永久保留占位。
- 已完成的正文与公式保持相同父级、组件类型和 key；不操作焦点和选区。
- 代码围栏中的 math 同样覆盖未完成片段，普通代码不变。
- 纯渲染能力，无新增 CLI。

## 验证与交付

用分片回放覆盖 `$$`、`\frac{`、分子/分母完成、矩阵完成、闭合围栏、结束仍无效，并断言中途无红色错误、结束后状态正确、历史文本与公式 DOM 身份不变。组件回放只作为开发证据，不能替代真实用户链路验收。
