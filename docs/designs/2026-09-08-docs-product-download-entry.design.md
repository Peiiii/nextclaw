# 文档站官网与下载入口设计

## 问题

用户可能从搜索结果直接进入任意文档页。当前文档站全局导航只在站内流转，Logo 也只返回文档首页；虽然安装说明页最终能跳到官网下载页，但深层落地页没有始终可见的官网与下载出口，了解产品和开始使用的路径都不够直接。

## 用户任务

从搜索或外部链接进入任意中英文文档页的用户，可以在全局页头直接返回对应语言的官网，或前往对应语言的下载页，并从链接目标确认自己已经离开文档站、进入产品介绍或安装流程。

## 现状与 owner

- `apps/docs/.vitepress/navigation/docs-navigation.config.ts` 是中英文全局导航的事实源。
- `apps/docs/.vitepress/config.ts` 负责把两套导航交给 VitePress，并保留 GitHub、搜索和语言切换等全局能力。
- `https://nextclaw.io/{locale}/` 是产品官网，`https://nextclaw.io/{locale}/download/` 是 Desktop、npm 与 Docker 的统一下载和安装入口。
- 站内 `/{locale}/guide/install` 继续负责解释安装方式和使用条件，不替代官网的实际下载入口。

## 设计

在中英文全局导航末端新增两个直接外链：

1. `官网 / Website`：进入相同语言的产品官网，承接产品认知与继续探索；宽屏直接展示，中等桌面宽度收进“更多”菜单。
2. `下载 / Download`：进入相同语言的官网下载页，作为高意图开始使用入口，保持一级可见并使用 VitePress 的品牌按钮样式突出显示。

两条链接都使用 VitePress 原生导航项，不新增自定义组件、状态或 JavaScript。宽屏直接展示“官网”“开发者”“关于 NextClaw”和“下载”；仅在中等桌面宽度空间不足时，把前三项收进原生“更多”菜单，下载入口始终保持一级可见。移动端继续沿用 VitePress 现有导航菜单，并隐藏重复的“更多”分组。文档首页首屏同时把主操作改为下载安装，次操作保留创建首个任务，让首次访问者先获得产品再进入任务教程。

## 取舍

- 不只增加“官网”：官网解决产品认知，但不能稳定缩短下载路径。
- 不只增加“下载”：文档站与产品站仍需清楚的双向关系，用户也可能只是想了解产品而非立即安装。
- 不把 Logo 改为官网链接：文档站 Logo 返回文档首页符合站内导航预期，改变它会破坏熟悉的返回路径。
- 不复制平台检测或安装包链接：下载页已经是这些变化信息的 owner，文档导航只指向该事实源。
- 不在所有桌面宽度统一折叠：宽屏有足够空间时直接展示完整信息架构；中等宽度通过原生分组保留全部入口。

## 验收

- 中英文任意文档路由的全局导航都包含对应语言的官网与下载链接。
- 1200px 及以上宽屏直接展示官网、开发者、关于和下载，不出现“更多”。
- 1024px 桌面宽度下下载入口仍直接可见，官网和低频项目可从“更多”进入。
- 下载入口在桌面导航中具有 CTA 视觉层级，在移动端仍可通过原生菜单访问。
- 中英文文档首页首个操作直达对应语言的官网下载页，仍保留创建首个任务的站内入口。
- 文档构建、导航类型检查和中英文结构检查通过；生成页面中的链接与文案正确。

## 非目标

- 不修改官网的下载逻辑、平台检测、发布版本或安装包地址。
- 不重做文档站整体导航、首页内容结构或视觉主题。
- 不新增账号、在线使用或云端工作台入口；当前没有已确认的统一 Web 使用入口可作为事实源。
