# BB 登录注册入口设计

日期：2026-09-28。来源：用户要求让首次进入的登录注册弹窗更精致、有趣、有品牌特点，呈现既有 Bibo 角色，并特别指出手机端更别扭。参考现网 `https://app.bibo.bot/` 的未登录画面与既有概览角色设计 `2026-09-27-bibo-overview-brand.design.md`。

## 现状与目标

现网桌面和 390px 手机共用 430px 宽的单列表单卡片，左上仅有一个星号，遮罩后仍能看到模糊工作台；手机卡片上下各留大段灰色空间。注册表单依次为邮箱、验证码、密码，成功发送验证码的文字与错误共用红色 `authError`。角色已有应用内 SVG，仅在登录后的概览使用。

首次访问者打开应用，应先认出 Bibo 及其「个人搭档」定位，在同一画面里找到注册或登录方式，完成原有邮箱流程后进入原工作台。出错时输入与模式保留，提示靠近操作；已登录者不再看到入口。品牌展示不虚构 Agent 已执行的事，也不把角色变成跳转按钮。

## 方案选择

1. **采用：同一入口按设备重排。** 桌面为左侧角色与一句品牌叙事、右侧完整表单的单层面板；手机成为覆盖整屏的独立欢迎界面，角色与文案压成上方紧凑首屏，表单自然接续。两端共享一个 AuthPanel、同一状态和提交行为。角色 SVG 从概览移到应用级展示组件，两个入口复用。
2. 保持原居中小弹窗、增加一张插画：改动小，但手机仍是被遮罩包围的长卡，品牌画面与表单争夺纵向空间。
3. 新增多步引导页：可做出戏剧感，却延长第一次使用，增加验证和恢复状态，现有账号流程没有必要拆步。

选方案 1。视觉识别靠官网已有紫色角色、暖白和低饱和绿色的反差，以及有节奏的留白和文字；不添加循环动画、假聊天气泡或无关装饰。表单仍以清晰、可达为先。桌面可有静态形状和角色压边，手机不照搬桌面插画的大尺寸。

## 入口与行为

- 未登录访问 `/` 或任意受保护路径时，背景工作台不可键盘操作，入口作为模态区域呈现。桌面焦点从标题进入注册／登录切换，再到表单；手机不自动弹系统键盘。登录成功继续原路径，账号 API、会话和数据路径不变。
- 默认注册。切换登录仅改变说明、验证码字段、密码 autocomplete 与主按钮；保留已输入邮箱。发送验证码期间按钮显示等待并禁用；成功用正常提示色说明发往的邮箱，失败用错误色和 `role=alert`。提交失败保留输入。
- 桌面 1440／768px 检查角色、品牌文案、表单同屏；手机 390／320px 检查首屏主 CTA、窄屏验证码行、滚动与键盘缩放、无横溢。登录和注册、提示成功与错误、禁用与键盘焦点均验收。动态效果遵守减少动态效果，角色本身无交互。

## Owner 与交付

品牌文案和响应式布局属于 `apps/bibo-hosted`；表单请求及模式继续由现有 chat store 与 client 拥有，不新增鉴权 API 或另一套状态。Bibo SVG 是应用内品牌资产，放在 app 的 `shared/components`，只被概览和认证入口消费；不放入通用 UI package，也不耦合通用控件。设计/实现一次闭环，交付本地可预览界面和桌面／手机实测截图；审美偏好由用户在可见版本上判断。此次不改变账号数据合同，不需迁移、NPM 或 Desktop 发布。`design-document: required`，`plan: not-required`。

## 设计 Review

方案沿用单一 AuthPanel 与现有 auth owner，视觉按断点重排而不是复制两个表单。共享角色恰有两个真实消费者；不引入品牌框架或新增步骤。未登录态的焦点隔离、操作反馈和移动键盘列为验收，设计可进入实现。

## 本地验收记录

未登录实际渲染已检查 1440×900、768×800、390×844、320×700、320×568，以及 900×500 矮桌面视口；经典和简约两主题的桌面／手机画面均可读，无页面横向溢出。320×568 注册表单高度 568px、内容 806px，卡片可独立滚动到提交按钮；模拟视口缩至 320×380 时聚焦密码框会将其滚入可见区域。桌面 500px 高时品牌文案完整保留，表单独立滚动。验证码成功使用正常提示色，失败使用错误色并保留邮箱；切到登录清理旧反馈。真实系统软键盘仍需在设备上主观确认。

BB 三份 tsc、Vite 构建、routing 登录回归、product 回归、定向 ESLint、diff-only maintainability 和新增代码治理通过。登录成功后背景恢复可操作；注册期间背景处于 inert。视觉设计仍可由用户在实际页面上判断品牌气质。

## 回访纠偏：手机首屏与并行部署

用户从真实手机反馈仍看到旧入口。复查发现 09:21 的客户端版本 `3e4d438e-f20c-4c08-a751-a99618302cb6` 曾在生产生效，但 09:25 的并行 BB 故障修复部署 `afff6f75-bfe3-4f2e-a2f8-7270b2eb6a3f` 将入口静态资源退回 `index-C9zmtr0Y.js`；不是手机缓存。故障修复随后合入远程主干 `ab654b705d4e05ecdb56afbdc151d2faf323469b`。从该主干执行客户端恢复部署，Worker 版本 `e6d0d22f-ae0c-4751-b8d4-ec551137b14a`；`app.bibo.bot`、带参数首页、workers.dev 与 `bibo.bot/app/` 跳转均重新返回 `index-DILd1CPX.js`，JS／CSS 与构建逐字节相同，诊断任务升级的容器 image `sha256:4ef68e222cc8ea7f8bdd9681aa1ca78890cda123eda9e8b522ff24b388fe364c`、version 23 保持不变。恢复后线上 iPhone 13／SE 视口与 1440／390 路由回放通过。

真实手机随后反馈新版仍须滚动才能看到注册操作，版面也显得堆叠。原因是手机把桌面完整品牌介绍和三项表单直接纵向排列，320×568 的主按钮位于首屏下方。改为手机分步：第一步只显示角色、单句定位、模式切换、邮箱与「继续」；注册继续时沿现有 API 自动请求验证码，第二步输入验证码与密码，可重新发送、返回修改邮箱；登录继续时只输入密码。桌面仍使用原双栏完整表单。短屏保留 44px 输入、46px 主按钮和可滚动的键盘状态，不用缩小普通字号换取装下所有字段；手机认证输入单独使用 16px，避免 iOS 聚焦 14px 输入时放大页面。手机的次要说明固定在底部，第二步收起；不新增账号 API 或状态 owner。

本地 Chromium iPhone 13 390×664 和 iPhone SE 320×568 初始页面无横向或纵向溢出，主按钮分别在 y=391／365，底部说明也在屏内。注册第二步的验证码、密码、成功提示、重新发送、修改邮箱和登录第二步在 390／320px 回放通过，主按钮无需滚动；模拟 320×380 键盘缩放时主按钮仍可经表单自身滚动到达。BB 三份 TypeScript 检查、Vite 构建、产品与路由回归、定向 ESLint、diff-only maintainability 及治理检查通过。真实手机软键盘与审美偏好仍须由用户在上线页面确认。

此次并行覆盖暴露出 BB 命令虽在文档要求“冻结远程主干”，脚本却不检查实际 checkout。`deploy` 与 `deploy:client` 增加构建前、上传前两次 preflight，拒绝脏工作区或 HEAD 不等于远程 `master`，防止落后 worktree 再覆盖较新静态资源；不改变容器 rollout 的范围选择。

## 手机比例再设计（2026-09-28）

用户提供的线上手机截图显示：184px 高的品牌区将角色下半身压进表单，白色表单仍占满屏高；安全提示靠 `margin-top:auto` 固定到底部，让主按钮与提示之间出现几百像素空白。先前验收只检查主按钮是否在首屏，没有检查图形是否完整、主要内容是否形成连续视觉组、空白是否合理。这是认证入口的局部视觉合同缺口，不改变邮箱两步流程或鉴权 owner。

比较三种布局：纯 ChatGPT 式居中表单最紧凑，但会丢掉用户明确要求的 Bibo 角色；沿用现有短横幅并补几处边距仍无法承载角色；采用随视口高度调整的品牌画面加单层表单，可以让角色完整、品牌文案与表单各有清晰比例。选择第三种，保留一份 AuthPanel 与现有状态、语义和操作。长手机把多余高度给品牌区，短手机压缩品牌区但保留完整角色；表单内容按自然高度排列，提示直接跟随主按钮。验证码／密码步骤把品牌区收为小标题带，保证输入和提交优先。横向窄屏时标题与角色不交叠，键盘缩小时允许认证页自身滚动。

黄金验收：未登录用户打开 `app.bibo.bot` → 首屏认出 Bibo 角色及用途、看到注册／登录选择、邮箱和继续按钮 → 输入邮箱进入对应第二步 → 完成注册或登录后继续原路径。AI 在 390×844、390×664、320×568 与 320×380 模拟键盘视口观察同一真实页面：首步角色全身可见、按钮和提示成组、主按钮在常见首屏可见；第二步验证码、密码、返回和重发可达；无横向溢出、遮挡或不可滚动的必要操作。桌面双栏、账号 API、错误恢复和主题配色不改。视觉偏好以用户看过线上版本后的反馈为准，不能靠 AI 自称达到某个主观等级。

设计 Review：仅调整认证入口的响应式布局；不新增组件、状态或图像资源。手机表单从全屏拉伸改为自然内容流，解决留白根因；角色与表单间留出明确边界，短屏用最小高度和内部滚动守住可达性。方案通过，可进入实现。`design-document: required`，`plan: not-required`。

本地两轮实拍复核：第一轮 320px 标题断成四行、安全提示末尾孤字，第二轮收短品牌主句及试用说明后均变为完整两行／单行；第二步角色原有手部仍被表单压住，随后上移至表单边界之上。最终 390×844 品牌区 450px、角色底部 y=391、表单起点 y=436、主按钮底部 y=659、提示底部 y=699；390×664 按钮／提示底部分别 y=533／573；320×568 分别 y=447／487，角色底部 y=198、表单起点 y=224。上述三视口首屏无横向／纵向溢出；320×380 键盘高度模拟可在认证页内滚动到主按钮。经典与简约主题、注册和登录第二步均实拍检查；真实 iOS 系统键盘与用户个人审美反馈尚未取得。
