# BB 登录注册入口设计

日期：2026-09-28。来源：用户要求让首次进入的登录注册弹窗更精致、有趣、有品牌特点，呈现既有 Bibo 角色，并特别指出手机端更别扭。参考现网 `https://app.bibo.bot/` 的未登录画面与既有概览角色设计 `2026-09-27-bibo-overview-brand.design.md`。

## 现状与目标

现网桌面和 390px 手机共用 430px 宽的单列表单卡片，左上仅有一个星号，遮罩后仍能看到模糊工作台；手机卡片上下各留大段灰色空间。注册表单依次为邮箱、验证码、密码，成功发送验证码的文字与错误共用红色 `authError`。角色已有应用内 SVG，仅在登录后的概览使用。

首次访问者打开应用，应先认出 Bibo 及其「个人搭档」定位，在同一画面里找到注册或登录方式，完成原有邮箱流程后进入原工作台。出错时输入与模式保留，提示靠近操作；已登录者不再看到入口。品牌展示不虚构 Agent 已执行的事，也不把角色变成跳转按钮。

## 方案选择

1. **采用：同一入口按设备重排。** 桌面为左侧角色与一句品牌叙事、右侧完整表单的单层面板；手机成为覆盖整屏的独立欢迎界面，角色与文案压成上方紧凑首屏，表单自然接续。两端共享一个 AuthPanel、同一状态和提交行为。角色 SVG 从概览移到应用级展示组件，两个入口复用。
2. 保持原居中小弹窗、增加一张插画：改动小，但手机仍是被遮罩包围的长卡，品牌画面与表单争夺纵向空间。
3. 新增多步引导页：可做出戏剧感，却延长第一次使用，增加验证和恢复状态，现有账号流程没有必要拆步。

选方案 1。视觉识别靠官网已有紫色角色、暖白和低饱和绿色的反差，以及有节奏的留白和文字；不添加循环动画、假聊天气泡或无关装饰。表单仍以清晰、可达为先。桌面可有静态形状和角色压边，手机不照搬桌面插画的大尺寸。

## 入口与行为

- 未登录访问 `/` 或任意受保护路径时，背景工作台不可键盘操作，入口作为模态区域呈现。桌面焦点从标题进入注册／登录切换，再到表单；手机不自动弹系统键盘。登录成功继续原路径，账号 API、会话和数据路径不变。
- 默认注册。切换登录仅改变说明、验证码字段、密码 autocomplete 与主按钮；保留已输入邮箱。发送验证码期间按钮显示等待并禁用；成功用正常提示色说明发往的邮箱，失败用错误色和 `role=alert`。提交失败保留输入。
- 桌面 1440／768px 检查角色、品牌文案、表单同屏；手机 390／320px 检查首屏主 CTA、窄屏验证码行、滚动与键盘缩放、无横溢。登录和注册、提示成功与错误、禁用与键盘焦点均验收。动态效果遵守减少动态效果，角色本身无交互。

## Owner 与交付

品牌文案和响应式布局属于 `apps/bibo-hosted`；表单请求及模式继续由现有 chat store 与 client 拥有，不新增鉴权 API 或另一套状态。Bibo SVG 是应用内品牌资产，放在 app 的 `shared/components`，只被概览和认证入口消费；不放入通用 UI package，也不耦合通用控件。设计/实现一次闭环，交付本地可预览界面和桌面／手机实测截图；审美偏好由用户在可见版本上判断。此次不改变账号数据合同，不需迁移、NPM 或 Desktop 发布。`design-document: required`，`plan: not-required`。

## 设计 Review

方案沿用单一 AuthPanel 与现有 auth owner，视觉按断点重排而不是复制两个表单。共享角色恰有两个真实消费者；不引入品牌框架或新增步骤。未登录态的焦点隔离、操作反馈和移动键盘列为验收，设计可进入实现。

## 本地验收记录

未登录实际渲染已检查 1440×900、768×800、390×844、320×700、320×568，以及 900×500 矮桌面视口；经典和简约两主题的桌面／手机画面均可读，无页面横向溢出。320×568 注册表单高度 568px、内容 806px，卡片可独立滚动到提交按钮；模拟视口缩至 320×380 时聚焦密码框会将其滚入可见区域。桌面 500px 高时品牌文案完整保留，表单独立滚动。验证码成功使用正常提示色，失败使用错误色并保留邮箱；切到登录清理旧反馈。真实系统软键盘仍需在设备上主观确认。

BB 三份 tsc、Vite 构建、routing 登录回归、product 回归、定向 ESLint、diff-only maintainability 和新增代码治理通过。登录成功后背景恢复可操作；注册期间背景处于 inert。视觉设计仍可由用户在实际页面上判断品牌气质。
