# Platform Admin 趋势图数值详情设计

## 问题与用户任务

管理员在“产品活跃”的“最近 30 日趋势”中只能看到柱形轮廓和日号，无法判断纵轴量级，也无法稳定查看某一天的活跃与成功数。现有实现把详情放在原生 `title` 属性和无障碍隐藏文本中；它没有可见的交互反馈，触屏与键盘也没有等价入口。

用户任务是：在保留 30 日整体走势的同时，快速判断数值量级，并精确查看任意一天的日期、活跃数和成功数。

## 设计选择

比较三个可行方向：

1. 每根柱子常驻两个数字：精确值最直接，但 30 天共 60 个标签会严重拥挤，零值尤其产生噪声。
2. 只增加浮动 tooltip：桌面精确查看较好，但仍缺少整体量级，触屏和键盘容易失去入口，滚动容器内浮层也更脆弱。
3. 增加 Y 轴刻度，并提供可见详情条，由 hover、键盘 focus 和点击共同驱动：默认展示最后一天，既能建立量级，也能精确查看单日数据。

采用第三种。它完整覆盖用户明确提出的两类缺口，同时不引入图表库、portal 或全局 tooltip primitive。

## 交互与视觉合同

- 图表左侧固定显示最大值、中间值和 0 三档 Y 轴刻度，横向滚动时仍可见。
- 图表上方显示当前日期、活跃数和成功数；默认选择趋势中的最后一天。
- 鼠标进入、键盘聚焦或触屏点击某一天时，详情条立即更新。
- 每个日期是语义化按钮，具备完整可访问名称和 `focus-visible` 反馈；不依赖原生 `title`。
- 当前日期柱组有明确但克制的背景/描边反馈；蓝绿颜色语义保持不变。
- 30 日密度继续使用横向滚动，不把 60 个数字常驻叠到柱体上。
- 空趋势返回明确空态，不构造无意义坐标轴。

## Owner 与边界

- `ProductActivityTrend` 作为 `admin-overview` feature component，拥有图表的局部选择状态、交互和样式。
- API response 继续是唯一数据来源；不镜像到 store，不修改后端或统计口径。
- 页面只传入 `trend`，不持有选中日期，不增加跨页面状态。
- npm 下载趋势不在本次范围内；当前用户反馈与真实复现只命中产品活跃图表。

## 验收标准

- V1：默认可见最后一天的完整日期、活跃数与成功数。
- V2：鼠标 hover 任意一天后，详情条展示该日精确值。
- V3：键盘 Tab 可聚焦每日按钮，focus 后展示相同详情，并有可见焦点反馈。
- V4：Y 轴显示最大值、中间值和 0，且柱体仍按同一最大值缩放。
- V5：窄视口保留详情条、Y 轴和横向滚动，不出现页面级横向溢出。
- V6：原管理后台数据加载、筛选和其它版块 smoke 不退化。

## 验证与交付

- 扩展现有 Platform Admin smoke，验证默认详情、hover、focus、Y 轴与窄视口滚动。
- 运行 Platform Admin `tsc`、lint、build、assembled smoke 和真实浏览器视觉检查。
- 本任务未单独获得生产部署授权；先完成可交付产物，部署状态在交付阶段明确。

## 非目标

- 不引入第三方图表库。
- 不改变 30 日范围、统计口径或蓝绿系列定义。
- 不增加导出、缩放、日期筛选或跨图表共享选择状态。
