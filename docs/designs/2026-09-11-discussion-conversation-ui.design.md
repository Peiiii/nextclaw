# 讨论主题与连续对话体验

- 风险 L2，standard；单批完成，不另建 plan。前序交付已合入 master（dddb9a9e2）。
- 目标：管理员从原讨论页找到主题、阅读不同身份的消息并持续回复，长对话无需滚动整页寻找输入框。
- 现状：DirectDiscussionPanel → useDirectDiscussions → 原管理员 API → discussion owner；已有主题列表、帖子、角色签名及发送接口。浏览器真实主题“测试对话”中管理员与 Agent 已回帖；界面是平铺文本、无定时刷新，草稿会跨主题串用。
- 选择论坛主题列表 + 单列消息流，参考 Slack 线程组织与 Discourse 主题/聊天并存；不做双人左右气泡，避免多参与者身份被左右位置误导。复用既有 API，无协议、订阅器或 Agent 改动。
- 左侧主题选择、右侧固定标题/滚动消息/固定输入区；窄屏主题与详情切换，有返回主题按钮。反馈讨论与直接对话复用消息展示。
- 作者名、认证角色、时间与正文分层；角色来自 authenticated/roles，Agent 保留明确标记，不以正文推断身份。无 Markdown 新依赖。
- 当前主题每 5 秒获取新帖，主题列表每 15 秒更新，仅页面活动时轮询；不调用模型。读取旧消息时保留位置，通过“查看最新消息”回到底部。
- 草稿在 provider 中按主题隔离，切换保留（离开页面不承诺持久化）。发送期间锁定输入/按钮，失败保留草稿，成功只清理对应草稿。Enter 换行，Ctrl/Cmd+Enter 发送；中文组合输入不发送。
- 不新增主题分类、聊天协议、已读回执、富文本编辑器或全局状态框架。

## 验收与交付

1. 桌面原入口可选主题，标题和输入区固定，长消息不撑破布局；窄屏能进入、返回。
2. 管理员与 Agent 显示身份标签；反馈讨论复用相同样式，原审批操作保持可用。
3. 当前主题新回复自动出现；读历史时不抢滚动位置。
4. A/B 主题草稿各自保留；发送失败保留草稿并提示，成功无重复发送；快捷键和中文输入有效。
5. 匹配 package tsc/build、定向交互验证、真实浏览器正常渲染和 diff-only Review 后交付本地可用入口；用户仅确认视觉偏好。测试数据只证明交互，不重演或冒充新的 AI 修复闭环。

方案 Review：检查了多参与者、异步回帖、发送失败和窄屏反例；以上边界已进入设计，无阻塞 finding。

参考：https://slack.com/intl/en-gb/help/articles/115000769927-Use-threads-to-organise-discussions ，https://www.discourse.org/chat 。
