# NextClaw 科研工作台交互原型设计

## 设计目标

本原型回答一个问题：科研人员如何在保持 NextClaw 通用底座不分叉的前提下，把一个课题作为长期、可复现、可观察、可积累的智能研究空间持续推进。

第一版只演示自然科学计算仿真。目标用户来自真实反馈：高校科研人员正在进行“智慧物流多智能体集群协同调度”研究，需要设计或优化算法、运行仿真实验、自动分析结果，并希望 NextClaw 在长期会话和上下文压缩后仍可靠使用项目的 Python 虚拟环境。

可观察的成功结果是：用户打开原型后，能在十秒内判断课题进展、当前执行环境、正在运行的实验、待决定事项和下一步动作；随后能完成“确认实验计划—模拟运行—查看结果—沉淀结论”的闭环。

## 核心产品判断

科研人员需要的不是一个回答科研问题的聊天机器人，也不是若干互不相关的写作、文献和绘图按钮，而是一套持续维护研究状态的工作系统。Chat 是表达意图的入口；科研工作台是长期状态与控制面；对话内卡片是当前任务的即时反馈；Skill 提供科研方法；Service App 或其它运行能力负责受控执行。

科研工作台的北极星是：

> 每个科研项目都是一个长期存在、可复现、可观察、可积累，并能由 AI 持续推进的智能研究空间。

### `AGENTS.md` 的角色

`AGENTS.md` 可以作为 agent 可读的规则投影，承载“本项目使用什么方法、遵循什么约束、优先读取哪些资源”等稳定说明，但不能成为运行环境、实验状态和证据关系的唯一事实源。

原因是：文本规则无法独立证明解释器真实存在、依赖健康、每次执行都经过同一环境解析，也不适合保存运行中状态、实验产物和可查询的证据关系。产品化后，用户通过界面维护结构化项目状态；系统按需把其中适合 agent 阅读的部分投影到上下文或规则文件中，避免用户必须理解提示词工程。

## 候选方案

### 方案 A：聊天与 `AGENTS.md` 增强

继续以 Chat 为主，通过模板自动生成科研项目规则。它实现最轻，但无法形成实验运行、证据、成果和恢复的稳定控制面，仍会把科研连续性压在模型是否正确读取文本上。

### 方案 B：独立“科研版 NextClaw”

复制一套产品入口、数据模型和 UI，直接为科研优化。短期感知强，但会制造平行产品和运行时，通用能力与科研能力容易重复演进，违背统一入口和生态扩展方向。

### 方案 C：通用研究原语 + 科研扩展包（采用）

底座提供项目上下文、环境解析、任务运行、产物、权限、事件和恢复等通用能力；科研扩展包提供研究问题、假设、实验、指标、证据、结论和论文等垂直语义，并通过 Skill、Panel App、Service App 和内联卡片组合体验。

该方案牺牲了“一次性把科研全部内置”的速度，但可以让同一批底层能力继续服务软件开发、数据分析、内容生产和其它长期项目，是最符合 NextClaw 通用平台定位的路径。

## 用户核心路径

### 1. 建立研究项目

用户从左侧固定的“研究”入口进入，选择现有代码目录或新建课题。NextClaw 扫描代码、文档、数据目录和可用运行环境，生成一份待确认的项目画像：研究目标、当前阶段、代码位置、数据位置、Python 解释器、结果目录和成功指标。

用户只确认业务含义，不编辑规则文件。环境无效或依赖缺失时立即显示，并提供检测或修复动作。

### 2. 回到课题

默认首页不展示泛化仪表盘，而是回答五个问题：现在研究什么、做到哪里、什么正在运行、有什么需要我决定、下一步最值得做什么。

用户可以直接说“继续昨天的实验”，也可以从工作台点击“准备下一轮实验”。两种入口进入同一实验计划 owner。

### 3. 形成实验计划

Agent 把自然语言意图转成结构化实验计划，包括假设、对照组、自变量、固定条件、评价指标、运行次数、停止条件、预计耗时和输出位置。用户确认的是研究意图和资源成本，而不是脚本细节。

### 4. 运行与观察

批准后创建不可混淆的 Run。工作台显示代码版本、数据版本、解释器、参数、进度、日志摘要、初步指标和异常。用户可以暂停、取消、调整后重跑；失败必须明确属于环境、代码、数据还是模型判断。

上下文压缩、刷新或重新进入不会改变 Run 所属环境。环境解析来自结构化项目状态，而不是最近一轮对话。

### 5. 分析与沉淀

运行完成后生成永久实验记录。用户比较基线与改进方案，将分析标记为“支持假设”“不支持”或“证据不足”，并把关键图表和结果加入证据库。

结论必须链接到实验和原始产物。后续数据或实验变化时，受影响的结论和稿件段落被标记为待复核。

### 6. 形成成果并继续迭代

论文、报告或汇报材料是研究状态的投影，不是孤立生成物。用户可从证据库生成大纲和初稿，且每个关键数字、图表和引用都能回到来源。新的证据缺口会重新进入实验或文献任务。

## 原型信息架构

原型使用一个 NextClaw 桌面工作区壳，展示同一科研扩展的三种承载形式：

1. **左侧固定入口**：进入长期科研工作台，选择课题和研究视图。
2. **主工作台**：展示课题总览、实验计划、运行观察、结果证据和论文衔接。
3. **对话协作区与内联卡片**：解释下一步、请求批准、报告异常和交付阶段结果。

评审栏提供五个可直接切换的故事阶段：

- 课题首页；
- 实验设计；
- 运行观察；
- 结果沉淀；
- 论文衔接。

首屏默认选择“课题首页”，并使用真实反馈中的项目数据。阶段切换用于评审同一产品闭环，不代表生产产品需要这组顶部控件。

## 跨科研场景的映射

自然科学仿真中的“实验计划—运行—指标—结论”，在其它场景中映射为：

- 文献研究：检索计划—阅读与归纳—证据矩阵—观点；
- 社会科学：研究设计—问卷或访谈—编码与统计—结论；
- 实验室研究：实验方案—人工或设备执行—观测数据—结论；
- 论文写作：论点结构—证据装配—段落与图表—审校与投稿。

第一版原型不把这些场景混进同一页面，只在“科研能力包”入口中保留它们的可扩展性说明。

## 状态与职责边界

### 通用底座原语

- 项目与 workspace 身份；
- 结构化、可查询的长期上下文；
- 环境发现、解析、健康检查和项目绑定；
- Job/Run 生命周期、日志、暂停、取消、重试和刷新恢复；
- 文件、数据、图表和其它产物引用；
- 权限、资源预算、通知和失败分类；
- App 实例存储、事件和跨表面打开能力。

### 科研扩展包语义

- 研究问题、假设和研究计划；
- 实验、协议、变量、指标和停止条件；
- 文献、数据集、实验记录、证据和结论；
- 稿件、图表和结论之间的追溯关系；
- 科研方法 Skill 与对应 Panel App 视图。

同一事实只保留一个 owner。科研扩展读取通用 Run 和 Artifact，不复制一套运行时；通用底座不理解“假设是否成立”等科研语义。

## 关键状态与恢复

- **首次进入**：展示项目扫描和画像确认，而不是空白仪表盘。
- **正常态**：突出下一步、运行任务、待决定事项和环境健康。
- **运行中**：持续显示使用的环境、代码、数据、参数与进度。
- **失败态**：区分环境、代码、数据和推理错误，保留已完成产物并给出重试路径。
- **刷新或重进**：恢复课题、视图和 Run 状态，不根据聊天文本重新猜测。
- **旧项目**：允许从目录和历史文件重新生成待确认画像，不声称自动恢复不可证明的历史实验关系。

## 交互与视觉原则

- 视觉应像可信赖的研究台账与仪器控制面，而不是泛化的 SaaS 数据大屏。
- 默认态首先表达研究目标、状态和下一步，次级统计不抢占首屏。
- 环境、代码和数据版本始终可见但保持紧凑；异常使用明确原因，不只用颜色。
- 所有状态切换和命令使用真实按钮语义，支持键盘焦点；阶段标签使用可理解的选中状态。
- 内联卡片承载一次批准或一次结果，长期浏览和比较回到工作台。
- 使用真实中文科研内容和合理数据，不使用占位文本。

## 原型交互范围

单文件 HTML 原型至少支持：

- 切换五个故事阶段；
- 从课题首页进入实验计划；
- 确认实验计划并开始模拟运行；
- 在运行态查看进度、环境、参数和日志摘要；
- 模拟完成运行并进入结果比较；
- 将一个结果标记为证据并看到论文衔接状态更新；
- 在窄屏下保持主要内容可读，不出现关键动作不可达。

## 非目标

- 不接入真实 Python、Conda、数据集、模型或后台任务；
- 不验证科研方法或实验结论的科学正确性；
- 不冻结最终数据库、API 或扩展协议；
- 不设计多人协作、伦理审批和投稿系统的完整合同；
- 不发布公网地址，不修改现有 NextClaw 产品实现。

## 验证标准

- HTML 可直接打开且无阻塞脚本错误；
- 五个阶段和核心 CTA 均能到达正确状态；
- 用户无需阅读说明即可识别研究目标、项目环境、当前实验和下一步；
- 运行前后都能追溯代码、数据、环境、参数和产物；
- Chat、长期工作台和内联卡片的职责没有重复或相互冲突；
- 视觉检查覆盖默认态、运行态、结果态和窄屏布局。
