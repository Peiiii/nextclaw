## 生成中切换会话的补充设计

2026-09-27 用户追加要求 M20。Navigation 链接拦截 → BiboApp 路由反跳 → BiboChatOwner 的 create/select guard 是三处同源阻断；发送事件回调直接写当前 messages、recoverRun 直接恢复当前 draft，因此不能只移除禁用样式。BiboClient 的 chat SSE 由 store 持有，切路由不销毁它；服务端 `BiboContainer.fetch` 允许运行期间 GET history，`run` 和会话写操作仍受账户级 inFlight 保护。这是当前服务的实际执行限制，本批修复导航，不增加模型并发或服务端队列。

采用现有单运行 owner：记录运行所属 sessionId 与该会话历史快照；当前查看会话仍由 activeSessionId/messages/draft 拥有。切换到其他会话读取其历史，切回运行会话直接呈现历史快照与持续 partial。committed 更新所属会话的正式历史和目录，只在它仍是当前会话时替换 messages；失败只恢复所属会话的 draft/failedMessages，并以按会话归属的错误供该会话显示。账号切换后的旧事件不得写入新账号。空会话创建请求期间切走也不能强行抢回当前路由或草稿。

删除三处导航 phase guard，保留单次发送互斥、保存提交判定与运行会话的停止。生成中的会话在导航显示小进度标记；其他会话可阅读和编辑下一条草稿，当前服务已有后台运行时暂不发起第二次模型调用。新建空会话不请求服务端，允许正常导航。删除会话等写操作继续遵循服务端约束。

风险升为 L3，design-document=required，plan=not-required：仍可在当前 owner 与既有浏览器 smoke 中闭环。验收：桌面／手机 A 发送 → 切 B 阅读并编辑草稿 → A 持续 delta，B 无 A 内容 → 切回 A 显示持续回复；在 B 时 A committed → B 不跳页、不丢草稿 → 回 A 有完整历史；在 B 时 A 失败 → B 不显示 A 错误 → 回 A 恢复失败内容并可重试。测试使用真实 React/SDK SSE 与控制事件回放，服务端读取约束复用已检查源码；不宣称真实模型并发能力。补充 design-review: passed，范围 M20 及这三条链路。

列表、按钮、输入、分段、Tab、菜单已复用现有公共组件；不新增视觉框架或第二套配方；运行归属集中在现有 store。配色由应用 token 覆盖，两主题共用几何。消息 speaker 标记继续保留已有语义，不重做协议或持久化。

## 文件工作区两行结构与目录面包屑（2026-09-28）
