## 范围判断

纳入文档编辑本身及相邻阅读、图片、表格、键盘与保存能力。团队权限、数据库计算/视图、评论通知和 AI 自动化属于不同产品结果，不以 Notion 的整个平台清单扩展本 goal。用户明确允许按实际情况取舍外部页面嵌入；本轮先验证文档核心，嵌入在调查后记录具体收益与产品边界。不得把尚未做完的核心能力改称范围外。

## 架构与方案

继续 Tiptap/ProseMirror 与现有 Markdown 保存主链路。换内核不能解决已知入口/序列化缺口，且会重新引入上一轮已关闭的 IME/历史/保真风险。文档持久化仍归 Bibo space store，内核拥有节点、选区与历史；临时浮层状态由 editor manager 管理，组件只连接和显示。

选区栏在现有 editor 的 selection/transaction 生命周期派生位置与状态，复用 AnchoredPopover 与 IconButton；不引入第二份编辑选区。纯布局和文案属于共享 UI，品牌色继续使用主题 token。块加号复用现有官方 DragHandle 的单一目标和定位，不给每个 NodeView 加入口。

命令目录应统一 slash、加号和菜单投影的 ID、标签、别名、分组、图标与执行语义，避免出现新增项只有半套文案的问题；不扩成全局插件注册框架。结构格式的表示比较普通 Markdown、标准 HTML 扩展和私有注释元数据：优先普通 Markdown；必要的富排版须使用可审计、可恢复的标准表达和既有 sanitizer，不容许静默丢失或直接放开任意 HTML。具体结构/媒体持久化设计在相关工作项写入前补足端到端证据。

## 黄金使用链路与验收

1. 打开笔记→阅读→编辑→选区就近格式/链接→加号/slash 插块→键盘调整顺序或删除→撤销→预览→保存刷新。结果的格式、内容、顺序保持，焦点始终可继续写作。
2. 打开含表格/代码/公式/图片的混合文档→调整对象与说明→窄屏继续输入→源码检查→保存并重新打开。无格式假支持、意外跳焦、工具遮挡和数据丢失。
3. 打开长文→目录定位→阅读布局调整→编辑标题和结构→目录同步→返回阅读。长文输入不因派生导航/浮层逐键全量重建而卡顿。

覆盖 1440/390/320px、两主题、鼠标/键盘/模拟触控、输入法、选区方向、视口边缘、滚动、菜单相互切换、原始特殊 Markdown、失败与冲突。实体设备/全部浏览器及主观偏好不能由本机 Chromium 测试证明。最终提供真实线上入口和本地预览，并说明可验证边界。

## 表格持久化方案补充（2026-09-29）

真实内核实验将首个单元格 colwidth 设置为 180，getMarkdown 后重新 parse 得到 colwidth=null；上游 renderer 只投影 text/header/align。当前列宽支持因此不完整。表头列、合并和逐单元格对齐同样超出 GFM 的表示能力。

普通表格继续 GFM；有列宽、合并、非首行表头或复杂块内容时，保存标准 HTML table，不使用平行 JSON 或私有注释。HTML 由同一 Tiptap schema 生成与解析，列宽规范化成标准 col width 并保留内核单元格 colwidth。只有受支持的表格 HTML 从 raw 节点升级成可编辑表格，未知 HTML 继续保留原文。阅读态仅对文档启用现有 rehypeRaw→sanitize 安全链，并补充明确的 col/colgroup 尺寸合同；禁止任意脚本、样式和 iframe。

表格操作优先复用 ProseMirror tables：行列增删/表头/移动、范围合并拆分和列对齐；菜单动作以实际目标单元格与 TableMap 为准，新增聚焦新增内容，其他操作保留原选择。验证覆盖宽度/表头/合并→源码→富文本→预览→保存刷新，及不可信 HTML 不执行。此路径仍保留 Markdown 文件可移植性，普通表格不无故转换。

## 图片链路方案补充（2026-09-29）

现有空间文件 owner 只以 UTF-8 读写文本，单文件 1 MiB；Worker `/api/space` 经租户 DO/容器代理，无二进制上传合同。不能把 base64 图片塞进 Markdown 或借文本文件接口伪装上传。

图片采用独立的私有资源入口 `/api/assets`：Worker 认证后，将有大小上限且按文件头核验的 PNG/JPEG/GIF/WebP/AVIF 保存到已有 R2 binding 的独立租户前缀；读取按当前用户隔离，不公开桶、不信任客户端用户 ID。返回稳定的同源 `/api/assets/<uuid>`，Markdown 只存引用；异步上传成功后才插入，失败保留文档和可重试反馈。相邻快照链不承载图片，也无需改容器镜像。认证、大小、非法类型、跨账号与保存刷新均需验证。

公共编辑器只接受 uploadImage 回调，不认识 Bibo API；客户端 SDK 和宿主接线承载上传协议。支持文件选择、粘贴/拖入；异步插入位置使用内核 bookmark 随 transaction 映射，避免用户继续输入时插错。图片 URL 编辑同时提供 alt、说明与宽度；有富属性时使用标准 HTML figure/img 表达并共享读写样式，普通 Markdown 图片不强制变格式。图片拖拽调整宽度必须可撤销且保存，移动端有明确数值/预设入口，不依赖 hover。

实现收敛：图片说明复用标准 Markdown image title，宽度使用标准 HTML img width；无需引入 figure 平行节点。官方 ResizableNodeView 3.31.3 的构造与 destroy 分别调用 `.bind(this)` 注册/解绑 update，函数引用不相同；本轮不接入该实现，复用现有唯一 ImageNodeView 的短生命周期 pointer capture 拖动，在提交时只写一次宽度事务，取消/销毁清理监听。此结论来自本地安装版本源码，非对所有版本的推断。

本地预览服务为临时独立数据，新增资源路由前须备份当前 home，保留原用户文档和浏览器草稿；禁止通过重启重新生成样例覆盖用户正在测试的内容。资源删除与孤立资源回收是后续资源生命周期设计事项，本轮不能提供会破坏撤销/历史引用的自动删除。

## 结构与强调方案补充（2026-09-29）

折叠采用同版本官方 Details/DetailsSummary/DetailsContent，复用其键盘、光标与展开状态；参照 [官方 Details 合同](https://tiptap.dev/docs/editor/extensions/nodes/details)。保存为标准 details/summary HTML，正文仍走同一安全 schema；阅读沿用现有折叠 primitive。明确验证标题输入、Enter进入正文、折叠/展开、嵌套内容、块操作与源码往返。

提示块采用 GFM 风格 `> [!NOTE]`（及已有导入的 TIP/IMPORTANT/WARNING/CAUTION），编辑复用 blockquote 节点加语义属性；阅读从 Markdown AST 提取同一标记，用共享文档样式呈现图标与强调底色。普通引用不改语义。下划线与高亮使用 u/mark 的有限 HTML 标记，parse/render 和 sanitizer 只放行对应语义；不开放任意 style，不把未知 HTML 升级后静默丢掉属性。插入目录与选区格式栏仍使用原单一命令/状态 owner，扩展不增加独立编辑器。

## 长文阅读与文档设置（2026-09-29）

以 [Notion 目录说明](https://www.notion.com/help/columns-headings-and-dividers) 为依据，目录聚合正文顶层标题，保留层级缩进，不包含列表、引用、折叠正文内的缩进标题。标题来自当前可见的阅读/编辑 DOM，不另外解析 Markdown 或复制内容状态。只有打开目录时收集一次；打开期间监听标题变化并合并更新，关闭即断开，避免日常输入增加工作。点击滚到章节，不移动编辑选区或写入文档。源码模式隐藏此入口。

文档导航与低频排版设置共用一个紧凑图标入口和已有 Popover：上方目录、下方标准/全宽、小号/标准字号，以及打开时计算的字符统计。两种模式共用 CSS 变量；偏好本地保存，禁止写入 Markdown。窄屏浮层限高可滚动且不占正文宽度，键盘可选目录并关闭。语义字符统计使用当前正文文本快照，不在每次输入中解析。

ND04/05 方案自审：复用官方节点、现有浮层与读写 owner；没有新的持久内容模型。目录范围与来源已明确，重复标题按实际 DOM 节点定位；退出源码/切换模式后重新取当前根。需验证尺寸切换不丢焦点/草稿、读写几何一致、目录跳转和无标题态，性能复用长文输入指标。design-review: passed，仅适用于此处结构和文档设置范围。

## 最终范围与体验收敛

手机提供常显“当前块操作”图标，直接使用同一块 manager 的当前选区入口；桌面仍以块旁加号/六点手柄为主要路径。窄屏隐藏已有二级菜单可达的列表和斜体快捷按钮，保留触摸目标尺寸，避免工具栏溢出。图片无指定宽度时，其说明按图片实际宽度居中；选中边框仍贴合图片而非外包空白。

本轮不开放任意网页 iframe：现有 HTML 文档预览按 CSP 隔离、Markdown 读取会清除 iframe；通用嵌入需独立定义来源、登录和隐私合同，没有已确认的文档写作收益。用户明确允许此项按产品边界取舍；已有链接、图片和 Mermaid 保持可用。私有图片复用现有 R2，不新增付费实例或常驻轮询；费用来自实际图片存储和请求，每张限制10 MiB，上传成功才写入引用。

复盘：本轮收敛暴露的窄屏工具栏、图片几何与重复焦点恢复问题，分别修共享样式/块 manager，回归保护实际入口。成熟参照、控件密度、图标/文字和真实视觉验收已由上一轮更新的 frontend-interaction-quality owner 覆盖，无新的一类规则缺口；不重复增加 Skill 或常驻指令。
