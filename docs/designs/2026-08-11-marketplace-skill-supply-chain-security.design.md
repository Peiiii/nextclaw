# Marketplace Skill 供应链安全与事故撤销设计

## 结论

本次事故不是 `bird` CLI 二进制被替换，而是第三方 `SKILL.md` 在导入时已经包含恶意远程执行说明，随后又被历史迁移批量赋予 `@nextclaw/*` 官方身份并自动发布。Marketplace 当时只验证文件结构和 Base64 可解码，没有验证内容风险；真实安装冒烟只证明“能安装”，没有证明“可安全执行”。

永久修复采用一条标准主链路：

```text
上传文件
  -> Marketplace API 内容安全准入
  -> blocked：拒绝落库
  -> review：允许保存但保持 pending
  -> safe：按身份与自动审核策略决定 pending / published
  -> 管理员发布前重新扫描
  -> published 才进入公开查询与镜像
  -> rejected 后源站立即不可见
  -> 国内镜像按最新公开清单驱逐已撤销技能的详情和文件缓存
```

Marketplace API 是内容准入与发布状态的唯一 owner。国内镜像只复制公开状态并负责撤销传播，不拥有第二套审核规则。CLI/UI 不自行复制一套可漂移的发布判定。

## 事故证据与根因

### 已确认事实

- 2026-02-27，`bird-su` 从外部技能仓库导入时，恶意说明已经存在。
- 同日技能改名为 `bird`，安装冒烟只检查安装成功和 frontmatter 名称。
- 2026-03-08，恶意内容进入 Marketplace D1 种子迁移。
- 2026-04-10，历史技能被批量赋予 `@nextclaw/*`、`published` 和 `admin`，第三方内容因此获得了错误的官方信任外观。
- 2026-06-20，本机审计删除了本地副本中的恶意段落，但没有撤销中央 Marketplace 条目，也没有检查国内镜像。
- 2026-08-11，源站拒绝发布后立即返回 `404`；国内镜像仍通过旧详情和文件缓存返回 `200`。同步器会刷新仍在公开清单中的技能，却不会驱逐已经从清单消失的技能缓存。

### 根因分层

1. 直接原因：导入的 `SKILL.md` 包含已知攻击活动的远程执行与混淆下载指令。
2. 准入缺陷：上传解析器只校验结构、路径和 Base64，没有内容安全策略。
3. 信任缺陷：`@nextclaw/*` 被视为无条件自动通过，官方 scope 等同于“安全”而不是“身份”。
4. 验证缺陷：安装冒烟验证可安装性，没有验证内容、来源、权限和执行风险。
5. 撤销缺陷：拒绝发布只改变 canonical D1 状态，国内快照镜像没有 tombstone/集合差分驱逐。
6. 响应缺陷：本机修复没有上升为中央撤销、全目录审计和公开影响处置。

## 设计目标

- 已知恶意内容不能通过任何发布身份写入 Marketplace 文件存储。
- 远程下载后直接交给 shell、混淆解码后执行等高风险内容不能自动发布，包括 `@nextclaw/*`。
- 管理员不能把仍命中已知恶意规则的历史内容重新发布。
- canonical 条目撤销后，所有公开源的详情、内容、文件清单和文件下载都在一次同步内变为不可用。
- 历史种子不再包含可直接复制执行的恶意载荷；已有数据库通过新迁移保持拒绝状态。
- 事故样本保留在管理员后台和 Git 历史中，不用公开下载路径继续承担取证职责。
- 安全策略结果可通过稳定的错误码和审核备注进行测试与审计。

## 非目标

- 本次不建设完整沙箱、行为检测或 EDR。
- 本次不把国内镜像升级成第二个发布后台。
- 本次不因为参考 VS Code 就复制它的代码、商标或全部产品结构。
- 本次不对所有合法安装脚本作语义重写；通用高风险模式先进入人工审核，不直接等同恶意。

## 方案比较

### 方案 A：只下架 `bird`

优点是动作最小；缺点是相同载荷可以换一个名字再次上传，国内镜像仍可能保留撤销内容。只能止血，不能解决根因。

### 方案 B：只在 CLI 安装时扫描

可以保护新客户端，但旧客户端、网页读取、其它安装器和镜像仍暴露；同时客户端与服务端容易形成两套漂移规则。不能作为主 owner。

### 方案 C：服务端准入 + 管理员复扫 + 镜像集合对账

这是本次选择。它在内容第一次进入系统时阻断已知恶意，在发布状态变化时沿唯一公开链路撤销，并让镜像以 canonical 公开集合为准清理孤儿缓存。CLI/UI 只消费可信公开结果。

## 冻结接口与状态语义

### 内容安全结果

安全扫描返回：

```ts
type MarketplaceSkillSecurityVerdict = "safe" | "manual-review" | "blocked";

type MarketplaceSkillSecurityFinding = {
  code: string;
  verdict: Exclude<MarketplaceSkillSecurityVerdict, "safe">;
  filePath: string;
};
```

- `blocked`：已知 IOC、远程命令混淆解码后执行、明确的命令替换远程 shell。上传直接失败，不落 D1/R2。
- `manual-review`：通用 `curl`/`wget` 下载后直接交给 shell、PowerShell 下载后执行等。允许保存，但无论发布者身份如何都保持 `pending`。
- `safe`：未命中当前策略；仍需遵循既有身份和自动审核配置。

策略扫描所有文本型文件，并对可识别的内嵌 Base64 文本做有限深度解码后再次扫描。二进制资产不按文本正则误判。

### 官方 scope

`@nextclaw/*` 只证明发布权限，不证明内容安全：

- `safe` 的官方技能可继续自动发布。
- `manual-review` 的官方技能必须进入 `pending`。
- `blocked` 的官方技能与普通用户技能一样拒绝。

### 管理员审核

- `rejected` 始终允许，用于立即隔离并保留证据。
- 请求改为 `published` 时重新读取当前存储的全部文件并扫描。
- `blocked` 不允许发布；`manual-review` 允许管理员在明确审核动作后发布。

### 镜像撤销

每次成功取得最新公开技能清单后：

1. 读取上一版 manifest 的 slug 集合。
2. 计算 `removed = previous - current`。
3. 遍历响应缓存元数据，只删除路径属于 removed slug 的详情、content、files 和 blob 缓存。
4. 写入新 manifest，并记录被驱逐的 slug。

只有在源站公开清单成功返回时才执行集合差分。网络失败沿用旧快照，不把网络故障误判为全量撤销。

## 数据与迁移

- 新增 `0010` 技能迁移，将 `bird` / `@nextclaw/bird` 明确设置为 `rejected`，写入安全隔离备注和审核时间。
- 历史 `0002` 中的公开恶意文本替换为不可执行的安全占位内容，避免新环境在迁移中再次写入载荷。
- 不删除线上 D1/R2 事故样本；公开读取由发布状态控制，管理员读取继续用于取证。
- 不新增第二个 security status 列；本阶段使用 `publish_status` 表达可见性，安全原因写入 `review_note`。只有出现多类独立合规状态时才扩展状态模型。

## VS Code 参考边界

上传、安装和管理交互可以复用 VS Code 已被用户理解的范式：发布者身份、来源、权限/风险提示、禁用、卸载、更新与回滚。复用的是用户心智和信息层级，不是把 UI 相似性当成安全能力。

NextClaw 必须自己拥有：服务端内容准入、官方 scope 策略、审核状态、撤销传播、镜像对账和事故证据。任何一个都不能外包给“用户点击前应该自己看懂”。

## 客户端更新的本地修改保护

Marketplace 技能安装后允许用户直接修改，因此普通更新不能静默覆盖技能目录。此前底层已经能检测本地漂移并支持 `force`，但 Web 链路把冲突压成通用 `MANAGE_FAILED`，设置页只能显示失败，用户既不知道原因，也没有安全的继续入口。

标准更新链路冻结为：

```text
用户点击更新
  -> 普通 update（不带 force）
  -> 无本地漂移：直接完成
  -> 有本地漂移：HTTP 409 + MARKETPLACE_SKILL_LOCAL_CHANGES
  -> UI 展示破坏性确认
  -> 取消：不再发请求，文件保持不变
  -> 确认：仅对同一技能重试一次 force update
```

职责边界如下：

- skill lifecycle 是本地文件漂移判定的唯一 owner，抛出具名且带稳定 code 的冲突错误。
- service 的 CLI 子进程边界只恢复这一个确定性错误；其它失败继续保留原有通用错误路径。
- server 将该错误映射为 `409`，并返回稳定 code 与技能 slug；UI 不解析堆栈文案。
- UI 只对该 code 抑制普通错误 toast，并在用户明确确认后发送 `force: true`。正常更新、卸载、启停和其它错误不进入覆盖确认。
- 不自动备份、不自动覆盖，也不把 `force` 设为更新默认值；未来若增加 diff/备份，应继续挂在同一冲突分支，而不是复制第二套漂移检测。

这一附加交互可以独立演进或移除：删除确认 UI 后，底层默认仍是拒绝覆盖，不会改变 Marketplace 安装和更新的安全主语义。

## 可观察验收条件

1. 两个公开域名的 `bird` slug、package selector、content、files 和 blob 均返回 `404`。
2. 上传包含本次 IOC 或混淆远程 shell 的文件返回确定性校验错误，D1/R2 不产生新版本。
3. 官方 scope 上传通用远程 shell 管道时返回成功但状态为 `pending`。
4. 管理员发布已存储的 blocked 内容失败；拒绝发布仍成功。
5. 镜像测试证明上一版存在、最新版移除的 slug 会驱逐全部详情/文件缓存，未移除技能不受影响。
6. 本地和远端迁移执行后，`bird` 最终状态为 `rejected`。
7. 定向 TypeScript 编译、lint、Python 单测、真实线上读取复核和可维护性检查通过。
8. 修改已安装技能后，普通更新返回 `409 / MARKETPLACE_SKILL_LOCAL_CHANGES`；确认后只追加一次 `force` 重试，取消时不产生第二次更新请求。

## 交付顺序

1. 线上 canonical 拒绝发布并精确驱逐国内镜像旧缓存。
2. 实现内容安全策略，接入上传与管理员发布复扫。
3. 修复种子并添加撤销迁移。
4. 修复镜像 removed-slug 缓存驱逐与测试。
5. 扫描现有线上目录和本机安装痕迹，形成事故影响与用户处置说明。
6. 通过分级验证后发布 Worker、应用远端迁移，并更新 ECS 镜像脚本；不重启 NextClaw 宿主。
