# NC-182：聊天发送预检查与接收确认

日期：2026-09-24。状态：实现前设计。范围：聊天输入框普通发送、插入当前任务及预设消息的共同提交链路。

## 用户结果

用户在聊天输入框写好消息，即使前端的运行时启动状态滞后，也可以点击发送。真实请求被接收后，输入框清空且消息进入会话；请求明确失败或返回未接收结果时，当前会话显示错误并保留可重试的草稿。空输入仍不可发送，正在提交同一条消息时仍阻止重复点击。

## 现状与边界

`isNcpChatRuntimeBlocked` 从启动状态推断可用性，`isNcpChatSendDisabled` 和 `buildSubmissionDraft` 都以该推断阻断发送。`useNcpAgentRuntime.send` 在请求未被接收时可能返回 `null`；上层 `useSubmissionDraftRunner` 只捕获异常，因而可能把 `null` 当作成功。上层已有 `sendError` 会话内展示和失败草稿恢复入口。

选择由实际 `agent.send` 结果决定发送成败：有可发送内容且没有正在提交时允许请求；仅收到非空运行句柄才完成清稿流程。抛错与空句柄走同一个失败反馈与恢复路径。启动状态仍可用于展示诊断信息，不充当发送许可。此处不新增并行状态机或传输重试。

## 验收链路

1. 用户在会话输入非空消息，客户端状态误报不可用；发送按钮可用，点击后真实调用 `agent.send`。若服务端返回句柄，消息显示且草稿不回填。
2. 用户发送时请求抛错或返回空句柄；会话内可见错误，原内容仍可编辑并再次发送。输入为空时按钮不可用，连续点击不会并发提交。
3. 新会话、运行中排队和快捷键发送沿同一提交判定；不因状态误报静默忽略输入。

验证包括输入可用性测试、控制器成功/失败测试、匹配范围的 TypeScript 检查，以及实际页面上正常和错误状态的交互检查。移动端导航与输入法草稿竞态由 NC-184 处理，流式输出阅读位置由 NC-183 处理。
