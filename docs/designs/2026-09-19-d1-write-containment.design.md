# D1 写入紧急止血设计

## 问题与证据

`nextclaw-provider-gateway-api` 的分发采用量同步每两小时运行一次。同步过程对
`distribution_download_assets` 使用无变更条件的 upsert，因此上游累计下载数没有变化时也会重写全部资产。
2026-09-19 的生产 D1 查询显示该语句在 12 小时内执行 17,195 次、写入 34,390 行，已经成为账号每日写入额度的主要来源之一。

## 决策

立即把 Worker 配置中的 Cron Trigger 显式设为空列表，暂停自动分发同步。显式空列表用于让 Wrangler 删除生产环境中已经存在的调度，而不只是停止声明新调度。HTTP/API、D1 schema、已有快照和管理员读取链路保持不变；不删除数据，不修改 Secrets，也不迁移数据库。

恢复定时同步前必须先给资产 upsert 增加“字段发生变化才更新”的条件，并以空变更同步证明 D1 写入接近零。恢复动作需要单独提交和生产验证，不能只在 Cloudflare 控制台手工加回触发器。

## 验收与恢复

- 部署后的 Worker 不再存在 `5 */2 * * *` Cron Trigger。
- `https://ai-gateway-api.nextclaw.io/health` 继续正常响应。
- 生产 D1 不再出现由自动分发同步带来的周期性批量写入。
- 手工管理接口和已有采用量快照继续可读；本次不主动触发刷新，避免在额度临界时制造新写入。

## 非目标

本次是紧急遏制，不重构分发统计、不清理历史数据，也不把同步迁移到新的调度系统。根治补丁完成并验证前，自动数据新鲜度让位于数据库可用性。
