# Bibo 紧凑动态状态图标

用户要求删除截图中的「Bibo · 空闲」文字状态，用简约 SVG 动效表达不同状态，且不能独占一行。状态让用户知道搭档是否正在参与，同时为阅读和操作留出空间。

## 用户链路与布局

登录后，桌面在侧栏品牌同一行看到唯一状态图标；收起侧栏后，图标移至图标栏顶部。手机在现有标题行看到图标。概览不为状态新建顶栏。悬停或键盘聚焦可读完整状态。其他会话有运行时，图标成为真实链接，点击返回运行会话；同会话与空闲时只读，不伪装成操作按钮。屏幕阅读器通过唯一 polite 状态文本获得更新。

发送后图标从空闲过渡至思考；工具执行、保存、停止和恢复连接分别显示不同轮廓与动效；完成后回到空闲。刷新和重连仍从原 store 取得状态，不新增请求、计时器或状态 owner。

## 唯一 owner 与取舍

账号运行事实继续由 BiboChatOwner/BiboRunRecoveryStore 持有，现有 RunStatus 只连接与展示。共享组件 ActivityIcon 仅拥有 SVG 图形与 CSS 动效，品牌颜色来自主题 token，Tooltip、NavigationItem 复用现有公共控件。只保留一个可见实例，删除旧的两处文字行与样式。

不采用单色静态圆点，因为不能以轮廓区分状态；不采用文字胶囊，因为仍占宽度。采用 18px 线性图标：空闲为呼吸圆点，思考为圆弧旋转，执行为错峰短线，保存为向下收拢箭头，停止为轻退方形，恢复连接为双向环弧。减少动态效果时停掉所有循环，保留各状态轮廓。

公开视觉变体只有 idle/thinking/working/saving/stopping/reconnecting；输入由 RunStatus 映射，组件渲染和 CSS 消费。没有序列化、存储、协议、runtime、安装变更。保留底层状态与跨会话链接，不引入图标注册机制、状态 service 或动画依赖。

## 验收与交付

桌面展开/收起、手机与 320px 窄屏都不出现独立状态行、重复图标或标题拥挤。发送、保存、停止、断流恢复、完成、刷新和后台会话跳转保留原行为。检查两种主题、hover、键盘焦点、屏幕阅读标签、减少动态效果和动效中间帧。沿现有浏览器冒烟验证发送、滚动、保存、刷新、失败恢复，运行 Worker/网页/脚本/共享 UI 类型检查、Vite 构建和 diff maintainability。

按 Bibo 已授权完整交付合同精确提交、集成远程 master、部署 Worker/UI（无 Container rollout）并线上复验。主观动效偏好由用户在 app.bibo.bot 判断；AI 证明渲染和行为。无需独立 plan，单批可闭环。

## 验证边界

六种状态、单一实例、品牌/标题同行、hover 与键盘提示、侧栏折叠、主题、减少动态效果、跨会话返回、断流恢复、停止和刷新由运行恢复浏览器冒烟证明。Worker/网页/脚本与共享 UI 类型检查、生产构建、141 项服务与状态测试、桌面/手机问答冒烟通过。

完整产品冒烟完成包含 320px 的主体流程后，在手机文件工具栏遇到既有断言差异：脚本要求 44px，实际为 44px 触控控件加上下各 6px，即 56px。使用 HEAD 原始 App、CSS、公共导出构建独立基线，与修改后产物沿同一文件页入口实测，均为 56px、padding 6px 12px。本次没有修改该工具栏，不把全产品冒烟报告为通过。

本轮纠偏沉淀在共享 UI README、Bibo 使用说明和本设计：状态放进既有身份/标题行，维持单一可见实例和状态 owner；不为一次性目录预算告警增加例外，图标与样式内聚在 feedback 目录。
