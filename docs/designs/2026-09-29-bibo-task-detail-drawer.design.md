# Bibo 任务详情抽屉

## 目标与现状

用户从任务列表或看板点击任务后，希望在当前工作上下文中阅读和编辑详情。现状是居中 `Dialog` 承载整个 `TaskForm`，正文与属性在同一竖列且属性默认折叠；长内容需要在较窄弹窗中连续滚动。任务选择、草稿、保存与失败恢复已由 `bibo-space.store` 和 `TaskForm` 负责。

## 方案

首版双栏表单被用户否定：标题缺少主次、说明被文本框截断、右侧属性与常驻删除操作抢占注意力。真实任务包含长 Markdown 和五个子任务，原短内容冒烟不能作为视觉验收依据。

重设计为阅读优先的任务页面：右侧抽屉内由大标题、紧凑属性、完整 Markdown 和带进度的子任务组成单列。默认焦点停在抽屉容器。顶部编辑动作原位切换到编辑模式，保存后留在详情阅读页；取消丢弃草稿，直接关闭保留草稿并在重开时恢复编辑。删除收进更多菜单并二次确认。子任务完成状态在阅读模式直接提交，失败保持原状态。

说明复用公共 `MarkdownEditor`，增加 `layout="embedded"`，编辑区随内容增长，使用任务详情的滚动容器。富文本内核、工具条、粘贴、Markdown 转换和图片上传与文件页共用。新建任务也消费同一编辑组件。公共 Sheet 提供 header actions 与 content focus；业务状态仍由现有 store 和领域动作拥有。

编辑器延迟同步必须在提交前 flush；提交读取 store 最新草稿，保存失败保留内容。保存期间的新输入不能被成功响应覆盖，版本号随成功结果推进。

本地 review 后继续收敛编辑态：标题下方以紧凑属性入口打开属性浮层，保持与阅读态一致的信息顺序；嵌入编辑器去掉外框和文件页的大内边距；添加子任务按需展开。属性浮层用 Escape 关闭时须保留任务抽屉及草稿。

选择右侧抽屉是因为它保留任务列表的空间位置，符合列表到详情的阅读方向。居中宽弹窗仍会遮挡列表；固定分栏会持续压缩看板和列表，因此不采用。仅扩展共享抽屉的几何参数，不新增业务状态或数据路径。

## 验收

以用户截图的长标题、三段目的说明、关联笔记和五个子任务为验收内容，检查桌面与手机的主次、全文可读、单一纵向滚动、操作可达和焦点恢复。行为检查覆盖富文本输入立即保存、失败重试、关闭重开恢复、取消清除、子任务更新、更多菜单及删除确认。文件编辑器默认 document 布局保持，导航抽屉仍从左侧打开。
