# 对话内互动成果官网展示设计

## 要解决的问题

首页曾把滑块、图表和会话卡片分别画在一个官网演示中。它只能说明“网页上的数会变”，却不能证明控件属于 NextClaw；访问者不会自然地把这段效果理解为自己在产品里可以得到的能力。

用户任务：访问首页的人看到一条真实的 NextClaw 对话，亲眼看到一份工程计算小工具直接出现在回复里。拖动载荷、臂长和安全系数时，梁挠度曲线、应力读数和“可/不可用”结论同步更新；该过程以短视频播放，而不是依赖一张静态截图来想象。

同时，官网现有首屏与结果截图多为 500KB–1.1MB 的 PNG，线上静态资源响应是 `Cache-Control: public, max-age=14400, must-revalidate`。首访被图片体积拖慢，复访也会频繁校验资源。

## 已确认事实与约束

- `nextclaw-inline` 是聊天内展示声明。Panel App 目标可作为消息内卡片展示；`placement: inline` 不会自动打开侧栏，用户可在需要时展开同一个结果。
- 聊天消息中的 `nextclaw-inline` 会由实际 `ChatInlinePanelAppCard` 渲染 iframe，不是官网自行模拟的聊天组件。
- 现有产品截图脚本可在运行中的真实 NextClaw UI 上使用公开、确定性会话数据和本地 Panel App fixture；该路径适合生成可复现的公开宣传资产，不会碰用户真实会话或数据。
- Cloudflare Pages 可通过 `apps/landing/public/_headers` 为带版本名的静态媒体设置浏览器长期缓存。不能把会原地替换的同名资源全部设为 immutable，否则用户会长期看到旧图。
- 首页区块仍由 `landing-home-sections.utils.ts` 编排。本批不改变产品运行时、聊天协议或 Panel App 行为。

## 候选方案与选择

1. 独立官网滑块：视觉能动，但与产品脱节，放弃。
2. 真实产品静态截图：能证明位置，却看不出“改参数后同步变化”，只可作视频 poster，放弃作为主视觉。
3. 在真实聊天内录制内联工程 Panel App：既证明发生在产品里，也把“操作→图形、读数、结论联动”直接交给观看者，采用。

## 主链路与信息结构

首页区块置于主工作台展示之后：

1. 标题说明结果发生的位置：`让结果直接出现在对话里`。
2. `<video>` 主视觉播放真实 NextClaw 会话：用户提出结构校核请求，助手回复中出现“悬臂梁载荷评估”内联 Panel App。
3. 视频动作依次为：先展示默认计算状态；拖动“载荷”；再拖动“臂长/安全系数”。同一张卡片里的位移曲线、最大应力、安全裕度与结论同时变化。
4. 紧邻视频以两个短步骤说明路径：先在回复里直接操作；任务要持续使用时，将同一个结果展开到 Panel App 工作区。
5. 视频不可播放时，使用同一真实会话的 WebP poster；页面不提供第二套官网替身控件。

这让用户看到的是“我在 NextClaw 说一句，工具就出现在这条对话里，并且可以继续操作”，而不是“官网也做了一段图表特效”。

## 组件、资产与边界

- 新增公开、确定性的工程 Panel App fixture 与截图场景。fixture 使用原生 range 控件，有可访问标签和当前值；每个输入事件只更新这一个小工具内的曲线、指标和结论。
- 将这一场景运行在真实 NextClaw 聊天 renderer 中，截图流程产出 poster 与 WebM；视频源保留在 `images/marketing/`，发布副本进入 `apps/landing/public/`。
- landing 区块仅嵌入视频、poster 与语义化说明，使用原生 video controls；不会重新实现滑块、计算或会话 UI。
- 首屏关键截图改用构建产物中的带 hash WebP；新视频与 poster使用版本文件名，并由 `_headers` 设长缓存和 immutable。未版本化的旧资源维持短缓存，避免发布后展示陈旧内容。
- 中英文页面共用同一条公开中文会话视频；英文文案将其明确称为示例会话，避免把中文 UI 误写成英文界面。

## 功能地图与异常边界

| 场景 | 用户看到什么 | 动作/结果 | owner |
| --- | --- | --- | --- |
| 首页主视觉 | 真实 NextClaw 会话中的内联工程工具视频 | 载荷等参数改变，图、数字、结论同步变化 | Panel App fixture + 真实 chat renderer |
| 视频不可用 | 同一会话的 WebP poster 与说明 | 保持“发生在对话里”的理解 | landing 原生 video fallback |
| 想长期使用 | “展开为 Panel App”的说明 | 安装后在真实产品中继续操作 | 现有 Chat / Panel App |
| 首访 | 更小的 WebP 与压缩 WebM | 降低首屏及演示媒体字节数 | landing 资源构建 |
| 复访 | 带版本名媒体命中长期缓存 | 不重复下载同一媒体 | Cloudflare Pages headers |
| 窄屏 | 视频等比缩放、原生控件可用 | 不横向溢出 | landing CSS |

非目标：不把官网视频误称为可操作官网控件；不引入新的聊天协议或产品运行时功能；不把一次性 HTML 结果和长期 Panel App 混成第三个产品概念；不对会原地更新的旧图片设置永久缓存。

## 验收标准

- 视频中可同时识别用户请求、助手回复和消息内的工程 Panel App；视频里的 range 输入由实际 iframe 接收。
- 改动参数后，曲线、至少两个数值和安全结论在同一录屏片段内同步变化。
- landing 没有独立官网滑块、伪会话或其 controller；视频元素有 poster、文本说明与原生 controls。
- 1512px 与 390px 页面无横向溢出；视频在小屏保留可播放入口。
- 新媒体格式、体积和哈希可核对；线上响应对版本媒体有长期 immutable 缓存，HTML 保持可更新。
- landing 类型检查、生产构建、定向 UI 录制、浏览器检查和线上响应头检查通过。

`design-document: required`。`plan: not-required`：一个已有 landing owner 与一条既有真实 UI 截图链路；方案已收敛为新增可复现 fixture、录制资产与资产交付策略。
