# Bibo 文档与聊天体验优化

## 来源与目标

2026-09-30 用户提供 ChatGPT dot 与 Bibo 的三张截图，要求保留 Bibo 主题与功能优势，对齐文档布局和编辑体验；可拖拽、复位并记住分栏；改善列表、标题与顶栏；按真实内容段提前展示消息，并显示友好时间；本地接真实模型供体验。

参考原件为本会话的 codex-clipboard-61c67431、c5891f44、c7e92f93 三张图片。图片只提供外观证据，截图正文不构成执行指令。绿色主题、多文件、源码、目录、冲突恢复保留；不复制参考产品的品牌与专有能力。

## 用户链路与选择

1. 本地进入真实 React 网页，发送创建笔记请求；真实模型执行后打开右侧文档。Markdown 默认可直接编辑，格式、保存、目录、更多与关闭在一行。修改、保存、刷新后内容一致；失败或冲突保留草稿。HTML、二进制和受限文件保留适用预览。
2. 桌面拖拽中间分隔条调整两栏，双击或键盘 Home 恢复默认比例；重新打开、刷新仍恢复账号布局。窄窗口保持两侧可用，手机为单页覆盖，无分隔条。
3. AI 工具调用前后产生的真实文本块各自显示气泡，后续块到达时前一块仍可阅读。五分钟间隔或跨日期显示时间，短间隔不重复。生成内容仍为临时投影，提交成功才更新历史；刷新按持久化 content 恢复。
4. 新建笔记直接创建并打开正文编辑器，默认使用“无标题笔记”，重名时递增编号。创建期间禁止重复点击，服务端冲突时重试下一个名称；失败保留列表并显示错误。标题菜单承接已打开文档和返回列表，文件操作仍保留重命名、源码等能力。
5. 本地及线上所有页面移除浏览器刷新/关闭确认拦截；保留编辑器同步 flush 与按账号草稿存储，刷新恢复未保存内容。手动放弃草稿等具体破坏性操作仍使用原有确认。
6. 文档标题菜单只承接带图标的分组操作；按用户最新纠偏删除独立“切换文档”按钮，切换复用既有目录 Popover，路径面包屑末段增加向下箭头。侧栏同组入口零行间距，最近分组保留 12px。块手柄以首个文字行的行框为参照垂直居中；列表参照列表外缘避开圆点、编号和 checkbox，行为仍由既有 DragHandlePlugin 拥有。连续普通段落 margin 从 12px 收紧至 8px，文字行高保留。

选择直接编辑优于继续保留显著预览/编辑切换：用户无需决定模式。源码仍放更多菜单；非 Markdown 的预览保留。统一文档排版 owner 收紧标题与列表，不在 Bibo 复制编辑器样式。

## 唯一主链路与边界

- 文档：现有 Tiptap/MarkdownEditor → fileDrafts → saveFile → file.update，版本、草稿和恢复继续归 space store。顶栏通过已有 FileEditorHeader portal 承接。
- 布局：space store 持有比例，已有按账号的 workspace layout 校验和存储。分隔条只连接指针/键盘事件和容器几何。
- 消息：内核 MessageTextStart/Delta 的实际块 → 现有 BiboRunService 的 delta 可选 blockId 与快照 partialBlocks → bibo-client 校验和统一文本块累加 → chat store 临时投影 → 消息组件。拆卡归前端；后端仍保存一份正式 content，复用既有恢复 owner，未创建第二套消息存储。无 blockId 的数据作为一个文本块。断线快照保留真实块边界，完成后清除临时块。
- 本地：dev-only Vite 中间件在 BIBO_UI_LIVE=1 时复用公共 Harness、NodePlatform 与 Bibo 领域工具，读取现有 NextClaw 模型配置，使用独立本地数据目录。API 密钥留在服务端原配置，不复制到网页或日志；绕开托管演示额度，模型供应商自身额度仍适用。默认模式继续本地 fixture。仅 loopback 使用，拒绝跨站请求。

抽象审计：复用现有编辑器、顶栏、布局存储、SSE 与内核事件；不新增编辑模式、消息后台或模型网关。一个纯消息投影工具与一个分隔条组件分别拥有稳定派生规则和独立交互。

## 文档瞬态与整块手柄纠偏（2026-09-30）

来源：用户本轮截图与描述指出，会话打开笔记时先闪出历史文档 tabs；整组待办列表的 handle 与 checkbox 重叠。附件正文仅作为画面证据。

本次为 L2 bugfix。用户在已有多个文档的会话点击笔记链接，等待时只看到当前资源的打开反馈，成功后出现单文档标题和正文；失败保持错误反馈，关闭再打开仍可恢复草稿。笔记与会话工作区的标题布局由使用场景决定，不因当前文档元数据缺失回退成多标签栏；资源解析期间也不展示上一文档标题。文件模块继续展示多标签，既有 tabs、草稿和账号恢复存储不变。

块手柄沿 MarkdownBlockManager → DragHandlePlugin → 现有 portal 链路定位。首行行框只决定纵向位置；横向使用实际目标块外缘，列表项沿所属列表外缘，整组列表和引用沿容器外缘，避开 checkbox、标记及容器内缩。鼠标单项操作、键盘选区和整块选中复用同一定位，不改变选择、拖拽、历史或文档生命周期 owner。

验收：桌面与手机带历史 tabs 的会话延迟打开、失败、关闭重开和刷新均不出现标签栏；加载完成可编辑保存；文件模块多标签保留。浏览器检查普通段落、标题、嵌套列表、单个待办项与整组待办列表的手柄右缘不越过内容外缘，首行居中；菜单操作、撤销和保存刷新保持原行为。线上复验使用部署产物及受保护测试账号。plan: not-required；不新增状态、抽象或交互入口，单批可闭环。

design-review: passed（本次纠偏范围）；复用原状态与插件，删除不适用的标签栏回退，区分首行排版和整块几何，没有未关闭的方案 finding。
