# 会话定时任务卡片管理

## 迭代完成说明

- 根因：CronJob 已提供启用、立即运行和删除能力，但会话工作区只将任务投影为内容全文和删除入口，长提示词会撑开卡片，且管理能力没有对齐全局定时任务页。
- 确认方式：核对 CronJob API、全局任务列表与会话工作区渲染链路，确认缺口仅在会话侧 UI 投影和交互编排。
- 修复：会话任务卡片改为两行摘要与渐进展开；接入启用/暂停、立即运行、详情和删除，并由共享 action hook 统一确认、pending 状态和成功回调。

## 用户/产品视角的验收步骤

1. 打开一段已有会话定时任务的会话工作区，确认长任务内容默认最多显示两行。
2. 点击“查看任务详情”，确认可查看完整提示词、调度信息和执行状态。
3. 使用开关暂停或恢复任务，确认状态即时更新。
4. 从更多菜单执行“立即运行”与“删除”，确认暂停任务运行会二次确认，删除操作需要确认。
5. 断开或失败加载任务列表时，确认显示失败状态并可重试。

## 可维护性总结汇总

- 复用既有 CronJob mutation contract，将确认、pending 状态和成功回调收敛到共享 hook，避免会话卡片与全局配置页维护两套管理语义。
- 卡片采用“摘要 + 详情”边界，完整提示词不再占用默认工作区空间；没有引入新的服务、状态 store 或平行 API。
- 文件组织 preflight 与自动治理检查通过；没有触达受治理的 red-zone 文件。
