# v0.33.8 文档站稳定静态资源 CDN 刷新

## 迭代完成说明

- GitHub、官网与文档站的产品主图已统一为 NextClaw 工作台截图，旧钢琴 Panel App 展示已由阅读卡片替代。
- 全球文档站部署后立即命中新图，但国内文档站的稳定图片 URL 仍返回旧对象；同一路径增加查询参数后返回新图，证明 OSS 源站已更新，问题位于 CDN 缓存刷新范围。
- 根因是部署脚本只刷新 HTML 路由和 `release-manifest.json`，而 `product-screenshots/` 等稳定文件名资源使用一年缓存，却不在刷新清单内。
- CDN 刷新清单现在递归纳入全部非内容哈希产物，并继续排除 Vite 的 `/assets/` 内容哈希目录；HTML 同时保留路由别名和实际文件路径。
- 双域验证器对网络连接失败及明确的瞬时 HTTP 状态执行最多四次、每次间隔五秒的可观察重试；内容、commit、tree hash 或非瞬时 HTTP 错误仍立即失败。

## 测试/验证/验收方式

- 对刷新清单生成器执行 Node 语法检查和定向 ESLint。
- 使用真实文档构建产物生成刷新清单，确认总数低于 1000 条单请求上限，包含工作台主图与 `release-manifest.json`，且不包含 `/assets/` 内容哈希文件。
- 使用真实线上域名运行仓库双域验证器，确认同一 commit 与 tree hash；GitHub runner 网络重试会在日志中输出失败 URL、尝试次数和原因。
- 推送后由 GitHub Actions 完成全球 Cloudflare Pages、国内 OSS/CDN 部署及线上验证。
- 对比全球与国内文档站稳定主图 URL 的 SHA-256，并确认页面不再出现钢琴展示或相关文案。

## 发布/部署方式

本次修复随 `master` 推送自动触发文档站部署。官网主图已在前一提交完成 Cloudflare Pages 部署，本次不重复发布官网，也不涉及 runtime、desktop 或 NPM 发布。

## 用户/产品视角的验收步骤

1. 打开 GitHub README、NextClaw 官网中英文首页和文档站中英文首页，首屏应显示 NextClaw 工作台截图。
2. 打开产品展示区域，Panel App 示例应为中文阅读卡片，不应出现旧钢琴界面。
3. 分别访问全球与国内文档站，稳定主图 URL 应返回相同的新图片内容，不依赖查询参数绕过缓存。

## 可维护性总结汇总

- CDN 刷新范围仍由单一生成器拥有，没有新增平行部署路径或站点特例。
- 规则按产物缓存语义划分：内容哈希 `/assets/` 自然换 URL，其余稳定文件名产物显式刷新，后续新增公开静态目录会自动继承正确行为。
- 验证重试只覆盖无响应网络错误和 allowlist 中的瞬时 HTTP 状态，次数与间隔固定；协议、内容和发布身份不一致不会被 fallback 掩盖。
- 保留 1000 条单请求上限，产物增长超出部署合同会明确失败，不会静默漏刷。
- 本次仅修改部署脚本并新增迭代记录；主工作区的会话功能源码、changeset 与 `ui-dist` 并行改动均未纳入。

## NPM 包发布记录

本次不涉及 NPM 包发布，也不新增 changeset。
