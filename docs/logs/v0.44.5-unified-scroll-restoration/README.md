# v0.44.5 统一滚动位置恢复

## 迭代完成说明

为会话、工作区、Panel App、文档浏览器和常用列表页接入共享的内存滚动位置恢复能力。Markdown 文件预览的根因是：切出渲染预览时，React 会先将待卸载滚动节点重置为 `0`，旧清理逻辑随后用该值覆盖已保存的阅读位置。

通过把最近一次真实滚动事件的位置作为清理时的事实源，并以稳定的文件标签身份作为 Markdown 预览记录键，修复了“Markdown 渲染预览 → 源文件 → 渲染预览”和“Markdown A → Markdown B → Markdown A”两种返回路径。

## 测试/验证/验收方式

- 定向 Vitest：4 个测试文件、11 项测试通过，覆盖滚动管理器、通用 Hook、Panel App iframe Hook 和 Markdown 文件预览。
- `pnpm --filter @nextclaw/ui tsc` 通过。
- 定向 ESLint 与 `git diff --check` 通过。
- 在网页端实际验证两条 Markdown 返回路径；从 `3000px` 返回后，在 20ms、100ms、500ms、1000ms 采样均保持原位置。

## 用户/产品视角的验收步骤

1. 在会话工作区打开一个较长的 Markdown 文件预览并向下滚动。
2. 切到源文件标签后再切回预览，确认回到原阅读位置。
3. 打开另一个 Markdown 文件预览后返回第一个文件，确认原阅读位置保持不变。

共享 Hook 和有界内存管理器集中拥有保存与恢复语义，页面只声明自身的稳定恢复键和滚动节点；没有新增页面级重复实现。自动可维护性检查无错误，提示工作区预览和文档浏览器文件接近行数预算；本次未扩大这两个文件的职责，后续可沿检查建议继续拆分。
