# 会话独立输入草稿

## 迭代完成说明

- 聊天输入草稿现在按正式会话的 `sessionKey` 独立保存；从会话 A 切到会话 B 时不会串入 A 的内容，切回 A 后会恢复原草稿。
- 尚未创建的“新会话”使用唯一的固定草稿分区，不生成随机 key，也不把多个未创建草稿误建模成并行会话。
- 页面刷新后会从持久化草稿 owner 恢复输入内容、结构化输入节点、技能选择、附件和当前输入偏好。
- “新增 Agent”携带的创建提示词会作为一次明确的新会话草稿写入动作，因此即使新会话已有缓存，也会展示本次入口要求的提示词。
- 根因是输入状态原先只由会话区域组件内的单份 `useState` 持有：组件跨会话路由复用时所有会话共享同一份状态，刷新后该状态又会整体丢失。端到端检查确认正式会话虽有稳定 `sessionKey`，输入状态却没有使用它分区；本次修复将草稿状态收敛到按会话键索引的持久化 store，直接修复状态 owner 和身份模型。

## 用户/产品视角的验收步骤

1. 在会话 A 输入一段未发送内容，切换到会话 B，确认输入框为空或展示 B 自己已有的草稿。
2. 在会话 B 输入另一段内容，再切回会话 A，确认恢复 A 的内容；切回 B，确认恢复 B 的内容。
3. 进入“新会话”输入内容，再切换到任意正式会话并返回“新会话”，确认恢复这一个新会话草稿。
4. 刷新页面，确认当前会话输入草稿仍在。
5. 点击“新增 Agent”，确认进入新会话且输入框展示默认 Agent 创建提示词。
6. 发送成功后确认当前草稿清空；模拟发送失败时确认原草稿恢复。
