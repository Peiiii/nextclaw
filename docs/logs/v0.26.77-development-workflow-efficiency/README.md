# v0.26.77 开发流程效率治理

日期：2026-08-08

## 迭代完成说明

本轮重构 NextClaw 的默认开发流程规则，目标是在不降低正确性底线的前提下，减少重复读规则、重复验证、低信息量工具调用和无条件二次复核。

根因不是某一次任务“做得太认真”，而是多层规则长期叠加后，把原本应按风险选择的动作写成了普遍必做项：`AGENTS.md`、交付、干净实现、验证、可维护性 guard、主观 review 和迭代留痕分别重复约束同一阶段；硬性代码净增长门槛还可能驱动 AI 为了过线搜索无关删减点。规则越多，AI 每轮需要读取和执行的上下文越长，验证也越容易重复。

本轮完成：

- 将默认开发任务划分为 L0-L4 风险级别，验证强度跟随行为风险，而不是跟随固定清单。
- 将 TypeScript 类型检查保留为类型边界的硬要求；将包级 lint、治理 ratchet、运行冒烟和主观可维护性 review 改为条件触发。
- 纯视觉、文案和主观效果优先使用渲染检查与用户验收；交互、状态、数据和协议行为继续由 AI 提供自动化或运行证据。
- 将复杂 UI、runtime update 和 release 细则移入验证 skill 的延迟参考，普通任务不再预读。
- 删除普通修复和重构的强制“生产语义代码净增小于等于零”；必要且清晰的最小增长允许存在，显式零增长治理战役仍保留专门合同。
- 将首次治理 preflight 限定为新增、重命名、移动文件，或改变角色与目录边界的任务。
- 可维护性 guard 默认只跑一次；主观 review 只在 guard 告警、结构/owner/抽象变化、大范围改动或用户明确要求时运行。
- 将流程效率反思嵌入既有收尾，不新增独立仪式。AI 需要检查重复读取、重复验证、低信息量动作和可条件化的规则；只有可复用、反复发生或高影响的结论才持久化。
- 普通局部修复和同批次微调不再自动创建独立迭代记录。

以字节数近似衡量规则输入体积：高频流程规则包由约 110 KB 降至 48 KB，减少约 56%；包含条件复核、留痕与延迟参考的完整相关规则包由约 127 KB 降至 60 KB，减少约 53%。这不是模型实际 token 的精确换算，但能稳定反映默认上下文负担的下降。

## 测试/验证/验收方式

- `git diff --check`：验证 Markdown 与规则改动不存在空白错误。
- 校验所有改写 skill 的 frontmatter，以及验证 skill 新增延迟参考链接均可解析。
- `pnpm check:governance-backlog-ratchet`：验证治理基线没有因规则重构发生非预期回退。
- 人工一致性检查 `AGENTS.md`、`commands/commands.md` 与各流程 skill，确认默认路径、风险分级、条件 review 和留痕边界没有互相冲突。

本轮只修改 Markdown 指令与 skill，没有触达 TypeScript、运行链路或用户运行行为，因此 build、lint、tsc、单元测试和运行冒烟不适用。

## 用户/产品视角的验收步骤

1. 用一个纯文案或纯视觉微调任务观察 AI：应选择 L0/L1，不执行全套治理和运行冒烟。
2. 用一个局部交互修复观察 AI：应选择 L2，运行定向测试和必要类型检查，最终只重复一次关键验证。
3. 用一个跨包协议或运行链路改动观察 AI：应选择 L3，并保留类型、契约和贴近真实链路的证据。
4. 查看最终汇报：AI 应说明实际执行和跳过的验证，但不应为了展示完整性堆砌无信息量命令。
5. 查看收尾反思：只有发现可复用的流程问题时才提出规则优化，普通任务不新增单独的“token review”步骤。

## 可维护性总结汇总

- 本轮主要是删除、合并和条件化重复规则，没有新增平行流程 owner。
- 高频规则输入体积减少约 56%，完整相关规则包减少约 53%。
- 新增的三个参考文件只承载低频复杂场景，避免默认 skill 继续膨胀。
- 可维护性 guard 与主观 review 的职责已分开：guard 提供低成本客观信号，review 只处理需要判断的风险。
- 本轮属于大型治理重构，因此创建一次迭代记录；没有为过程中每个细小修正分别留痕。
