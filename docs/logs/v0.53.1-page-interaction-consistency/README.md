# 页面交互一致性与设置导航分组

## 迭代完成说明

本批统一共享资源操作菜单、整行反馈和设置导航。原问题来自普通路由被通用资源工具栏包裹、菜单布局命令抢占业务入口、页面导航绕过已有组件，以及各调用方覆盖状态样式。通过公共菜单调用链、真实 DOM、桌面/移动预览与回归测试确认。

移除普通设置空工具栏，更多动作回到业务操作末尾，页面/收件箱菜单纳入整行区域；侧栏页面复用导航组件。二级菜单采用保留父菜单的级联，复用单一模型、渲染与浮层样式，支持键盘和边缘避让。设置按基础配置、常用设置、安全与隐私、系统与扩展四组组织；模型、提供商、渠道保留最前。中文 Extensions 改为扩展。

交互质量基线及共享组件、skill、失败路径回归的约束合并到原 owner。详细方案见 ../../designs/2026-09-13-page-action-hierarchy.design.md。

## 测试/验证/验收方式

UI 类型检查、定向 ESLint、共享菜单及消费者回归、设置桌面与移动导航测试；真实预览检查菜单父子同时可见、焦点退层、右侧翻转、390 像素宽度避让，以及四组导航顺序。规则渐进加载、diff-only 可维护性和新增代码治理检查适用于本批。

## 发布/部署方式

用户授权本批提交、合入 master 并推送 origin/master；随后运行主线协调器确认本地镜像同步。未请求产品版本发布或部署，UI patch changeset 留待后续版本发布。

## 用户/产品视角的验收步骤

1. 打开设置，依次看到基础配置、常用设置、安全与隐私、系统与扩展；前三项为模型、提供商、渠道。
2. 在页面或会话菜单打开布局与位置，父菜单保留，子菜单侧向展开；Escape 仅退出当前层。
3. 检查侧栏页面整行反馈，更多按钮不独占一行、不位于反馈区域外。
4. 在窄屏打开设置与菜单，入口可达且布局操作不被裁切。

## 可维护性总结汇总

复用既有导航与 ContextMenu owner，删除 CurrentPageActions 和父菜单替换式实现。分组定义是唯一事实源，平铺导航由分组派生。未新增依赖或平行交互 skill；子菜单文件留在既有菜单目录。已有文件接近预算的告警保留，未为压行数扩大重构；最终检查结果见提交前验证记录。
