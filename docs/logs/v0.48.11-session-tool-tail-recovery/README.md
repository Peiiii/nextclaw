# 会话刷新后重复工具消息修复

## 迭代完成说明

实现、代码验证与真实实例复验完成，本批提交用于主干集成。根因：journal replay 将中途 assistant 快照误转为 final，后续工具开始被过滤，结果却经 fallback 合成新 assistant；增量投影将错误消息保留下来。真实 journal 增量恢复精确复现三个重复结果，完整重放复现七个；保留真实状态的判别实验消除了两者。

修复保留 draft 状态，在原有消息 upsert owner 中恢复活动快照，按已证明工具归属处理恢复事件；迟到结果需要旧消息时重读同一 journal 前缀，未知事件不制造消息。投影升级至版本 8，旧派生记录从原 journal 重建。详见[设计与验收契约](../../designs/2026-09-08-session-tool-tail-recovery.design.md)。

## 测试/验证/验收方式

已完成修前真实页面、API、journal 取证及精确分段复现。kernel 46 项相关测试、toolkit 55 项测试及两个包 tsc 通过。正式回归比较六轮、九次工具调用的 live、增量和完整恢复；覆盖取消/失败/结束后的迟到工具、已知旧工具的结果、旧投影重建及原始 journal 不变。原始现场日志 9419 个事件、9 个保存边界逐项对照通过：两条消息，正文/思考/九个工具结果及运行耗时完整。targeted ESLint 无错误，维护性检查无阻塞项，治理和 ratchet 通过；原有长测试文件的预算告警未恶化。

## 发布/部署方式

真实 18792 服务已加载修复，5318 入口保持不变。用户两个原会话分别恢复为两条、六条正常消息，原 journal 哈希不变。正常新会话经过三次请求、六次工具调用，运行中刷新继续同一请求，结束后刷新六条消息全量哈希不变；浏览器显示三条已完成回复，无额外工具行或等待状态。

用户授权验证通过后合入 origin/master。本任务不包含 NPM 发布。用户明确更正规范：任务所需的现有实例重启无需另行许可，重启前说明影响并检查运行状态；已同步 AGENTS.md 与实现阶段规则。

## 用户/产品视角的验收步骤

1. 在加载修复版本的真实产品中，打开原会话并刷新。
2. 确认完整回复仍在，末尾没有额外的工具消息或等待动画。
3. 在正常会话发起多轮工具请求，运行中刷新一次、结束后再刷新，确认工具与正文归属同一回复。

## 可维护性总结汇总

复用已有 state manager 和 journal replay，不增加另一套协议或前端过滤。将投影 tail 读取及历史归属恢复内聚到独立 store 文件，避免继续扩大已达预算的投影持久化文件；活动快照归入既有 upsert 工具函数。
