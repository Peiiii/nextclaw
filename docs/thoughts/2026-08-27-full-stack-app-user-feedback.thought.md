## 原始反馈

> 1. mcp 没有配置功能 2. 重点是应用，应用打包测试容易直接应用模块容易直接崩溃 3. 对话不停的慢输出 4. 应用这块其实非常好，但是太轻量化啦，我尝试使用 fastapi+sqlite + 前端应用走 mcp能跑起来，说明具备啦可行性，但是打包应用存在问题。 应用这块是个大创新，但是不能局限于轻量级，要实现可以开发重量级的东西，替代部分的桌面软件。 至少保证 后端+sqllie+ vue/react 应用的打包发布

> @WP

> @WP 我跟公司的业务负责人聊过，很多普通人员有很多这种轻-中量级的应用需求，这些应用其实有很多开源的替代品，但是你让他们自己去部署，简直是无解，他们自己手工安装一个技能都费劲，所以你的应用傻瓜式安装，让用户使用应用简单化。但是太轻量又不行，要能实现稍微复杂一点的后端，能做一个比如营销有关的应用，有自己的数据库，你现在通过 MCP 的方式还行，就是在应用的复杂度能力这块需要更强一点，比如支持 vue/react dist 打包后的使用，后端通过 sqlite + 后端的方式，最终实现用户线上直接点击安装就能使用。

> 还有你既然做啦线上，那就要支持团队化，团队内共享技能，agent 应用等等，这个在企业内痛点挺大。

## 最小索引

- MCP：缺少可感知的配置能力。
- 应用可靠性：打包、测试与运行时崩溃问题。
- 对话体验：持续慢输出。
- 应用复杂度：希望支持后端、SQLite、Vue/React 构建产物，以及可替代部分桌面软件的轻—中量级业务应用。
- 安装体验：普通业务人员可直接点击安装并使用，无需自行部署或手动安装技能。
- 团队能力：共享技能、Agent 与应用。
