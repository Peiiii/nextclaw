### 必须不发生

- 不能用另一套 Bibo 专用 Agent、丢失长期上下文或关闭现有文件能力换取零容器与速度。
- 不能把一次请求失败、取消或断线后的半成品当作已提交消息/文件；不能从过时快照回滚覆盖新状态。
- 不能把测试环境的一次成功、定价估算或代码已部署称为生产效果证明。

### 架构不变量

- 对话语义、事件和模型输入的 owner 在 NextClaw 公共内核；宿主只提供存储、网络、进程和可用工具能力。NextClaw Node 宿主本身消费同一合同。
- 每位用户的会话和文件事实只有一个持久权威与明确版本；并发读不抢占发送消息的排他状态，写入有版本/幂等约束。
- Bibo 不决定 NextClaw 的通用类型、扩展语义或其它宿主生命周期。

### 代表性场景

1. 新用户首次聊天；老用户间隔一小时后续聊、同一会话长上下文续聊、重复点击与刷新重试。
2. 对话创建/修改/展示 Bibo 文件，随后刷新、跨实例读取；失败或取消时检查可见状态。
3. 同时读取个人空间与发送消息，以及两个用户交错运行；不出现假忙、串数据或重复事件。
4. 现有 NextClaw 用户升级后启动本地实例，完成会话、工具、扩展和持久状态恢复。
5. 生产小流量切换、旧状态导入、回滚演练和监控；逐类量化冷/热首字及平台用量。

### 交付边界

用户已授权提交、推送、主干集成、生产部署及必要发布。交付覆盖 Bibo 线上和受影响的 NextClaw 安装/升级，不以原型或设计文档收尾。用户创建的长期 HTTP 服务是此前讨论中的独立未来产品能力；本次需保证通用架构可容纳，现有 Bibo 尚未承诺该功能。

### 阶段安排

一个整体交付阶段。设计、纵向原型、迁移、实现、灰度和发布按依赖排序；任何局部完成都不关闭整体合同。边缘方案若实测达不到上述结果，先回设计；共享 Node/按需池是有条件备选，不能悄悄改掉 BE-01 的已确认目标。

### 当前阶段门

- 结果：边缘架构与全部旧账号迁移已经生产落地；已采样旧会话、尾延时和包发布取得对应证据，整体结果仍待 BE-01 按需 OS 路径验收。
- 保持项：BE-03、BE-04、BE-05 的旧用户和 NextClaw 通用性不变量。
- 场景：已采样的新旧聊天、文件、错误、并发和 Node 升级路径之外，补一条用户请求独立 OS 能力→安全分流→按需启动→结果回到同一会话的端到端路径；触发能力与权限边界先在设计中定清。
- 本阶段不做：不会把临时缓解或原型当作整体完成；所有 BE 项保持本次交付范围。
- 待关闭缺口：BE-01 的按需 OS 执行器路径没有实现；需明确产品能力和安全隔离合同，完成真实工具触发、容器按需启动、状态/成本/体验验证后重新验收。跨时段尾部波动、历史偶发保存错误及完整账单仍按已披露限制继续观察。
