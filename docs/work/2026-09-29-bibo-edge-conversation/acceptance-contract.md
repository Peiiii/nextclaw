### 必须不发生

- 不能用另一套 Bibo 专用 Agent、丢失长期上下文或关闭现有文件能力换取零容器与速度。
- 不能把一次请求失败、取消或断线后的半成品当作已提交消息/文件；不能从过时快照回滚覆盖新状态。
- 不能把测试环境的一次成功、定价估算或代码已部署称为生产效果证明。
- 不能把旧 Bibo 未开放 OS 能力、边缘平台限制或“未来可扩展”当成本轮已承诺任务的豁免；不能用工具数量、方案文字或单次纯聊天冒充真实任务完成。
- 不能把旧 `conversationMode`/legacy Harness 保留为最终产品的另一条对话链路，也不能把永久双写、整包压缩快照或旧容器回退当作正常工具路由；上线前备份只承担有限恢复用途。

### 架构不变量

- 对话语义、事件和模型输入的 owner 在 NextClaw 公共内核；宿主提供存储、网络、进程及适合自身环境的工具实现。NextClaw Node 宿主消费适用的同一上层合同，不要求与 Bibo 共用每段工具源码。
- 每位用户的会话和文件事实只有一个持久权威与明确版本；并发读不抢占发送消息的排他状态，写入有版本/幂等约束。
- Bibo 不决定 NextClaw 的通用类型、扩展语义或其它宿主生命周期。能力授权、调用结果语义与对话状态转移由同一 NextClaw 公共基座拥有；Node 和 Bibo 可装配不同的适用工具与宿主端口，不各自复制 Agent 主链路。下层不得导入或识别 Bibo。

### 代表性场景

1. 新用户首次聊天；老用户间隔一小时后续聊、同一会话长上下文续聊、重复点击与刷新重试。
2. 对话创建/修改/展示 Bibo 文件，随后刷新、跨实例读取；失败或取消时检查可见状态。
3. 同时读取个人空间与发送消息，以及两个用户交错运行；不出现假忙、串数据或重复事件。
4. 现有 NextClaw 用户升级后启动本地实例，完成会话、工具、扩展和持久状态恢复。
5. 同一会话内先读文件（容器调用 0）、由 Agent 按需取得 OS 并挂载所需目录、在挂载路径执行命令、再直接读该命令写入的文件（无需再次唤醒，也没有保存工具）。验证基本成功/失败/取消与回收后的持久文件读取，核对上下文、隔离、结果、容器计数及 BE-13 延时；完整扩展模块及多 OS 生命周期另行评估。
6. 生产小流量切换、旧状态导入、回滚演练和监控；逐类量化冷/热首字及平台用量。
7. 以小文件、跨 1 MiB 文件、100 MiB 文本与二进制文件验证同一工作区的直达读取、执行器写入和再读取；记录实际内存、响应时间、重启恢复与失败清理，不以模型单次输出 50 KiB 的分页上限冒充存储上限。
