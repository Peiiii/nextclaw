# 开发执行 Plan 合同

仅当 Design 已冻结，且任务无法在单批中可信闭环时读取。Plan 是大型任务的跨批执行合同，不是第八个 lifecycle phase。

## 触发门

任务需要多个存在依赖或交付顺序的执行部分，并且跨 owner、跨会话/交接、部分完成恢复或分批验证中的任一项使单批闭环不可信时，写入或更新 `docs/plans/YYYY-MM-DD-<topic>.plan.md`。Feature、bugfix、文件数、预计工时或 Token 单项都不是充分理由；单批可闭环时不创建 plan。

## 必备内容

- 链接上位设计，声明目标、范围和非目标；
- 按依赖顺序列出执行部分，以及每部分的 owner、输入和交付结果；
- 为每部分定义验证、Review 和必要交付边界；
- 写清中断、部分完成和跨会话继续时的恢复入口；
- 为每部分选择一种设计策略：复用上位设计、轻量内联设计、实现前新增或更新稳定设计文档，或满足指定触发条件后返回 Design 决策。

## 细化设计门

某部分跨越新的状态 owner、协议、持久化、兼容/迁移/fallback、用户工作流或真实方案分叉时，默认在该部分开始前新增或更新设计文档。上位设计已完整覆盖且没有新分叉时，不重复拆文档。当前证据不足时只记录触发条件，不在总计划里虚构细节。

## 执行与返工

Implementation 只执行当前部分，并在首次编辑前读取其设计策略。要求细化设计但文档缺失，或条件式策略已经触发时，返回 Design。执行中新证据改变上位合同，先更新 design，再同步 plan；不得只改步骤掩盖设计变化。

Plan 不复制上位架构、协议或状态合同：design 回答“采用什么结构”，plan 回答“按什么顺序交付”。
