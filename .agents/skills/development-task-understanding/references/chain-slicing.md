# 长链路调试

用于把多 hop 故障从“全链路盲跑”收敛为第一个违约边界。输出固定为：症状、黄金复现、链路地图、观察点、当前假设、根因 owner、同链路验收。

## 方法

1. **冻结症状**：用可观察信号写清实际行为、预期行为和失败判据。
2. **选择复现层级**：优先同入口真实复现；成本过高时依次选择边界回放、命中错误 hop 的最小测试、已有 trace/journal/artifact。不能因端到端昂贵而直接猜修复；记录替代基线和成本判断。
3. **画合同链路**：写成 `入口 -> 归一化 -> owner/state -> transport/runtime -> consumer`，每个 hop 只记录收到什么、承诺输出什么。
4. **链路二分**：先选最能缩小搜索空间的边界，判断错误发生在它之前还是之后，避免从头线性猜。
5. **布置最少探针**：只在边界记录 `correlation/session/run/message id`、hop、输入输出摘要、状态变化、分支、耗时与重试。探针应结构化、可对比、可删除，避免正文和叙事日志。
6. **单假设实验**：写成“若 X 是根因，则 Y 边界应出现 Z”。昂贵环境可在一次运行放多个互斥探针，但每个探针必须有独立信号和结论。
7. **定位第一个错误 hop**：最后报错点不是根因；第一份违反合同的输出决定下一步 owner。
8. **在 owner 上修复**：优先修合同映射、状态所有权、事件顺序或 source of truth，不在渲染层和下游追加掩盖分支。
9. **同链路复验**：复用修前入口、输入、配置和指标。证据优先级为真实链路、贴近真实的 smoke、最小替代验证。

## 一次真实事件定位

用户能稳定触发一次输入时，先让同一 trace 贯通完整候选链路，再请求触发：外部入口、扩展提交、ingress、队列、路由、run、事件流和出站发送。逐 hop 比较计数；从一次变成两次或从有值变成丢失的第一个边界就是缩圈点。只有观察点无法提前覆盖或会改变问题本身时，才分轮请求用户复现。

普通症状与附加前提必须分别证明。压缩、继承、特定工具、消息类型或 runtime 只有在真实失败链路中出现，才能进入根因；特殊场景失败不能自动解释普通场景。

## NextClaw 校准

需要复现时固定隔离的 `NEXTCLAW_HOME`、session、project root、provider/model/runtime 和 skill 集。常用对照：

- 流式：第一个错误事件、事件顺序、首次字段丢失；
- UI 状态：server truth、persisted truth、rendered truth；
- 配置：加载快照与保存快照；
- prompt/skill：可用 skill 快照与实际请求选择。

跨轮且有上下文压缩风险时才把事实、证据、排除项和下一步写入工作笔记。

## 完成条件

- 有可验证症状和修前基线，或有明确的替代证据；
- 找到第一个错误 hop 并给出证据，不以概率猜测代替；
- 修复落在正确 owner；
- 用同链路复验，或明确未验证缺口。
