# 分层根因分析

在直接证据已经足够时，把“哪里坏了”追到“为什么系统允许它发生和扩散”。证据不足时先回到调查或长链路调试，不把推断包装成根因。

## 五层模型

1. **现象层**：用户看见什么，哪个信号证明失败。
2. **直接触发层**：哪个输入、状态、事件或分支触发失败。
3. **生成路径层**：坏状态怎样被写入、生成和传播。
4. **防线缺口层**：哪个合同、校验、原子性、隔离、恢复、错误表达或测试缺口允许影响扩大。
5. **系统/产品层**：暴露了什么长期架构、资产韧性、用户体验、自感知、自恢复或治理缺口。

不要求每次五层都有问题，但至少追到生成路径或防线缺口。每层说明它解释了什么、尚未解释什么，并标注“已证实 / 高概率 / 待验证”。

涉及长期用户资产、自动化任务、会话历史、配置或发布物时，额外检查读取端韧性和恢复路径。`try/catch`、坏数据清理或提示重试只能算局部恢复，不能自动成为长期修复。

## 输出

按 `现象 -> 直接触发 -> 生成路径 -> 防线缺口 -> 系统性原因 -> 最小恢复 -> 长期修复 -> 机制沉淀` 给出结论；明确真正 owner。只有教训可复用、反复或高影响时，才进入规则、测试或自动化沉淀。

完成要求：直接触发明确；至少证实生成路径或防线缺口之一；短期恢复与长期修复分开；owner 与待验证边界明确。
