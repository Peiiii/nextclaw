# 主观可维护性复核

只回答触发原因相关的问题：

1. 是否仍有可直接删除或复用的重复路径？
2. 新抽象是否减少真实复杂度，还是增加名字、文件和跳转？
3. owner、状态、生命周期和文件边界是否更清楚？
4. 复杂度是否被移到 helper、wrapper、兼容层或统计范围之外？
5. 更小方案是否只缩小 diff，却保留双 owner、错误边界或迁移债？
6. 更大方案是否有当前消费者、已知变化轴或高迁移成本证据？

防止过度设计不等于最小改动或 MVP；比较过小与过大两端，按全生命周期净复杂度选平衡点。必要的结构性增长可以通过；只有显式零增长合同才要求非测试净增 `<= 0`。使用 findings-first 短格式：结论、触发原因、发现、修正方向。
