# 复杂 UI 验证

仅在主验证流程明确路由到本文件时读取。普通样式、颜色、间距、文案和静态布局不使用这里的重验证合同。

## 真实表面

- 用户点名具体入口、URL、端口或控件时，只在该表面验收；相邻页面、另一个弹层或同名列表不能代替。
- 运行实例必须消费当前源码或最新产物。组件测试、静态检查和旧实例截图不能证明当前页面已生效。
- 若开发服务回退到其它端口，不能把回退端口当成用户报告端口的证明。

## 外部视觉复刻

对齐指定仓库、主题或视觉集合时，固定源版本并逐项核对名称、素材、高辨识度元素和遗漏。只有人物、品牌图形或核心交互被用户明确接受为抽象替代时才算通过。普通原创样式调整不需要 fidelity matrix。

## 列表与瞬态行为

- 分页、懒加载问题要走到终态，观察 hasMore、最终数量、末页和错误状态。
- 虚拟列表、动态高度或滚动闪烁要覆盖与根因相关的瞬态，例如首次进入、普通/大跨度滚动、分页前插、内容展开；只覆盖真正受影响的场景，不机械执行完整矩阵。
- 瞬态问题不能只用最终静态截图证明，应使用连续观察、DOM 指标或能复现同一时序的测试。

## 编辑器、IME 与选区

这类修复需要在最终 consumer 覆盖相关 beforeinput/input/composition 顺序，并直接断言正文 DOM 身份、文本与 caret。若根因只涉及其中一种事件或平台，只验证对应路径，不扩成无关平台全矩阵。

## 结构化输入与附件

- mention、附件、文件、技能或项目输入涉及语义传递时，至少覆盖“语义节点 → outgoing parts/metadata → 持久化展示”；应进入 Agent 上下文时，断言真实 send envelope。
- 涉及点击消费时，再覆盖“持久化 token → 点击 → 目标 owner/action”。只改视觉展示时不加载这条消费闭环。
- 入口渲染、发送语义和点击消费是三种不同风险；只验证本次触达的风险，不默认三套全跑。

## 验收输出

记录精确入口、主要操作、观察指标和结果。用户只负责主观审美确认，技术交互正确性仍由 AI 验证。
