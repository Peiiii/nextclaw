# 版本传播图质量门

用于 stable/major 版本的 release review 配图。它只审版本传播图，不影响普通产品截图刷新。

## 先证明这是 NextClaw

- 先做“去标题识别”：遮住版本号、标题和说明后，画面仍应凭真实产品壳、NextClaw 品牌资产或本次功能状态，让目标用户认出这是 NextClaw 及其相关任务。
- 只靠后加文字建立关联的通用 3D 静物、抽象网络、机器人、办公桌或任意 SaaS 都能套用的画面直接淘汰。
- 抽象概念视觉只能承担氛围或辅图，不能单独作为版本主图。主图至少包含一个占据主要视觉权重的真实 NextClaw 界面或经核验的品牌资产；组合图不能把界面缩成装饰，也不能用 AI 生成或改写产品 UI。

## 去重与选图

1. 读取最近 5 个 stable minor 的 `docs/releases/*.release-review.json`，打开其中的 `imagePath` 与本次候选图。
2. 相同路径、相同主体截图、只换裁切/边框/标题的变体都视为重复并默认淘汰。只有用户明确要求延续同一 campaign，或该界面是唯一事实证据且新截图能证明新状态时才可复用，并记录理由。
3. 先写一句本版本独有的视觉命题，再选证据和形式。禁止因为旧图已存在、尺寸合适或能通过 schema 就拿来凑字段；没有匹配素材时重新截取真实界面，或制作带真实产品主锚点的版本摘要图。

## 六维验收

逐项按 5 分制写出具体缺陷：

1. NextClaw/功能可识别性；
2. 与本次主结论的相关性；
3. 相对近期版本的辨识度；
4. 视觉焦点与信息层级；
5. 细节完成度；
6. 社交缩略图下的可读性。

可识别性低于 4 分直接淘汰；其余任一项低于 4 分必须迭代，低于 3 分直接淘汰，不能用平均分掩盖短板。最终图至少经过一次打开检查和一次针对最低分维度的定向迭代。报告对比过的近期图片、淘汰原因和最终评分；草稿、默认模板、通用截图或未经检查的生成结果不得绑定 release review。
