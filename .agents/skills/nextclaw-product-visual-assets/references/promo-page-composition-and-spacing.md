# 宣传页构图与留白合同

## 适用边界

本合同只约束 Promo Page Studio 的宣传页面和传播卡片，不替代 NextClaw 产品 UI 的设计系统。目标不是让所有页面长得一样，而是避免文字、截图和空白区域失去比例。

## 开放设计依据

- [Carbon 2x Grid](https://carbondesignsystem.com/elements/2x-grid/overview/)：以 8px mini unit 建立网格、固定间距和视觉节奏，并优先使用 1:1、2:1、3:2、4:3、16:9 等稳定比例。
- [Carbon Spacing](https://carbondesignsystem.com/elements/spacing/overview/)：用离散 spacing token 代替任意数值，区分组件内部空间与布局空间。
- [GitLab Pajamas Spacing](https://design.gitlab.com/product-foundations/spacing/)：8px 分隔相关元素，16px 分隔不同元素，24px 分隔子区块，32px 分隔大区块。
- [GitLab Pajamas Layout](https://gitlab-renovate-forks.gitlab.io/design.gitlab.com/product-foundations/layout/)：响应式重排后仍保持信息层级、顺序和关系。
- [USWDS Design Tokens](https://designsystem.digital.gov/design-tokens/) 与 [Typography](https://designsystem.digital.gov/components/typography/)：用有限 token 控制字体、行高和间距，避免连续任意值造成视觉漂移。

下面的百分比预算是 NextClaw 宣传卡片基于这些原则形成的本地规则，不是上述系统的原文规定。

## 默认几何

- 页面使用 8px 基准；允许的主要间距为 8、16、24、32、48、64、80、96px。微型描边或图标内部可用 2、4、12px。
- 同一传播组默认使用 1:1 卡片和 24px gutter，保证卡片节奏稳定；只有内容天然需要横向叙事时才整组切换 2:1 或 16:9，不能单张随意变形。
- 卡片安全区为宽高的 5–7%；核心文字、品牌和截图圆角不能穿出安全区。氛围纹理可以延伸到边缘。
- 所有标题、正文、截图边缘至少共享一组可见 key line；不要让每个对象拥有不同的随机左边界。

## 方形卡片的面积预算

以实际可见面积估算，不追求像素级数学精确：

| 区域 | 建议范围 | 阻断信号 |
|---|---:|---|
| 标题 + 正文 | 22–34% | 超过 40%，页面像海报文案而不是产品视觉 |
| 产品截图 | 38–55% | 低于 32% 时事实对象通常不可辨；高于 62% 时氛围和留白消失 |
| 主动留白 | 18–30% | 低于 14% 显得拥挤；高于 38% 且没有构图意图则显得空洞 |
| 品牌、标签、装饰 | 4–10% | 与标题或截图争夺第一视觉焦点 |

“主动留白”是帮助视线移动、区分层级或显露背景材质的空间，不是因为元素没放满而剩下的洞。

## 文字预算

- 每张卡只保留一个主判断。中文标题默认 8–22 个可见字符，最多三行；英文标题以三行内读完为准。
- 需要锁定中文语义换行时，在 brief 的 `cards[].title` 中用换行符分行；渲染器把每段变成不可再次拆开的语义行，并阻断单行超过 12 个可见字符。不要只依赖浏览器自动换行。
- 正文默认 18–52 个中文可见字符，最多三行；正文只解释标题与截图的关系，不重复标题。
- 标题与正文之间用一个小层级间距，正文与截图之间至少用一个大层级间距。相关文字靠近，事实截图与装饰保持距离。
- 标题是第一焦点时，截图应成为第二焦点；截图是第一焦点时，标题降级为短标签。禁止两个同等巨大的焦点互相竞争。
- 字号必须与文本量联动：字多先删文案，其次降一档字号；不能持续缩小到无法阅读。

## 截图作为卡片

- 截图自身使用 14–20px 圆角、1px 低对比描边和单层柔和阴影；不得再包一个带标题栏的大白框，除非真实产品窗口边界就是传播对象。
- 完整截图维持源图比例；卡片围绕截图留空间，不把截图拉伸去填任意容器。
- 截图可以与文字纸片轻微叠压以建立前后关系，但完整边界不得被卡片边缘、纸片或装饰遮挡。
- 细节标签贴在截图内部边缘或紧邻截图，不单独占据一条厚工具栏。
- 多图拼接需要共同基线、等圆角和等阴影。`sequence` 体现时间/操作顺序；`overview-with-details` 体现总览与细节，不做无语义拼贴。

## 布局角色

- `hero-window`：文字约占上方 28–34%，完整截图悬浮于下方，截图是第二焦点。
- `evidence-board`：标题更短，标签位于文字与截图之间；截图占下方约 45–52%。
- `editorial`：文字纸片占左侧约 46–54%，截图卡片在右下建立叠层；二者均保留完整边界。
- `full-bleed`：只承载概念表达，主要价值来自主动留白和背景构图；不放事实截图。

## 两轮验收

1. **缩略图验收**：把整页缩到宽 360–420px。仍应一眼识别每张卡的标题、产品截图和焦点顺序；如果只剩背景和大字，截图太小。
2. **实际尺寸验收**：以最终传播宽度检查标题行数、截图完整边界和关键对象可读性。桌面好看但窄屏失去层级，或窄屏拥挤，都必须重新分配比例，而不是只缩放整张卡。

任何预算都可以因明确艺术意图偏离，但 brief 的 `designNote` 必须说明偏离解决了什么问题；“看起来更丰富”不算理由。

## 五星挑刺法

“五星”不是五星好评，而是每个可独立感知的视觉模块固定挑出五个有证据的问题。用户说“挑毛病”“按之前的方法审”“五星挑刺法”或“每个模块挑五个问题”时召回本节。

### 审稿单位

- 先按真实页面结构切分：开场、每张传播卡、渠道预览、证据/说明区、结尾；另加一次整页模块关系审查。
- 必须按实际桌面像素和 360–420px 窄屏分别观察；不能只看整页缩略图。
- 每个模块列五个互不重复的问题。问题必须指出可观察对象、失衡关系和用户影响，不能用“感觉一般”“还可优化”凑数。
- 审美审查之前先做内容审查：逐模块回答“它承担什么叙事任务、比上一模块新增什么信息、用户看完记住什么、由什么证据或解释支撑”。背景、纹理、装饰、留白和一句泛化口号都不算信息增量。

### 内容成立性门槛

内容是宣传视觉的主体，图片背景只是增强美感与氛围。每个模块必须先满足：

1. 有明确的叙事任务，不是为了凑数量或填版面存在。
2. 至少提供一项具体信息、场景、机制、结果或可信主张；不能只有可替换到任何产品上的口号。
3. 信息密度与占用面积匹配：只有一句话时应收缩为转场、居中结论或合并到相邻模块，不能占据完整大卡。
4. 需要证明产品行为的主张必须有真实证据；愿景或总结可以无截图，但必须对前文完成提炼或推进。
5. 背景只能支持内容的情绪、层级和阅读，不能因为背景漂亮就判定模块成立。

任一模块无法回答前两项时，内容成立性直接记 `9–10` 分并判定不通过；先删、合并或重写内容，不进入换背景、调圆角、加装饰等视觉优化。

### 构图和谐性门槛

布局原型的定义与选择由[宣传页区块布局原型目录](promo-page-layout-archetypes.md)负责；本节只负责检验选定原型是否在实际像素中成立。

内容成立后，优先选择经过长期验证的稳定构图；对称不是唯一答案，但视觉重量必须平衡。没有明确巧思时，不要为了显得“有设计”随意错位。

默认从以下经典骨架中选择：

- **居中堆叠**：单一结论、总结或转场居中，文字和辅助信息共享中心轴。
- **稳定双栏**：文字与证据按约 `40/60` 或 `50/50` 分栏，共享垂直中心、顶部线或底部线。
- **主次叠放**：只有在主对象、锚点和遮挡关系清楚时使用；重叠必须强化因果或层级，不能只是填空。

使用非对称构图时，brief 的 `designNote` 必须说明它的视觉巧思，并同时满足：

1. 至少两个可见对齐锚点，例如共同中心线、基线、边线或固定间距。
2. 主体面积、明暗对比和信息密度形成可解释的视觉重量平衡；不能让标题、截图、标签和背景装饰全部压向同一象限。
3. 留白形成完整而有方向的形状，能够把视线引向主体；随机剩下的大片空白不算主动留白。
4. 截图有明确承托关系，不悬浮在随机坐标，也不与卡片边缘形成似贴非贴的偶然切边。
5. 锐利 UI 与柔软背景之间有圆角、边界、尺度或层级过渡，不能像把另一张图直接贴上去。

执行三项快速检查：缩到缩略图做“眯眼测试”，确认第一眼重量中心；按四象限估算“面积 × 对比 × 密度”，确认没有单侧坠重；隐藏背景再看前景，若布局立即显得散乱，说明背景在替构图兜底。无法识别经典骨架、又说不清非对称巧思的模块，构图记 `7–8` 分并回到经典骨架。

### 八个观察维度

1. **内容**：模块为什么存在、呈现什么具体信息、用户看完得到什么、是否有信息增量与相称证据。这是第一优先级。
2. **构图**：模块采用什么稳定骨架；视觉重量、对齐锚点、留白形状和非对称意图是否成立。
3. **层级**：第一、第二焦点是否明确，标题、截图和装饰是否争抢注意力。
4. **主体**：截图完整之外，claim 对应对象能否在缩略尺寸下一眼找到。
5. **文字**：语义断行、行数、字重、对比度、长度和字体角色是否协调；中文词组不得被强制拆开。
6. **空间**：留白是否引导视线并建立节奏，还是无意义空洞；安全区、基线和间距是否一致。
7. **风格**：圆角、阴影、材质、标签和说明区是否属于同一视觉世界。
8. **序列**：相邻模块是否有推进、变化与收束，还是重复同一背景和构图。

### 评分与排序

- `9–10`：破坏核心理解或品质感，必须先修。
- `7–8`：明显影响传播和构图，当前轮应修。
- `4–6`：完成度问题，在高分问题解决后处理。
- `1–3`：偏好或微调，不得挤占结构问题优先级。

每个模块内部先列内容问题，再按严重度排序并计算平均“问题指数”；随后把全部问题合并，给出全局前十。全局排序同分时，内容成立性优先于视觉完成度。相同根因造成的多个症状要归并为一个修复方向，不能通过修十处 CSS 掩盖一个错误内容或布局。

### 分数冻结与变化举证

- 分数是绝对严重度，不是“比上一版好多少”的相对评价；修完后不能因为投入了工作就自动降分。
- 对同一模块保留上一轮问题和分数。模块的素材、文案、几何结构或视觉关系没有发生可见变化时，原问题默认原分冻结。
- 任一问题降 `2` 分及以上，必须逐项写出可观察变化及其如何减轻用户影响；只有换了背景位置、圆角或措辞，不能消除“缺少第二视觉对象”“主体不显著”等结构问题。
- 如果复审发现上一轮评分过低，应向上纠正并明确承认基线错误，不能为了维持“已经通过”的结论继续压低分数。
- 达到交付线只改变是否继续修改，不改变问题是否公开。五个问题、原始分数和残留风险始终保留。

### 交付时的强制输出

最终回复必须包含：

1. 每个页面模块五个问题，按分数降序排列；即使模块表现很好，也列出真实的低分完成度问题。
2. 每个模块的问题指数，以及整页全局前十。
3. 与上一轮相比的分数变化；下降 `≥2` 的项目逐项给出视觉证据，未实质变化的项目标记“分数冻结”。
4. 明确结论：通过、带残留问题通过、或不通过。不得只说“已验收”“没有高分问题”。
5. 若交付 HTML 或图片，同时给出预览链接；审稿内容不能只藏在折叠区、临时文件或内部日志里。

### 修复闭环

1. 先处理内容根因：删除、合并或重写没有叙事任务、信息增量或证据的模块；内容成立后，再处理换素材、重截 focused panel、改语义断行、重分面积或改变卡片序列。
2. 一轮只选择能同时消除多个高分问题的最小改动；不要平均润色所有低分问题。
3. 重新渲染桌面和窄屏，再执行一次挑刺。没有 `≥8` 的问题且每个模块问题指数都不高于 `5.5` 才可称为达到当前交付线；结论通过也必须公开完整评分。
4. 最多连续两轮；仍未达线时披露剩余问题和需要换图、改文案或改变艺术方向的原因，不用微调无限循环。

### 常见伪通过

- 背景和字体很美，但模块没有具体内容、信息增量或故事任务。
- 只有一句泛化口号，却占据一整张大卡；视觉留白被误当成内容完成度。
- 文字在左上、截图在右下，却没有共同轴线、承托关系或对角线意图；随机错位被误当成高级的不对称。
- 背景装饰、截图和标签全部压向同一侧，另一侧的大块空白却没有引导作用。
- 截图完整，但主体太小，观众仍看不懂。
- 留白比例达标，但留白没有方向和作用。
- 标题字符数合规，但中文词组被拆行。
- 每张卡单看成立，但背景、构图和节奏重复，没有整页推进。
- 页面前半段精美，证据区或结尾突然变成后台、报告或默认组件。
