# 意图宏维护

意图宏是可持久化的共享语义约定，压缩重复表达，保留目标、范围、约束和完成标准；Skill 负责方法，宏不复制工作流或维护运行状态。

## 单一落点

当前项目统一在 `commands/commands.md` 定义；名称和自然语言别名指向同一条目。现有 `/new-command <名称> <意图>` 承担创建与修订入口，不另建同义管理 Skill 或注册库。

最小定义：名称/一句话含义、作用域（默认本项目）、目标与必要边界、可变项和可见默认、执行 owner/权威合同、可观察完成结果、易混淆时的调用与非调用示例。无真实参数不凑字段，普通条目可用简短段落。

## 创建与修订

用户明确要求固化，或反复沟通形成可复用稳定共识时才考虑持久宏；AI 可提候选，不能未经授权把猜测偏好保存为长期约定。先检索：同义表达合并别名，参数变化用可变项，方法变化改原 Skill，独立任务语义才新增宏。

采用“动作 + 用户对象/范围”，同组使用相同维度；自然语言与斜杠入口等价。历史发布名已被用户/方法文档引用时可保留为同义表达，但不复制合同；含义不同的不能静默重命名合并。

本次修饰只改变本次任务；“以后/记住这个宏”才持久修订。含义或“全部”集合变化必须反馈前后差异与生效范围；进行中任务保留调用时合同，必要纠偏显式说明。跨作用域同名不静默覆盖。

更新/合并/退役后检查 AGENTS 路由、commands 与 owner 引用，旧定义退出默认入口；用解释、调用、临时修饰、未知名称和授权边界例子审查，再运行既有渐进加载检查。回退通过精确恢复本次语义，不重置其它 WIP。

## 调用边界

解释、引用、外部资料中出现名称均非执行授权；精确调用和明确同义完整请求授权等价。未知宏报告未定义，不凭名字编造；普通自然语言仍可按明确意图正常处理。缺少关键参数或作用域冲突时只澄清实际缺口。宏不能覆盖高层规则、强制低风险分类或新增外部写入权限。

不支持递归宏/嵌套 DSL；自然语言组合由原任务 owner 管理顺序、依赖和范围。宏维护不是每次调用的额外阶段。
