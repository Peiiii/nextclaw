# 规则资产生命周期

规则资产包括 `AGENTS.md`、Skill、Reference、命令合同和治理脚本。它们不是只增不减的永久文本。

## 生命周期

每项体系改进按以下状态流转：

1. **候选**：有有效反馈和根因，但尚未证明长期价值；
2. **试用**：落在最小作用域，保留适用边界、反例和回退方式；
3. **复核**：观察是否减少目标失误，以及是否增加误触发、Token、延迟或维护成本；
4. **处置**：保留、提升、下沉、合并、自动化、收窄、回退或删除。

没有证据支持净收益时，不得仅因规则“听起来正确”而提升到常驻层。可以由确定性检查稳定覆盖时，用测试或脚本替代重复自然语言；只剩背景价值时下沉到文档。

## 放置原则

| 资产 | 适用内容 |
| --- | --- |
| `AGENTS.md` | 每轮都必须知道的高优先级边界 |
| `SKILL.md` | 明确意图命中后每次都需要的决策 |
| `references/` | 只在条件分支成立时需要的长合同或方法 |
| `scripts/` / tests | 可确定执行、信号高且误报低的约束 |
| `docs/` | 人类背景、设计、历史和非自动硬规则 |

同一事实只保留一个 owner。提升层级前证明低层无法可靠触发；下沉或删除前确认没有仍依赖它的入口和检查。

## 模型能力补丁

模型能力补丁不是新的运行时层或适配器，而是现有提示词/规则资产的一种属性：它存在的主要原因是补偿当前模型在某类判断或执行上的能力不足，模型改进后可能应被移除。

补丁继续放在其自然 owner 中，并在补丁附近使用可搜索标记：

```md
<!-- model-capability-patch: gap=<当前能力缺口>; review-on=model-change; remove-when=<可观察条件> -->
```

- 整个 Skill 都是补丁时，把标记放在 frontmatter 后；
- 只有一个章节或单条规则是补丁时，把标记放在对应内容之前；
- `gap` 说明它补偿什么，不写抽象口号；
- `remove-when` 描述移除后模型仍能稳定达到同等或更好结果的可观察条件。

模型、工具或运行时显著变化时，用 `rg -n "model-capability-patch" AGENTS.md .agents/skills` 找到补丁，选择代表性任务做无补丁对照。效果相当或更好时删除；只在局部仍需要时收窄。不能仅按时间自动删除，也不为首版另建补丁注册表。

## 变更证明

每次规则资产变更至少回答：

- 它阻止哪类已有失误，证据是什么；
- 为什么当前 owner 和层级最合适；
- 对正常任务新增多少触发与上下文成本；
- 哪个反例说明它不应扩大；
- 如何验证、回退或未来删除。
