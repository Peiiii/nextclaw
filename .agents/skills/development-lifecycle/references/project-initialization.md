# 项目初始化

由 lifecycle 拥有的 `initialization` 流程合同，复用现有阶段 owner；不是独立 Skill、安装器或第二套开发流程。

## 触发与范围

创建新独立产品，或目标目录虽存在但仅有管理脚手架、尚无服务本次目标的产品运行链路时进入。已有产品的新增功能走 standard，修复已约定链路走 bugfix；只接入/升级开发体系、创建文件夹或纯设计不等于授权实现新产品。遵守目标位置、项目规则和明确授权，不将来源项目的 Git/部署授权移入新项目。

先检查目标目录、现有改动、上级与项目规则、同类可复用路径和真实目标。已有初始化证据仍有效时只补缺口，从当前阶段继续；不能因为 README 简短、未发布或缺少某框架就重建产品。

## 阶段门

1. **Understanding**：明确用户/主任务、最小完整结果、设备/部署宿主、范围与授权、数据/凭据归属、已知/未知和技术决策状态。按项目约定接入开发体系并验证；创建目录、安装开发规则和记录项目元数据可以先于产品方案，不视为搭建产品脚手架。
2. **Design / Review(mode=design)**：在正式产品脚手架、产品依赖安装与实现前，形成目标环境和技术栈决策、owner/主链路、失败恢复、验收及适用部署方案，由既有 Design 方法完成选型、Review 核对。限定问题的可丢弃实验仍允许；不强制候选数量、默认技术栈或人工审批。缺少会改变选型的外部信息时只暂停依赖工作。
3. **Implementation**：按已审方案搭建最小完整项目和首条用户链路，不把空模板当成果。版本/启动/构建入口与实际运行一致，敏感材料按事实归属存储，README写真实入口与命令；项目规则留在AGENTS共享受管段外，不复制共享Skill。
4. **Validation / Review(mode=implementation)**：从真实入口完成代表用户任务并观察结果，检查必要设备、错误/恢复与适用类型/构建链路；“依赖安装成功”“模板能启动”“tsc通过”均不单独证明初始化完成。
5. **Delivery / Retrospective**：沿原授权提供可用入口和恢复说明；需要上线且已授权时完成真实上线验收。沿用 lifecycle 的整体完成门。

## 上下文与完成判断

在原任务设计/日志中保存用户输入与有效要求、技术决策及依据、当前阶段、适用验收状态、可用入口、证据指针与未完成项；大型交付沿用其现有恢复入口，不另外建初始化账本。README承载长期运行说明，任务记录承载本轮状态，不让二者平行维护动态进度。

初始化完成须同时有：有效选型与方案Review、服务用户目标的运行链路及证据、真实交付入口、可恢复的上下文，以及原lifecycle必要门通过。初始化流程不降低原用户结果，也不保证宿主停止后自动执行。
