# Development Retrospective

## 轻量判断

每个任务结束前检查目标、方案与交付差距、返工和重复沟通。当前结果未完成先返回对应阶段，不能写成未来优化。无可复用增量直接结束，不默认生成日志、规则或测试；待用户验收时可先判断，反馈更新同一记录。

## 分流

先区分任务恢复记录、事实更新和长期方法/流程改进，不能使用同一沉淀门：

| 发现 | 正确落点 |
| --- | --- |
| 产品错误 | 返回实现与相关回归验证，不用提示词代替修复 |
| 已验证事实变化/资料冲突 | 原知识条目或权威源，及时更新，不等重复 |
| 方法不足 | 原阶段/专项方法 owner |
| 方法存在但没触发 | 路由与触发条件，不复制方法 |
| 顺序、完成门、返工有缺口 | 总流程 Meta Skill |
| 稳定的重复沟通约定 | 现有意图宏登记处 |
| 可确定的高价值重复错误 | 优先已有测试/工具/通用检查 |
| 特定模型能力不足 | 原 owner 的条件补丁，模型变化时复核退出 |
| 偶发疏漏、无增量总结 | 修正当下，通常不持久化 |

## 长期改进门

方法/流程候选须有重复、系统性或高影响单次事件的证据，说明原 owner 为何失效、覆盖的一类问题、适用/反例、收益与成本、验证和退出条件。不因措辞强烈、道理正确或单例细节自动创建全局规则。

正式抽象时读取[经验层级校准](references/experience-abstraction-calibration.md)。优先定位原 owner 后更新、合并、收窄、下沉、替换或删除；只有独立价值无现有落点时才新增。不以净零行数牺牲必要知识，不借机治理无关领域。

## 处置与路由

一次只返回当前资产的 owner 和处置建议，由总流程调度，不回链或自行启动其它阶段：

- 流程、方法、宏、AGENTS 或模型补丁改进：`nextclaw-agent-instructions-governance`，执行[资产生命周期](../nextclaw-agent-instructions-governance/references/rule-asset-lifecycle.md)。
- 事实、决策、想法或知识更新：读取[项目知识治理](../../wiki/skills/process/project-knowledge-governance/SKILL.md)。
- 有独立交付意义的重要批次留痕：读取[迭代记录治理](../../wiki/skills/governance/nextclaw-iteration-log-governance/SKILL.md)。

在当前授权范围内处理可确定更新；无体系修改授权时给出候选，不以复盘扩大产品任务。输出证据、唯一落点、更新/合并/删除/不沉淀决定与验证边界。已有方法充分但一次漏执行，先修调用证据，不追加“务必注意”。
