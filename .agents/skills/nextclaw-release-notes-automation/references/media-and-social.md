# 版本配图与社交

- 图片必须真实、公开安全并直接证明主结论；空态、mock、加载态、被裁断结果或弱装饰图不采用。
- 用户可见 UI、真实工作流、结果形态和新入口优先真实产品截图；纯 CLI、协议、稳定性、内部链路默认无图。
- release summary 返回的候选图逐项判断；采用时复制为版本稳定资产，中英文页面使用匹配 locale。
- Stable minor 在公开 release note URL 返回 200 后默认发布一条 X 短帖；patch 和内部治理默认不发，major 版本单独确认宣发范围。
- X 帖默认带一张高信息密度图片：优先能直接证明主价值的真实产品截图；性能、架构或后台行为无法由 UI 证明时，使用明确标注测量口径和边界的版本摘要图，不把概念图冒充产品截图。
- 用户已给出 stable minor 长期发布授权时，不再逐次请求文案确认；有授权工具时直接发布并记录 URL。没有能力时交付可直接发布的文案和图片路径，明确阻塞。
- 社交文案只写版本号、主要用户价值、1-2 个亮点和 release note 链接，不写内部流程。
