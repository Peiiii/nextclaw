# X 发布交接与故障处理

仅在发帖、回复、点赞、关注、使用真实浏览器或诊断 CLI 故障时读取。执行前核对 [X 当前自动化规则](https://help.x.com/en/rules-and-policies/x-automation)：禁止自动点赞和主动自动关注；未经对方请求的自动回复不得用于陌生账号扩散；AI 自动回复需平台事先书面批准；非官方 API 的网站脚本化操作有账号风险。当前仓库未验证可用于 X 写入的合规官方 API 路径。

## 发布路径选择

- 用户指定真实浏览器时，用现有登录的真实 Chrome 读取页面与准备成稿；内嵌浏览器不共享登录态。用户明确禁用 bird 时，搜索和核验也不用 wrapper。
- 已授权撰写并发布时不重复索要正文确认，但授权不替代平台允许的写入途径。当前没有经核实的合规自动写入路径时，交付成稿及目标链接供用户手动发布；用户的后续修订仍属于当前任务。
- 将来若接入官方 API，先核实对应动作、授权、平台规则与回读能力，再由该路径执行。不得把现有 CLI 的内部 GraphQL 或浏览器脚本化点击当成官方 API。

## 真实 Chrome 读取与核验

用户要求真实浏览器时：

1. 用当前 Computer Use 工具取得真实 Chrome 状态，读取页面显示的账号与最近帖子；不通过 shell 读取浏览器凭据，也不调用禁用的工具。
2. 先排除上一轮结果不明的重复帖子；核对现有帖子详情中的作者、完整正文、素材和链接。时间线截断或加载中不代表正文缺失或发布成功。
3. 为用户准备成稿时，在交付前检查事实、首句、链接、受众和素材。用户手动发布后，可凭其提供的链接或可见时间线核验；没有核验结果不报成功，也不自行重发。

## CLI 同名冲突与 226 处理

- 先用 `which -a bird` 和 `ls -l` 检查解析目标，再读对应 package 名。`/opt/homebrew/bin/bird` 曾指向无关的 `bird-cli/bin/index.js`，输出 `Init Modele` 等帮助不是 X 授权失败。
- 本机正确包曾位于 `~/.npm/_npx/*/node_modules/@steipete/bird`，当次版本 0.8.0。用 `rg --files --hidden ~/.npm/_npx` 查找 `@steipete/bird/package.json` 并核实，不能把某次 npx 缓存哈希写死为永久路径。
- 把已核实包所属的 `node_modules/.bin` 临时前置到本次命令 PATH，再运行仓库 wrapper；不替换全局 bird、不安装同名未知软件。需环境代理时使用本机支持该能力的 Node；当次成功读取使用 `/opt/homebrew/opt/node@25/bin/node` 与 `NODE_USE_ENV_PROXY=1`，使用前确认路径存在。不得打印代理凭据或认证参数。
- 模板：`PATH="<已核实的 node_modules/.bin>:$PATH" NODE_USE_ENV_PROXY=1 <支持环境代理的 node> .agents/skills/x-twitter-bird/scripts/x-bird.mjs whoami --plain`。用户禁用 bird 时本节整体不适用。
- 返回 226（疑似自动化）只说明该次请求被拒，不能据此断言账号已封禁或确定触发因素。先查重并停止该动作的自动写入，不把真实浏览器操作当作绕过拒绝的替代路径；页面出现限制、验证挑战或连续异常时也停止并报告可观察事实。不靠随机节奏、切换身份或网络规避限制。
- 真正出现 CAPTCHA 时按当前电脑操作工具的权限合同处理；若要求操作当下确认，笼统的“任何权限”不能替代。普通网页发布不需要新增 CAPTCHA 确认，只有实际遇到挑战才处理。持续验证失败、明确封禁或需要用户输入时报告具体状态，不宣称已完成。

## 关注与互动的反馈核验

- 用户要的是相关读者的关注时，发帖、有效讨论和个人主页能否说明账号价值是主要链路；不以关注/粉丝比例单独预测回关，它只是推荐候选的弱线索。
- 用户手动关注或互动后，如需复盘，可读取正在关注列表、账号关系或目标帖；按钮瞬时变化但刷新后未持久生效，记为未确认，不能计入完成量。
- 记录可核验的原始指标与观察时间：新增相关关注者、有效回复、个人主页访问或帖文互动中实际可见的项。关注数、点赞数和原帖热度不能替代这些结果；不可见指标标未知。按真实反馈调整选题与互动，不根据一次低样本结果推断平台算法。
