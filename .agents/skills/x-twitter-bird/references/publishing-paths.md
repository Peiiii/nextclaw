# X 发布路径与故障处理

仅在实际发布、使用真实浏览器或诊断 CLI 故障时读取。

## 发布路径选择

- 用户指定真实浏览器时直接使用；本机已验证 Chrome 的现有登录会话可发布 X，内嵌浏览器和独立 DevTools 浏览器不共享该登录态。不要先把用户送到未登录的内嵌 intent 页面。
- 未指定工具时，读取与搜索可以用 wrapper；发布优先检查真实浏览器已有登录态。浏览器不可用时才评估 CLI 写入，不默认反复尝试接口。
- 已授权撰写并发布的当前任务可直接执行成稿，不再机械索要正文确认；没有发布授权时只交付草稿。用户的后续修订仍属于当前任务，按修订后的版本发布。

## 真实 Chrome 操作与核验

以下是 2026-09-09 已成功验证的路径，不保证网站界面和账号权限永久不变：

1. 用 `cua.getState()` 查真实浏览器；未暴露 Chrome tab 时用 `cua.getApp('com.google.Chrome')` 操作原生窗口。工具提示会话未激活时重新 getApp 获取状态，不改用 shell 模拟点击或读取浏览器凭据。
2. 在新标签页打开 X，读取页面上的账号名、个人资料链接和编辑个人资料入口，确认发布身份。检查最近帖子，尤其上一轮提交失败或结果不明时，先排除重复。
3. 从页面的“发帖”进入编辑器；读取最新 AX 树后定位“帖子文本”，用 paste 填入完整文案。每次操作后刷新 AX 状态，不复用历史元素编号；若导航回个人页，使用页面上真实可见的发帖入口。
4. 提交前回读编辑器，核对第一句关键成果、全文、链接、受众及素材。以实际剩余字数和按钮状态确认长帖能力；本账号当次支持长帖，不能因此假设所有账号都支持，也不能为套 280 字删掉用户要求的重点。
5. 授权内点击发帖一次。等待发送结果，记录时间线中的新帖 URL；进入详情核对作者、展开后的完整正文、链接和应有素材。长帖在时间线截断不代表发布被截断。
6. 详情页停在加载态时检查当前状态，必要时刷新一次；可用 wrapper 按已知 ID 辅助回读。加载中、点击成功或只看到发送提示都不代替完整核验；结果不明不能重发。

## CLI 同名冲突与 226 处理

- 先用 `which -a bird` 和 `ls -l` 检查解析目标，再读对应 package 名。`/opt/homebrew/bin/bird` 曾指向无关的 `bird-cli/bin/index.js`，输出 `Init Modele` 等帮助不是 X 授权失败。
- 本机正确包曾位于 `~/.npm/_npx/*/node_modules/@steipete/bird`，当次版本 0.8.0。用 `rg --files --hidden ~/.npm/_npx` 查找 `@steipete/bird/package.json` 并核实，不能把某次 npx 缓存哈希写死为永久路径。
- 把已核实包所属的 `node_modules/.bin` 临时前置到本次命令 PATH，再运行仓库 wrapper；不替换全局 bird、不安装同名未知软件。需环境代理时使用本机支持该能力的 Node；当次成功读取使用 `/opt/homebrew/opt/node@25/bin/node` 与 `NODE_USE_ENV_PROXY=1`，使用前确认路径存在。不得打印代理凭据或认证参数。
- 模板：`PATH="<已核实的 node_modules/.bin>:$PATH" NODE_USE_ENV_PROXY=1 <支持环境代理的 node> .agents/skills/x-twitter-bird/scripts/x-bird.mjs whoami --plain`。发布文本用结构化参数或安全 shell 引号，避免美元金额、反引号及换行被 shell 解释。
- 返回 226（疑似自动化）不等于账号已封禁。本次 wrapper 刷新 query IDs 后仍写入失败，但相同账号在正常 Chrome 页面发布成功。失败后先读取时间线；确认未发布，再走已有登录的正常页面，不换账号、代理或指纹绕过限制，不盲目重试接口。
- 真正出现 CAPTCHA 时按当前电脑操作工具的权限合同处理；若要求操作当下确认，笼统的“任何权限”不能替代。普通网页发布不需要新增 CAPTCHA 确认，只有实际遇到挑战才处理。持续验证失败、明确封禁或需要用户输入时报告具体状态，不宣称已完成。
