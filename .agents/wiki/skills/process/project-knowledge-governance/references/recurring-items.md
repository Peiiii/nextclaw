# 周期事项（Recurring，试用）

## 适用与分流

用户要求保存或建立每天、每周等固定频率反复履行的职责时，使用 `docs/recurring/YYYY-MM-DD-<topic>.recurring.md`。它回答“每个周期要完成什么、怎样才算完成、结果到哪里查”。日期取创建日；跨周期修订原文件，不每天新建合同。

单次动作用原任务/plan；持续观察和复查用 track；根据每轮证据选择下一轮实验用 loop。一次周期内需要实验或开发时引用这些原 owner，不在 recurring 复制方法。仅描述未来可能定期做的事，尚未要求保存事项时，继续留在 thought。

## 单一 owner 与内容

周期文档保存稳定职责和执行意图，不成为新编排器。至少包含：

- 目标、范围与依据，引用长期方向/事实 owner，区分用户要求、已确认选择和待验证建议。
- 意图状态：草案、启用、暂停或结束；草案不可因到期自动执行，暂停/结束须明确恢复意图。单次成功不结束长期职责。
- 频率、时区、执行时段或事件条件；未确定的参数写待定，不声称已配置。
- 输入与每次动作、可观察的完成标准、质量或资源边界、结果保存入口。
- 执行与维护角色、授权来源、需要最小用户输入的条件；文件存在不能提供发布、发送或其它外部授权。
- 调度关联：未配置，或宿主 automation/任务的 ID/入口及核对时点。真实启停、频率、下次触发和通知配置由宿主单一维护，不抄成第二份动态状态。
- 最近一次实际执行证据链接及必要摘要；尚未执行时明确写出。详细历史、进行中状态与验收沿用项目原任务/日志/平台记录。
- 重复、漏跑、中断与失败的处理，以及暂停、结束和重新评估条件。

不为完整性填数字预算或制造空执行日志。现有产物可直接成为证据；只更新实际变化的摘要，不把计划日期写成最近完成时间。

## 创建、发现与当次执行

1. 优先使用已知文档；否则以 `rg --files docs/recurring` 找同主题，复用原项。列举时只读取主题、意图状态和结果入口摘要，不每轮扫描所有事项。建立索引或项目导航时链接原文件。
2. 创建时对齐目标、稳定动作、完成标准和权限。保存/头脑风暴默认草案；明确执行请求按现有授权推进可做的当次任务，自动调度是否开启分别判断。
3. 当用户或已配置宿主触发执行，读取仓库当前周期文档及相关最新证据，核对意图状态、实际授权、输入和质量条件。宿主保存的旧 prompt 不能覆盖项目当前暂停/结束决定。普通一次执行沿所属内容/运营/开发流程，不为每次小动作强造设计、plan 或大型验收账本。
4. 以事项身份和所属周期核对实际完成记录；同一周期已完成的外部动作不重复。中断、超时或发布结果未知时，先查询原任务/平台状态，再决定续做或重试，不能以“没有本地成功日志”推断外部未发生。
5. 依本事项的补跑策略处理漏跑；未约定时记录缺口并处理当前周期，不默认堆积补发、无限重试或扩大预算。失败与质量不足记录真实未完成原因，不计作成功。
6. 若周期职责确有执行但目标持续无进展，或同一失败重复且没有新证据，读取[停滞后的全局重评](stagnation-reassessment.md)，重新选行动。未执行、数据窗口未到、外部等待与策略无效分开；完成次数不代替业务结果。
7. 完成后回链实际产物和验证/平台证据，必要时更新最新摘要。实质效果复盘按[行动闭环](review-actions.md)选定并执行当前可做的下一步；单次职责已完成不强造新需求。暂停/结束需分别处理文档意图和关联宿主配置；只改文档不能声称宿主也已停用。若宿主变更尚未成功，明确缺口，触发执行仍遵守暂停意图。

## 调度与通知

文档是职责约定，不会让后台自动运行。只有用户明确要求定时主动执行时，才连接当前宿主的调度能力；先检索是否已有对应任务，避免重复创建。记录实际配置结果，未成功则保持未配置或说明恢复入口。改频率、暂停或删除配置沿宿主工具合同，不自造调度器、后台进程或数据库。

定时 prompt 引用当前文档路径，要求每次读取目标/质量/状态与已完成证据；不复制整份合同。通知遵守用户意图，默认只在有实际交付、重要变化、失败或需用户动作时反馈，状态未变不反复提醒。

## 轻量模板

```md
# <主题>：周期事项

创建日期：YYYY-MM-DD
意图状态：草案 / 启用 / 暂停 / 结束
维护与执行角色：<谁维护、谁执行>

## 目标与依据
<长期方向入口；明确要求与待验证建议>

## 周期与每次完成标准
<频率、时区、执行时段/触发；输入、动作、质量/资源边界和可观察交付>

## 权限与调度关联
<授权来源、不可替代输入；未配置，或宿主 ID/入口和核对时点>

## 结果与恢复
<原任务/产物/平台证据入口；尚未执行，或最近实际执行链接>
<重复、漏跑、中断、失败处理；暂停/结束/复核条件>
```

## 试用复核

用真实重复职责观察是否提高发现、接续和执行对账的可靠性，是否误触发或增加维护负担。只需观察的事项合并回 track；实验方法保留在 loop。没有独立收益时收窄或撤销，不自动新增顶层 Skill、常驻上下文或专项调度系统。
