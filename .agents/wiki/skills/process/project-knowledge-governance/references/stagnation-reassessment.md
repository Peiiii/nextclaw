# 停滞后的全局重评（试用）

适用于已承担改善结果的长期关注、周期职责或循环实验。状态检查用于发现变化；它不能替代改善行动。只读监控、暂停/结束的事项与明确禁止改变策略的委托，不因此获得额外执行权限。目标与执行状态仍归原事项/任务，不建立另一套账本或调度器。

## 什么时候触发

依据项目原有观察窗口和成功信号判断，而非统一的“连续N次无变化”：有效窗口已到却没有目标推进；同一失败重复且没有新信息；反复只做健康检查、文档或调度而没有改善动作；或用户直接指出“没有进展”。首次建立事项时说明何时足以判断策略需要重评；尚无依据则明确未知。

先区分：动作尚未执行、动作执行但结果未知、样本/窗口不足、外部等待/工具不可用、策略有证据不奏效。缺数据不写成零，未到观察窗口不宣布失败。窗口未到不阻止独立可做的调查、咨询处理或准备；外部阻塞只暂停依赖它的步骤。

## 跳回目标，再选行动

1. **重看全局。** 重述用户最终结果、当前差距与最早瓶颈；对照近期动作是在改善这个瓶颈，还是只改善实现细节。核对仍然有效的限制和授权，不沿用已被用户解除的限制，不缩减目标或靠频繁改指标制造进展。
2. **提出可辨别的解释。** 区分事实、假设与未知。先查目标/受众是否匹配、价值与优势是否表达、入口/分发是否可用、输入到结果是否顺畅，再选最能改变决策的一项；不机械研究所有维度。重复的实现错误返回原调查/修复阶段。
3. **向外寻找更好的做法。** 若现有证据不足以决定下一步，进入原调查流程，用官方资料、同用途高结果案例或当事人的一手复盘搜索核验。通常先核验1—3个最相关案例；已有新鲜且可比的证据直接复用，不为每次唤醒重复搜索。记录来源/时点、输入输出、受众/渠道、真实指标与时间/价格口径、关键做法、条件及未公开部分。分清结果、作者主张与自己的归因，不能从成功案例推导单一因果。
4. **借鉴机制，保留差异。** 比较案例解决的瓶颈与本项目瓶颈。可以参考产品表达、交付方式、获客入口或执行顺序；不能抄未经授权素材、虚构资历/结果，或把不具备的能力写成承诺。幸存者偏差、渠道规则、历史积累、投放、团队与成本不同均可能影响可比性。外部案例不是当前有效性的证明。
5. **选一个最有信息价值的动作并执行。** 沿[行动闭环](review-actions.md)明确预期信号、实际执行与复测后的决策。优先触及最早瓶颈且可回退的行动，必要组合调整说明不是单变量实验；确需外部输入时给直接入口和最小步骤，继续独立可做工作。
6. **学习和接续。** 回链真实动作、回执/产物、效果、缺口与下一决策。到原观察点比较预期和实测，选择保留、调整、换路径或停止该做法；停止做法不等于结束用户目标。重复失败无新证据时退出同一重试，不能以无限调参、搜索或扩大预算代替决策。不能仅因一轮成功把方法永久固化。

最小输出是：**当前差距 → 本轮判断 → 可比证据/缺口 → 已执行或确切阻塞 → 下次判定点及失败分支**。不要求每次新建design/plan/loop；使用原owner，实施和发布继续遵守已有生命周期。通知频率按用户明确偏好与宿主配置；需要每轮汇报时说明实际动作与未完成项，普通监测默认不反复通知相同状态。

## 参考与验证边界

[IHI改进模型](https://www.ihi.org/library/model-for-improvement)及[小范围PDSA试验](https://www.ihi.org/library/model-for-improvement/testing-changes)强调目标、改善判据、预测、实际试验和从结果学习。本方法借其结构，不将医疗场景的具体规则移植为通用软件门槛。

[Paul Graham的一手创业观察](https://www.paulgraham.com/ds.html)记录Airbnb早期主动走访用户、改进房源展示，以及Stripe现场协助用户接入。可借鉴的是主动查真实使用障碍并动手改善；它不证明每个项目都应线下获客、手工接入或复制同一种素材，也不授权陌生人群发。

以上是方法依据，2026-10-07核验；适配本项目的行动与效果需要真实试验。试用后复核是否减少被动轮询、改善决策与执行，是否造成低样本误触发、额外搜索或越权；无净收益时收窄/合并/撤回。正常推进、合理等待和只读监控不加载本长方法。
