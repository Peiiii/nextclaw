# 大型交付的工作记录与持续日志

仅在大型交付中使用。本参考拥有记录载体、模板、读写和恢复方法，不决定任务 flow、验收标准或整体完成。验收正文由[验收合同方法](../../acceptance-contract-governance/references/acceptance-contract-method.md)维护，设计由原 Design owner 维护。

## 固定入口与职责

默认布局如下；已有项目等价载体映射一次，写入工作记录，不另建同义副本。一个大型交付保持一个稳定恢复入口，不因跨轮或多批日志复制当前进度。

```text
docs/designs/YYYY-MM-DD-<topic>.design.md
docs/work/YYYY-MM-DD-<delivery-slug>/
  acceptance-contract.md
  current-state.md
  artifacts/                             # 按需：附件不自动构成验收证据
docs/logs/YYYY-MM-DD-<topic>/
  README.md                              # 含“原始输入与约束”章节或独立文件入口
  YYYY-MM-DD-inputs.md                    # 按需：原始输入与约束较多时独立承载
  records/YYYY-MM-DD-<topic>.md           # 按需：过长或需独立审查的过程详情
```

日期是记录创建日；同一委托跨天沿用目录，同日独立委托用可区分的主题。work 使用单数。日志也支持 `v<semver>-<slug>/README.md`，新建默认日期，旧记录原地续写，不为同批造日期/版本双副本。目录身份与实际发布版本分开，项目专属章节可保留。

日志保存原始输入与约束的来源记录、关键历史与交付汇总；合同引用来源，保存当前有效约定与验收账本；design 保存方案、对齐依据和理由；current-state 保存当前执行状态与恢复导航。plan 遵循原触发门，附件和长详情按需，不要求每工作项建文件、编号或五段表格。

旧任务的 working-notes 或项目等价入口原地续写，不并建第二份。明确改名时同步所有当前入链，保留历史可定位性；两种名称并存不能仅凭新名称或修改时间判定权威，应沿任务入口与实际内容消歧。

## 原始输入与约束

在依赖这些输入设计/实现前整理到本任务 `docs/logs/`。默认用 README 的同名章节；多份原型、长要求或需要独立引用时拆为 `YYYY-MM-DD-inputs.md`，README 保留入口。同一任务只维护一处，不每日复制；已有等价原始材料可直接链接，在日志中保留索引与用途说明。

按实际输入保留以下内容，短内容可用列表，不强制表格：

- **来源与版本**：用户表达的日期及必要原话，HTML/图片/附件/文档的可访问位置，commit、内容校验值或明确版本；可变且不可回溯的来源按权限保存必要快照，不假称未提交内容已被 Git 保存。
- **预期与用途**：用户希望得到的结果、必须保持的功能形态/交互/外观或其它约束；明确材料是实现基准、部分参考还是待探索。区分用户明确要求、确认选择、授权内决定和 AI 推断；角色不明且影响结果时才澄清，不把全部素材细节自动变成硬约束。
- **范围与未决项**：哪些部分适用、明确排除什么、缺失/冲突/尚未确认的内容；关联当前合同条目，已有 ID 则引用，不为每句原话新建编号。
- **后续补充与替代**：保留旧来源，追加纠偏或替代关系及生效依据；当前有效标准仍由合同决定，日志不另维护一份现行验收表。

先读相关原件再提炼，摘要只作导航。合同、设计和当前状态都能定位该记录；新输入须在后续依赖动作前更新。未提供原件时如实记录，不虚构已核对。敏感材料遵守项目权限，不复制凭据或受限数据。

## 当前状态模板

```markdown
# 当前执行状态
## 身份与入口
- 交付主题；整体状态（进行中/暂停/阻塞/待验收/已完成/已停止）；最近核对时间
- contract-id；合同路径与修订；原始输入记录；整体/当前部分设计的具体段落及 Review 指针；日志；plan（有则链接）
## 执行现场
- 仓库/工作区、分支/产物；本任务未提交改动的定位及与其它 WIP 的边界
- 接续所需的运行环境、操作标识和核验入口（适用才填，不存凭据）
## 当前进度
- 当前环节；已闭合结果和依据；待开始/进行中/已实现未验证的必要工作及原验收 ID
## 未闭合事项
- 待设计部分与触发点；失败/过期验证、未关闭 findings；待决定/外部条件
- 未核实动作；待同步文件及修订（无则写无）；引用原记录，不复制历史
## 下一步
- 下一具体动作及前提
```

工作记录从已有任务/设计入口可达；交接或压缩摘要保留其路径。有效标准和验收状态以原账本为准，不抄第二份；有 plan 时进度引用其工作项，无 plan 时用简短列表保留必要工作。整体执行状态不代替验收结论，不因普通进展提升标准修订号。已完成时回链实际交付，未完成项不能借整理移出范围。

## 查找与接续

仅在用户要求恢复/继续或当前任务需要接续时查找，不因打开项目自动执行旧任务。优先使用用户、任务、设计给出的入口；没有入口时列出本项目 `docs/work/` 下 current-state.md 和旧 working-notes.md，先读候选的身份与状态。其它布局沿项目路由/日志的明确映射找回，不全量加载历史。

按本次用户意图匹配交付；多个未完成项不能按日期新旧选，也不能全部启动，无法消歧才询问。缺状态字段视为未知；已完成/已停止记录不是默认续做目标。暂停或停止任务须有明确恢复指令；模糊“继续”不解除其它任务的暂停。

选定后读有效合同、适用设计和必要证据，再核对实际工作区与未核实外部动作。先前记录的状态不等于当前事实；找不到产物、发现版本变化或指针冲突，先修复相关恢复信息，不盲目重做提交/部署。依赖缺口的动作暂停，其它独立工作沿原授权继续。

## 日志模板与及时记录

大型交付在首次需要保存输入时就创建或复用日志，最迟执行启动时建立；不用等全部完成。纯讨论继续原讨论/设计，不借此启动实现。默认 README 模块为：`关联入口 → 原始输入与约束（或其链接） → 过程记录 → 交付汇总与复盘`；项目已有交付章节映射承载，不再复制汇总。

- 关联入口：contract-id、原始输入章节/文件、合同/设计、唯一工作记录。
- 过程记录：按时间或可靠顺序追加“主题 → 实际观察/决定/失败 → 依据链接 → 对后续的影响”。待验证/未完成如实写明。
- 交付汇总与复盘：进行中注明尚未交付；收尾汇总实际范围、可用入口、验证与 Review、重要修订、限制及经验落点，引用原过程。

预期或关键方案改变、实验/验证结果、重要集成节点、失败/排除路径/返工、Review finding、外部操作与阻塞变化，均须在后续依赖动作前及时落盘。同一短工作单元可合并细节，不逐命令记账。关键实验先保存问题与判定；普通实现引用已有标准。外部动作先留意图与核验入口，完成后记录真实结果。

较长详情妨碍浏览或确需独立 Review 时才拆 `records/YYYY-MM-DD-<topic>.md`，模块为“问题与判定、过程与依据、结论与影响”，README 留摘要/链接。取消逐单元编号；返工更新原主题并保留失败及纠正依据。附件放 artifacts 或引用已有稳定来源，不存凭据或复制受限原始数据。

## 更新与恢复

普通关键进展写日志；当前状态改变才更新笔记；验收新证据更新原账本；新约定生效才修订合同/设计并使受影响证据 stale。不每次重写全套文件，也不重验无关风险。

证据/Review 记录注明适用约定、产物版本或实际工作区差异、环境、结果与限制及可恢复定位；未提交改动不能只绑定不含改动的 HEAD。finding 关闭依据留在原记录，后续总结不能掩盖未关闭问题。短结论可直接保存，长输出引用附件。

多文件变更先在笔记留下待同步对象，修改权威 owner，再对账受影响引用与证据，完成后清除待同步。不是原子事务：中断后先检查版本、工作区和未知结果的外部动作。旧约定无可访问历史时保存必要差异或只读快照；不得假称 Git 已保存未提交内容。

结束轮次、等待或交接前刷新当前状态，但不能只等可预测的压缩通知才保存。恢复依次读当前笔记、有效约定、相关设计和必要日志；不全量重读历史，不把摘要当合同。缺失会影响决策的材料先恢复或澄清，其它独立工作继续。

日志保留当时事实，当前下一步只有工作记录一个 owner。后续纠正关联原事件；补录注明来源与未知。完成后原材料和引用保留，不能靠回忆补全过程；下一独立任务不覆盖旧记录。
