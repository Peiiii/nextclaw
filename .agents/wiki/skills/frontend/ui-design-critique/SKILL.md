# UI 设计挑刺与收敛

<!-- model-capability-patch: gap=容易把“模块齐全、可点击”误判为高质量界面，忽略空壳区域和真实任务中的注意力成本; review-on=model-change; remove-when=无此 skill 时仍能稳定找出并删掉高影响冗余、用同视口真实参考解释取舍且复验任务效率 -->

## 判断对象

审查真实渲染的页面，不审查组件清单或设计形容词。先说清楚用户在这个页面的首要任务、进入时已有的上下文、下一步最可能做的动作。概览、对话、阅读、编辑和审批可以采用不同密度；不能因为某种布局在参考产品上出现，就不问任务地套用。

## 建立参照

选与该任务相近的成熟产品界面，记录产品、版本或观察日期、具体页面、视口和可见状态；优先看真实使用界面及交互，营销图只能作为低置信参考。同视口并排比较以下事实：主任务在首屏的位置、导航层级、内容宽度、面板关系、信息密度、操作顺序、状态反馈。写出参考设计**解决了什么问题**和自己的界面是否有同一问题，不照抄颜色、装饰或品牌特征。无法访问真实界面时明确说出证据限制，不能声称已做像素级对标。

## 先做删减审查

逐个检查占用首屏面积的区域，尤其是顶栏、标题带、侧栏、卡片、说明文字、状态卡和空白画布。对每块问：

1. 它让用户更快完成什么任务？移除后会失去什么具体信息或操作？
2. 同一信息或入口是否已在别处稳定可见？标题、面包屑、返回按钮、来源、状态说明是否重复？
3. 空白是在帮助阅读、保留内容节奏，还是只由固定高度、宽卡或占位容器造成？
4. 这块区域是否把关键内容挤出首屏，或迫使用户跨列、滚动、来回跳转？

答不出具体价值的区域优先删除或合并；不要先通过加文案、图标、卡片或更大间距修补。删除后须保证可发现性与返回路径仍成立。

## 再审层级与空间

按真实任务从上到下、从左到右走一遍。检查主内容是否比导航和辅助材料更显眼；阅读行宽、字号、行高、列表密度是否适合实际语言；对话与关联内容是否能并行而不压窄主任务；移动端是否仍有明确主滚动面。截图之外，用 DOM 几何、可见元素和代表操作验证显著问题，不能以“没有横向溢出”代替布局合格。

每轮尽可能找出所有具体缺陷；用户要求数量时按其要求，不为了凑数把个人偏好写成问题。每项记录「页面与视口、看到的现象、任务成本、参考做法及其理由、决定删除/合并/保留/重排、复验结果」。优先修任务受阻、空间浪费和重复认知，再处理微小装饰。修完重新截图、操作、再挑刺；剩下的批评若只是可互换的审美偏好，应明确标为偏好，不虚称完全无缺陷。

## 完成边界

交付前至少覆盖一个真实内容充足的桌面页面、主要模块间跳转和一个窄屏场景；用户指出的问题必须在对应页面复验。报告实际删掉或缩减的区域、参照证据、仍存在的客观问题与概念原型的能力边界。控件语义、键盘与状态仍归 [前端交互体验质量](../frontend-interaction-quality/SKILL.md)；本 skill 只负责页面级取舍与视觉效率。
