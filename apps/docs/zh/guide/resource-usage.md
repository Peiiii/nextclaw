# 运行资源与内存基准

NextClaw 可以长期运行在 VPS、NAS 或 Linux 设备上，同时不让所有已安装的消息渠道一起常驻。未使用的渠道没有独立扩展进程；启用渠道或开始授权时才启动对应运行时，最后一个实际需求结束后再退出。

## 当前建议的服务器起步配置

目前经过验证的 Linux 服务器基线是 **2 vCPU、2 GiB 内存**。这是已经跑通的起步配置，不代表所有部署方式的最低要求。使用本地模型、浏览器自动化、外部 Agent runtime、MCP server，或者与其他服务共用主机时，需要为这些工作额外预留资源。

1 GiB VPS 尚未完成同口径的启动峰值和真实任务验收，因此目前不作为公开支持承诺。

## 已验证的 ARM64 Linux 数据

下表使用源码提交 `248bf88b`，运行在 ARM64 Linux、Debian 12 容器和 Node.js 22 环境中。每轮限制为 2 vCPU、2 GiB 内存，使用全新数据目录、空 workspace，不运行 Agent 或模型请求；健康检查通过后保持空闲 60 秒再采样。

| 场景 | 渠道进程 | working set 三轮（MiB） | 平均 | peak 三轮（MiB） | 平均 | PSS 三轮（MiB） | 平均 |
| --- | ---: | --- | ---: | --- | ---: | --- | ---: |
| 空配置 | 0 / 0 / 0 | 172.67 / 161.41 / 160.74 | 164.94 | 222.84 / 187.91 / 187.25 | 199.33 | 208.16 / 209.87 / 209.58 | 209.20 |
| 单微信 | 1 / 1 / 1 | 201.96 / 187.05 / 189.84 | 192.95 | 231.29 / 217.78 / 218.52 | 222.53 | 249.67 / 234.89 / 237.26 | 240.61 |
| 单 Discord | 1 / 1 / 1 | 247.95 / 245.84 / 239.62 | 244.47 | 310.70 / 288.37 / 278.61 | 292.56 | 292.72 / 292.44 / 286.10 | 290.42 |

旧的启动方式会让十个渠道进程全部常驻，在同口径 ARM64 Linux 环境下空闲 working set 约为 865～885 MiB。现在空配置三轮平均为 164.94 MiB，下降约 81%，同时没有渠道扩展进程运行。

禁用最后一个微信渠道后，进程会在 30 秒宽限期结束时退出；60 秒时渠道进程数回到 0，working set 回到 160.48 MiB。

## 测量口径

- working set 使用 Linux cgroup 的 `memory.current - inactive_file`。
- peak 使用整个容器生命周期的 cgroup `memory.peak`。
- PSS 汇总 `/proc/*/smaps_rollup`。
- 每个场景连续运行三次，表格保留全部结果，不挑选最低值。
- 进程采样会包含一个短生命周期 shell，渠道进程数则单独核对。

working set 和 PSS 的记账方式不同，应分别与同类指标比较，不能直接相减。

## 哪些操作会增加内存

空配置数字描述的是空闲运行时。以下操作会按实际工作增加内存：

- 启用消息渠道；
- 启动 Native、Codex、Claude Code、OpenCode、Hermes 或其他 Agent runtime；
- 使用浏览器自动化或浏览器连接器；
- 连接 MCP server 或其他子进程；
- 预览或处理大型文档、表格、图片和生成的应用；
- 在同一台机器上运行本地模型。

本地模型的内存主要由模型和推理运行时决定，不包含在这组数据里。

## 架构边界

ARM64 数据已经证明按需进程生命周期和相对降幅。生产 AMD64 镜像已经通过架构与功能检查，但模拟器内存不会作为 VPS 数据。真实 AMD64 VPS 完成空配置、单微信、单 Discord 各三轮同口径验证后，会把结果补充到本页。

在此之前，不能把 164.94 MiB 理解成所有 VPS 或操作系统都会固定得到的数值。
