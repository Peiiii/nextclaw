# 让 Agent 持续观察

当已接入的服务提供状态或事件时，你可以让 Agent 持续跟进同一个会话：后续处理时带上最新状态，或在关键事件发生时把消息送回这个会话。

持续观察依赖已安装的 Extension 提供可观察对象。先直接问 Agent“这个会话能观察哪些内容？”，它会查找当前可用的 Extension；如果没有合适的 Extension，它会说明原因。

## 两种观察方式

### 后续处理时带上最新状态

适合部署进度、项目待办、服务健康度这类会变化、但不需要每次变化都打断会话的信息。

例如，你可以说：

> 持续跟进这次发布。以后处理这个会话时，请带上最新的发布状态。

Agent 会把该状态关联到当前会话。之后每次需要继续处理这个会话时，NextClaw 都会读取最新快照并带给 Agent。状态变化本身不会单独唤醒 Agent。

### 关键事件发生时继续会话

适合付款失败、构建失败、告警升级、需要审批等需要及时处理的情况。

例如，你可以说：

> 订阅客户付款失败事件，排除测试订单；同一笔订单在 30 分钟内只处理一次。

事件符合条件后会进入原来的会话：会话空闲时可以立刻开始处理；会话正在工作时会按正常队列等待，紧急事件也只会在安全的下一步接入，不会粗暴中断正在进行的处理。

## 让 Agent 帮你设置和管理

不需要记住底层命令。直接告诉 Agent 你要跟进的对象、要忽略的噪声，以及希望它在什么情况下继续会话即可。

这些说法都可以直接使用：

- “查看这个会话现在正在观察什么。”
- “暂停部署状态的持续跟进，等我说继续再恢复。”
- “取消付款失败事件的订阅。”
- “只保留高优先级告警，重复告警不要反复处理。”

观察关系只属于当前会话。Agent 可以查看、暂停、恢复或移除它们；它不能借此改动另一个会话的观察关系。

## 重启、权限和安全边界

已经建立的观察关系会和会话一起保存。NextClaw 重启后，只要相应 Extension 和会话仍然可用，就会恢复它们；如果 Extension 被移除、权限失效或目标会话已不再可用，这段关系会显示为不可用，方便你让 Agent 检查和处理。

来自外部服务的状态和事件会作为数据交给 Agent，而不是当成新的指令。持续观察也不会绕过已有的工具权限和确认规则。只订阅你信任、且你有权访问的服务。

目前持续观察仅支持 NextClaw 的原生 Agent 运行时。
