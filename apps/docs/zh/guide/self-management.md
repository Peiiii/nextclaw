# 自我管理：更新、重启与继续工作

你可以让 NextClaw 帮忙维护 NextClaw 本身：查看版本、检查服务状态、诊断问题，以及在明确授权后更新和重启。对于一个长期使用的搭档，维护自己也应服务于正在为你做的事。

::: info 受控重启恢复即将提供
本页的“重启后自动继续会话”已完成实现与本地工程验收，尚未随正式版本发布。旧安装不能仅靠执行下面的命令获得这项保证；需要先安装包含此能力的版本。版本查询、诊断和更新仍走现有 CLI。
:::

## 不只把服务重新启动

假设你正让 NextClaw 修改一份报告，另一个会话还在整理文件。这时需要更新运行时。你希望它维护好自己，回来继续这两件事，而不是让你重新找回每个任务，再逐个解释“刚才做到哪里”。

受控重启会记录当时正在运行的会话。旧进程退出，新进程就绪后，系统只恢复那些确实被这次重启中断、且仍符合条件的运行。发起重启的会话和其他并行会话都在这个范围内；已经完成的任务不会因此再做一遍。

这提供的是协作的连续性，不是进程永不停机。连接仍可能短暂断开。

## 怎样交给 NextClaw

可以直接说：

> 检查你的版本和运行状态。如果有可用更新，就通过命令行更新；需要时重启，恢复后先核对版本和健康状态，再继续当前工作。

不需要更新、只是明确要求重启时：

> 重启 NextClaw，回来后继续这项任务。先检查刚才的操作结果，不要重复执行。

Agent 使用与人相同的普通命令行，不需要专用更新工具：

```sh
nextclaw --version
nextclaw status --json
nextclaw update
```

只有更新结果表明需要重启时，才继续执行：

```sh
nextclaw restart
```

回来后用 `nextclaw --version` 和 `nextclaw status --json` 核对结果；需要排查时再使用 `nextclaw doctor --json`。不要把更新与重启无条件连成一串：没有可用更新、更新失败和更新成功后等待重启，需要分别处理。

## 重启后，AI 怎么知道发生了什么

恢复时，系统会向新的运行提供明确说明：这次计划重启已经完成；原来的工具进程和执行栈没有恢复；不要因为工具结果中断就再次执行更新或重启；先检查版本、健康状态以及之前操作的实际结果。

历史与已持久化的进度继续可用，但未完成的工具调用不会被自动重放。例如，重启前发起过写文件或外部请求，恢复后应先核对文件或远端状态，而不是假定“没有收到结果就是没有执行”。

每次交接只领取一次。单个会话恢复失败不会让整批会话反复重试；你仍可查看失败情况并决定是否继续。这些措施减少误重试的机会，但不代表任何模型在任何情境下都绝不会作出错误判断。

## 适用范围

| 情况 | 自动继续会话 |
| --- | --- |
| 支持本地运行时 API 的后台服务或前台宿主，执行普通 `nextclaw restart` | 恢复本次被中断且仍匹配的运行 |
| 同一宿主上的其他并行会话 | 同样参与恢复，不只恢复发起会话 |
| 任务已经完成，或只是普通执行失败 | 不因重启自动重跑 |
| 重启后会话已经开始了新的运行 | 不用旧任务覆盖或追加到新运行后面 |
| 崩溃、断电、系统重启或直接终止进程 | 不属于计划重启恢复 |
| 桌面宿主、系统 supervisor 托管的退出 | 暂不覆盖 |
| 旧版本直接 stop/start，或首次从不支持恢复的版本升级 | 无法补造旧进程的恢复记录 |
| `restart` 显式指定端口、打开浏览器或启动超时参数 | 走兼容重启路径，不承诺恢复 |

恢复记录有有效期，当前为五分钟。记录损坏、过期或与此次启动不匹配时，不会自动唤醒会话。这里只处理重启前正在运行的任务，不是对任意排队任务的持久调度保证。

如果重启命令超时，先查状态。请求可能已经被接收，超时本身不是“重启失败”的证据。

## 自我管理与长期协作

查看版本与健康状态，让 NextClaw 知道自己处于什么状态；按你的授权更新与重启，让它能够维护自身运行；回来继续未完成的工作，让维护不轻易成为协作的终点。

这是自感知与自治的一部分。它不意味着自行扩大权限，也不意味着改写自身代码、训练模型或不受约束地“自我进化”。决定要做什么、何时执行高影响操作，仍由你的目标和授权约束。
