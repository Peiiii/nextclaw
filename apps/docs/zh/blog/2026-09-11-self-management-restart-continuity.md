# NextClaw：重启之后，接着做事

发布时间：2026-09-11

标签：`自我管理` `会话恢复` `可靠性`

“更新一下你自己，回来继续。”

对一个长期协作的 AI 搭档，这应该是一句能交付结果的请求：检查版本、完成更新、必要时重启，然后回到刚才没做完的事。NextClaw v0.53.0 为受控重启补上了多会话恢复。

## 当前结果

| 场景 | v0.53.0 的行为 |
| --- | --- |
| 使用普通命令完成更新和受控重启 | 继续所有符合条件的活跃会话 |
| 多个会话同时运行 | 新进程分别领取并继续，不只恢复发起重启的会话 |
| 旧工具进程因重启中断 | 不恢复或重放工具，先核对更新、版本与服务状态 |
| 会话已经完成或普通执行失败 | 不把它误判为重启中断并重新运行 |
| 同一份重启交接被再次看到 | 只领取一次，避免重复恢复 |

## 维护自己，也要记得正在做什么

一份报告改到一半，另一个会话正在整理材料，这时运行环境需要更新。服务重新启动只是第一步。用户真正需要的是：NextClaw 回来后知道还有哪些工作没完成，沿用已经保存的进度，而不是等待逐个唤醒任务。

NextClaw 会在受控重启前记录正在运行的会话。新进程就绪后，它会检查并继续符合条件的运行。已经做完的任务不会重跑，普通执行失败也不会被当成重启中断。

这让维护少一次人工交接，也让正在进行的工作不轻易止于一次进程重启。

## 不把“没收到结果”当成“再执行一次”

AI 重启自身时，发出命令的旧进程可能已经退出，来不及收到完整工具结果。如果只看到中断，它可能把已经完成的重启误认为失败。

新的交接会明确告诉后续运行：计划重启已经完成，旧工具进程没有恢复，不要因此再次更新或重启；先核对版本、服务健康与先前操作的实际结果。

系统不会自动重放工具。会话恢复也不是把旧执行栈搬进新进程，而是带着保存的历史与明确的重启说明，继续判断下一步。

## 自我管理，是长期搭档的一部分

NextClaw 的目标是做好用户的长期个人智能搭档。要长期参与工作，它除了能处理任务，也需要知道自身是否可用，并在授权范围内维护运行环境。

检查状态、更新运行时、重启后继续工作，是这条链路上的具体一段。这里的自治有明确边界：服务用户的目标，遵守用户的授权，不把软件升级说成模型变聪明，也不会自行扩大权限。

## 能力边界

- 当前恢复覆盖支持本地运行时 API 的后台服务和前台宿主，以及不带配置覆盖参数的 `nextclaw restart`。
- 桌面宿主和系统 supervisor 的退出、崩溃恢复、旧版本首次升级，以及任意排队任务的持久调度不在本次范围内。
- 重启后的会话会继续判断下一步，但不会恢复或自动重放重启前的工具进程。

本地验收使用签名测试更新源，跑通了一次更新、连续两轮真实重启和三个不同运行进程；两个会话在每轮重启后分别恢复，之后仍能接收普通新消息。模型输出使用确定性模拟器，因此这项证据证明的是进程与会话恢复链路，不代表所有模型都不会误判后续动作。
