# 2026-08-14 · NextClaw v0.36.2

发布时间：2026-08-14
标签：`release` `npm` `patch`

NextClaw v0.36.2 继续打磨 App、Panel App 和 Service App 的数据管理。应用列表不再为了展示而扫描整份磁盘占用或创建目录；删除被意外中断后，NextClaw 会在下次启动时完成清理并给出可诊断结果。属于同一 App 的 Service 也回到唯一的 Apps 管理入口。

## 增强

- **统一管理 package 内的 Service**：Service Apps 中由 App package 提供的 Service 现在使用“在应用中管理”。点击后会切换到 Apps，定位并聚焦所属 App，不再同时出现两套卸载入口。
- **更清楚的数据状态**：App 卡片会区分“尚无数据”“正在统计”和“大小不可用”，不会再把查询失败误解为 0 B。
- **更轻的应用列表**：Apps 和 Service Apps 的列表、详情与目录查询保持只读；真实磁盘占用由 App Data 统一统计，需要运行时的目录只在安装、启用或调用时创建。

## 修复

- App instance 或 Workspace Service 在永久删除中途退出时，残留的删除事务会在下次启动自动收敛，不会重新出现在应用列表中。
- 删除 Service source 时，只有“路径不存在”会被视为已经删除；权限错误和其他文件系统异常会继续明确报告。
- 已恢复的 Service source 会保留原有 action grants，避免旧清理事务误删重新可用的授权。
- App 安装、启用、卸载等后台操作结束后，Apps、App Data 与 Panel App 会一起刷新，已有 Panel 刷新不再等待完整磁盘统计。

## 默认行为与兼容性

- App 卸载和 Workspace Service 删除仍默认保留个人数据；只有显式选择永久删除，NextClaw 才会移除受管 instance。
- 既有 `instance-v1` 数据布局、稳定 instance id 和同一发布者重装恢复语义保持不变，不需要手工迁移。
- package 管理的 Service 仍使用所属 App 的整体生命周期；独立 Workspace Service 继续保留自己的删除与数据去留选择。
