# 2026-08-14 · NextClaw v0.36.0

发布时间：2026-08-14
标签：`release` `npm` `minor`

NextClaw v0.36.0 给 App 数据补上了完整生命周期。更新继续使用原来的个人数据；卸载时默认保留，也可以明确选择永久删除。保留下来的数据不会再变成看不见的目录，而是会回到 Apps 页面，等你决定恢复使用还是稍后清理。

## 功能

- **已保留的应用数据**：Apps 页面会列出已经卸载但仍保留的数据。每条记录显示 App、受管实例路径和实际占用，并提供独立的永久删除入口。
- **卸载时选择数据去留**：App 和 Workspace Service 都会在删除前给出“保留个人数据”与“同时删除数据”两种明确选择，默认选择保留。
- **六类存储清单**：data、config、state、cache、tmp 和 logs 的用量会分别展示，让永久删除的范围在操作前就可见。

## 增强

- CLI 新增 `nextclaw app data list --json`，可以查看 active 与 retained 数据；永久删除需要返回的 data id 和 `--confirm <app-id>` 同时匹配。
- 开发态 Service 可以使用 `nextclaw app dev <dir> --reset-data --confirm <app-id>` 精确重置当前源码对应的实例，不影响同名 App 的其他数据。
- 删除期间会锁定对应 App 实例并再次检查状态，避免刚刚重装的 active 数据被旧的清理动作误删。

## 修复

- Workspace Service 删除后保留的数据现在会出现在统一清单里，不再成为只能手工查找的隐藏残留。
- Service source、受管数据和 action grants 使用可恢复的删除流程；失败会明确报告并尽可能恢复原状态。
- 永久删除失败时会保留路径和占用上下文，键盘焦点停在错误摘要；成功后焦点回到稳定的 Apps 区域。

## 默认行为与兼容性

- 更新、回滚和同一发布者重装继续复用稳定 instance；既有 instance-v1 数据不需要重新迁移。
- 卸载和 Workspace Service 删除仍默认保留个人数据。只有显式选择“永久删除数据”才会移除六类受管目录。
- 通过授权访问的外部文档不在 App 受管实例内，永久删除 App 数据也不会删除这些外部文件。
- NextClaw 不承诺在现代文件系统上进行法证级安全擦除；“永久删除”表示移除 NextClaw 管理的引用和文件。
